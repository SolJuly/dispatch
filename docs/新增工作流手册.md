# 新增工作流：模板与流程（固化版）

> 2026-11-11 定稿。这份文档和三个工具（`wf_templates` / `wf_infer` / `wf_lint`）
> 一起构成「新增工作流」的唯一正确路径。**绕过它们的操作一律视为待审改动。**

---

## 0. 一句话

```
拿图 → wfctl new（自动跑完反推 + 门禁 + 导入）→ 人审三处 → 预演 → 真机 → 转正 → 上线
```

七个步骤里，**只有第 ③ 步（人审三处）和第 ⑤ 步（真机）需要人动手**，
其余全部是命令。

---

## 1. 为什么需要固化

从 5 条工作流涨到 54 条的过程里，出过的事故几乎全部落在同几类上，
每一类都花过真钱才发现：

| 类 | 事故 | 代价 |
|---|---|---|
| 名字对不上 | 图里要 `image_2`，`params` 里没这个键 | 上传不上去 |
| 值不在候选里 | `text_encoder` 写了镜像里没有的文件 | 提交那一刻才被拒，已开机 |
| 默认值被静默吃 | required 带 default，图里没写 → 服务端补 | 行为和你以为的不同 |
| **正负提示词绑反** | `prompt` 绑到负向编码器 | **出片必糊但作业 PASS** |
| 标 verified 却没证据 | 手改 `compat.json` | 没有可追溯性 |

这些不是"某人粗心"，是**仓库允许它们存在**：54 张卡、每张 8–12 个字段，
靠人记规则必然漏。所以规则必须能执行。

## 2. 三个工具

### 2.1 `wf_templates` — 8 个骨架

```
python3 -m tools.p20.wf_templates          # 列出全部
python3 -m tools.p20.wf_templates i2v      # 看某一个
```

| 模板 | 形态 | 什么时候用 |
|---|---|---|
| `t2i` | text → image | 只要提示词 |
| `i2i` | image + text → image | 拿图改风格/加细节 |
| `t2v` | text → video | 只给提示词出片 |
| `i2v` | image + text → video | 首帧推运动（最常用） |
| `flf2v` | image + image_2 + text → video | 首尾帧插值 |
| `v2v` | video + image + text → video | 动作迁移 / 整片重绘 |
| `upscale` | image → image | 超分放大 |
| `inpaint` | image (+mask) → image | 擦除 / 局部修复 |

模板提供**骨架**（该有哪些参数、说明怎么写、期望判据给什么），
图提供**真实值**（绑到哪个节点）。两边都不全时 `wfctl new` 会告警。

每个模板里带 `REVIEW_` 占位符的字段必须在落盘前由人确认 ——
`wfctl new` 会把没被真实绑定替掉的占位参数直接丢掉并告警。

### 2.2 `wf_infer` — 从图反推参数契约

```
python3 -m tools.p20.wf_infer --graph workflows/pack/video_ltx2_3_i2v.api.json
python3 -m tools.p20.wf_infer --graph X --json          # 机读
python3 -m tools.p20.wf_infer --graph X --emit-card      # 打印整张卡骨架
```

节点 id 是 ComfyUI 导出时生成的随机数字串（`1349`、`src`、`ks`），
手填 `bindings` 必然出错，而错了的后果不是报错，是渲染时 `_set()` 抛异常 ——
**那时实例已经开好、钱已经花了**。

反推出的东西里有三处机器判不了，工具会明确标 `confidence != high`：

1. **正负提示词方向** —— 靠图连通性追，追到就标 `medium` 要人念一遍
2. **参数该不该暴露** —— 内部中间量（`ComfyMathExpression.values.a`）不暴露
3. **默认值是否合理** —— 图里的值是作者调试留下的（`egyptian_queen.png`），
   媒体类一律标空 + `required`

### 2.3 `wf_lint` — 19 条门禁规则

```
python3 -m tools.p20.wf_lint            # 全量
python3 -m tools.p20.wf_lint --key K    # 单条
python3 -m tools.p20.wf_lint --strict   # 警告也算失败（发布前）
python3 -m tools.p20.wf_lint --rules    # 列出规则 + 每条防的是什么
```

| 编号 | 级别 | 防什么 |
|---|---|---|
| WF001 | ERROR | 卡不是合法 JSON / 缺顶层字段 |
| WF002 | ERROR | graph 文件不存在 |
| WF003 | ERROR | model.slots 指向不存在的节点 |
| WF004 | ERROR | params.bindings 指向不存在的节点 |
| WF005 | ERROR | prompt 与 neg_prompt 默认值相同 |
| WF006 | ERROR | prompt 默认值里含负向词 |
| WF007 | WARN | params 里暴露权重文件名 |
| WF008 | ERROR | name 写死状态词但已 verified |
| WF009 | ERROR | 视频卡没有时长判据 |
| WF010 | ERROR | output 不是保存节点 |
| WF011 | ERROR | 媒体类型与 loader 不匹配 |
| WF012 | WARN | 参数没有 description |
| WF013 | ERROR | 默认值违反自己声明的 type/min/max |
| WF014 | ERROR | 参数类型 UI 渲染不出来 |
| WF015 | ERROR | 两个槽位绑同一节点 |
| WF016 | WARN | experimental 出现在可用区 |
| **WF017** | ERROR | **prompt/neg_prompt 绑到错误的一侧** |
| **WF018** | ERROR | **正负绑到同一节点同一条输入** |
| **WF019** | ERROR | **任意两个参数绑同一条输入（后者覆盖前者）** |

## 3. 七步流程

### ① 拿图

ComfyUI 里点 **Save (API Format)**，不是普通 Save。

判据：文件顶层是 `{"节点id": {"class_type": ..., "inputs": {...}}}`，
不是 `{"nodes": [...]}`。

> 失败 → `wfctl new` 会直接报"图不是 ComfyUI API 格式"，重新导出即可。

### ② 一条命令跑完 落盘 + 反推 + 门禁 + 导入

```bash
python3 -m tools.wfctl new \
    --key my_wf --name "显示名" --kind video \
    --graph /path/to/my_wf.api.json \
    --model <模型key> \
    --template i2v
```

不给 `--template` 时按图的输入形态自动推荐：
有视频输入 → `v2v`；两张图 → `flf2v`；一张图 → `i2v`；都没 → `t2v`。

> 失败 → 按输出改 `registry/workflows/my_wf.json`，然后
> `python3 -m tools.wfctl update --key my_wf`

**槽位对不上会在这里拦住**（不用等 `p20ctl import` 抛异常）：

```
✗ 模型卡 ltx_2_3_22b_dev_fp8 覆盖不了图里推出来的槽位。
  图要的槽位 : ['ckpt', 'text_encoder']
  模型卡有   : ['ckpt', 'lora', 'lora_2', 'upscale']
  缺         : ['text_encoder']

  三条路，选一条：
  a) 换个模型卡：--model <已有覆盖这些槽位的卡>
  b) 给模型卡补 files.text_encoder
  c) 加 --drop-slots text_encoder 明确放弃由 registry 管理
```

### ③ 人审三处（机器判不了）

**a) 正负提示词方向**

把 `prompt` 和 `neg_prompt` 的默认值各念一遍。方向反了出片必糊且不报错。
2026-11-11 实测：**5 张卡犯这个错，其中 4 张已经是 verified** ——
也就是说"真机跑通过"完全不代表正负绑对了。

**b) 参数是否重复**
同一个节点同一条输入只能有一个参数管。渲染顺序是字典序，
后面的会覆盖前面的 —— 用户改哪个都可能被另一个旧值盖掉，且完全不报错。

> 2026-11-11 实测 `scail2_int8` 有 `prompt` / `prompt_2` / `prompt_3` 三个，
> 其中 `prompt` 和 `prompt_3` 都绑 `1404.text`。加了 WF019 才查出来。

**c) 模型卡覆盖**

`registry/models/<key>.json` 的 `files` 要覆盖卡里 `model.slots` 的每个角色。
缺一个 → 渲染时 `apply_model` 抛「缺槽位」，而那时实例已开好。

**d) 该暴露的参数是否都暴露了**

尤其 `frames` / `length`：它必须绑到**决定 latent 长度**的节点
（`EmptyXxxLatentVideo.length` 或 `WanVaceToVideo.length`）。

> 绑到 `ImageFromBatch.length` 是**裁切**不是总帧数。
> 2026-11-11 踩过：`scail2` 图里 4 个 `ImageFromBatch.length=1`，
> 照它写 frames 默认 1，用户不改就出 1 帧废片。

### ④ 预演（¥0，不建机）

```bash
python3 -m tools.p2.asset_preflight --workflow my_wf
```

查三样：图里要的节点在不在镜像里、权重在不在共享库、值在不在候选列表。

> **查不到**：张量形状、显存够不够、推理会不会 NaN —— 这三类只能真机跑。
> 别指望预演能包治百病：`fasth3_ominiref_r2v` 预演说"能过"，
> 真机上仍然 `tensor a (24) must match b (768)`。

### ⑤ 真机验证（花钱，约 ¥0.13–0.5/次）

```bash
python3 -m tools.p20.p20ctl new --workflow my_wf --allow-experimental --run
```

> 失败 → 作业目录在 `reports/p1/jobs/<job_id>/`，看 `manifest.json` 的 `issues`。

### ⑥ 转正（唯一能写 verified 的入口）

```bash
python3 -m tools.wfctl verify --key my_wf --job-id <job_id>
```

硬条件，缺一不可：

- 作业 `state == DONE`
- `manifest.verdict == PASS`
- 作业 meta 与当前卡一致（workflow_key × model_key）
- **过门禁**（门禁漏的错会被永久写进 `compat.json`）

质量分 D 会拦下来，确要转正加 `--allow-low-quality`，但先看 `issues`。

### ⑦ 上线

```bash
./deploy.sh    # repo-guard → sync_share → 重启 → healthcheck
```

## 4. 改了工作流之后

**改 `registry/workflows/<key>.json` 或 `workflows/*.api.json` 之后必须**：

```bash
python3 -m tools.wfctl update --key <key>     # 自动 bump 版本 + 门禁 + 导入
```

因为 `registry.db` 是派生索引，`.gitignore` 里排除了它 ——
**改完 JSON 不跑 import，UI 还是旧的**。

改完图谱想让参数跟上：

```bash
python3 -m tools.p20.wf_infer --graph workflows/<key>.api.json   # 看新图推什么
```

想自动补图里漏写的必填字段：

```bash
python3 -m tools.p20.graph_fill --dry-run    # 先演练
python3 -m tools.p20.graph_fill --apply      # 真写回（自动备份 .bak）
```

`graph_fill` 刻意不补：模型名、文件名、提示词、连线型输入。
补错这些**不会报错，只会静默出错片**。

## 5. 已知边界（别指望工具能兜住）

| 类别 | 为什么兜不住 |
|---|---|
| 张量形状不匹配 | 本地没有求解器，`fasth3_ominiref_r2v` 就是例证 |
| 显存够不够 | 取决于卡型和图的实际峰值，静态算不准 |
| 推理会不会 OOM / NaN | 同上 |
| 权重版本对不对 | 文件名对得上不等于版本兼容 |
| 提示词方向 | 只能靠人念一遍（工具只标 `medium` 提醒） |
| 成片好不好看 | 质量分只抓崩坏，不评审美 |

## 6. 用户自定义工作流（下一步的地基）

这套东西为「用户上传自己的工作流」准备好了三件事：

1. **`wf_infer` 不依赖 registry** —— 给一张 ComfyUI API 图就能反推契约，
   用户不用懂 `bindings` 是什么
2. **`wf_lint` 的 18 条规则全是纯函数** —— 可以在用户提交时就地跑，
   把「能跑但有隐患」的卡当场拦下并给出人话原因
3. **`wf_templates` 的模板是数据不是代码** —— 加一类新形态只需加一个
   `Template(...)`，不动逻辑

还差的部分：用户上传要有人审队列（谁审、审什么、拒绝理由怎么写）、
配额与隔离（一个用户的工作流不能影响别人的调度）、
以及权重授权（用户的工作流引用了平台没有的权重时怎么处理）。

# 多租户设计：资金池 + 账号池 + 多云联动

> 目标：别人用自己的账号登录、烧自己的钱；跨云时不必重复注册；资金池承担 GPU 租金，账号池提供各平台 API Key。

---

## 0. 结论先行

| 你的设想 | 可行性 | 现实 |
|---|---|---|
| 用户注册自己的账号 | ✅ 可做 | 需要建用户表 + 登录页 |
| 用户不烧你的钱 | ⚠️ 分两种 | **账号池模式**：用户预充值到池 → 你代付但盈亏由池结算；**自带 Key 模式**：直接烧他们的余额，最彻底 |
| 跨云不用重复注册 | ✅ 关键洞察成立 | 用户只注册**一次**（你的系统），**平台账号由账号池统一托管**，用户看不到 |
| 资金池承担 GPU 费用 | ✅ 可做 | 本质是预付钱包 + 按作业扣减，`manifest.cost` 已经可靠（实测 0.2222） |
| 账号池获取各家 API Key | ✅ 可做 | `CS(cfg)` 已支持独立凭证，**34 处调用点可用 env 注入绕过，零改动** |
| 联动多云 | ⚠️ 要做抽象层 | 智云一家独大，Provider Protocol 只需 14 个方法 |

**最关键的一条发现**：账号池不需要改 34 处 `CS()`。

```bash
$ CS_PUBLIC_KEY=ENVKEY CS_PRIVATE_KEY=ENVSECRET python3 -c "from compshare.cs import CS; print(CS().cfg)"
{'CS_PUBLIC_KEY': 'ENVKEY', 'CS_PRIVATE_KEY': 'ENVSECRET'}
```

`load_config()` 环境变量优先级高于 `credentials.env`。而真正会建机的 **spawn 点只有 3 处**（`webui/api.py:423`、`webui/api.py:526`、`tools/p1/p1queue.py:78`），**这 3 处目前都没传 `env=`**。

所以账号池的最小实现是：3 处加 `env={**os.environ, **account_env}`。

## 1. 三个池的职责划分

```
                    ┌─────────────────────────────┐
   用户 A ─┐        │      你的系统（唯一入口）      │
   用户 B ─┼───────▶│  注册 / 登录 / 提交 / 查产物   │
   用户 C ─┘        └──────────┬──────────────────┘
                               │
              ┌────────────────┼────────────────┐
              ▼                ▼                ▼
        ┌──────────┐    ┌──────────┐    ┌──────────┐
        │  资金池   │    │  账号池   │    │  资产池   │
        │ wallet   │    │ accounts │    │ assets   │
        └──────────┘    └──────────┘    └──────────┘
         ¥ 余额          API Key          镜像/权重
         按作业扣       按 provider 分     平台级共享
```

### 1.1 资金池（wallet）

**职责**：记录每个用户还有多少钱，按作业实际消耗扣减。

**关键前提已验证**：`manifest.cost.amount` 是可靠的真实花费。

```json
{"hourly": 2.15, "minutes": 6.2, "amount": 0.2222}
```

`run.py:723` 用 `hourly * minutes / 60` 计算，`minutes` 来自 `up_at` 到落盘的墙钟差，**与云账单同口径**。

**数据模型**

```sql
CREATE TABLE wallet (
  user_id      TEXT PRIMARY KEY,
  balance_cny  REAL NOT NULL DEFAULT 0,
  held_cny     REAL NOT NULL DEFAULT 0,   -- 预扣（作业在跑时占住）
  updated_at   TEXT NOT NULL
);

CREATE TABLE wallet_txn (
  txn_id     TEXT PRIMARY KEY,
  user_id    TEXT NOT NULL,
  ts         TEXT NOT NULL,
  kind       TEXT NOT NULL,   -- recharge|hold|settle|refund|adjust
  amount_cny REAL NOT NULL,   -- 正数入账，负数出账
  job_id     TEXT,
  note       TEXT
);
```

**扣费流程（两阶段，防超支）**

1. **提交时预扣**：`hold = budget.max_cost`（如 ¥1.6）。`balance >= hold` 才允许建机。
2. **完成时结算**：`settle = manifest.cost.amount`，退回 `hold - settle`。
3. **失败时释放**：`refund = hold`，全退。

**为什么必须两阶段**：单阶段（跑完才扣）会让用户同时提交 10 个作业把余额刷成负数。预扣的上限来自 `job.budget.max_cost`，而这个字段**已经存在且被写进 job.json**（实测 `{"max_minutes": 40, "max_cost": 1.6}`）。

> ⚠️ 但要先修一个 bug：`run.py:297` 的 `cap` **只打印不校验**（全仓库 `if.*cap` 零匹配）。预扣依赖它，必须让它真的生效。

### 1.2 账号池（accounts）

**职责**：托管各平台 API Key，按 provider 分桶，按用户或按作业分配。

**数据模型**

```sql
CREATE TABLE provider_account (
  account_id   TEXT PRIMARY KEY,       -- acc-uhost-01
  provider     TEXT NOT NULL,          -- compshare | autodl | runpod | ...
  label        TEXT NOT NULL,          -- 人可读："智云主号"
  public_key   TEXT NOT NULL,          -- 加密存储
  private_key  TEXT NOT NULL,          -- 加密存储（cryptography 44.0.3 可用）
  region       TEXT,
  zone         TEXT,
  project_id   TEXT,
  max_instances INTEGER DEFAULT 5,     -- 智云 Level1 = 5 台
  enabled      INTEGER DEFAULT 1,
  created_at   TEXT NOT NULL
);

CREATE TABLE account_lease (
  lease_id   TEXT PRIMARY KEY,
  account_id TEXT NOT NULL,
  job_id     TEXT NOT NULL,
  leased_at  TEXT NOT NULL,
  released_at TEXT
);
```

**分配策略（三选一）**

| 策略 | 逻辑 | 适用 |
|---|---|---|
| `shared` | 所有作业抢同一个池，谁快谁得 | 小规模，最省心 |
| `per_user` | 每个用户绑一个 account_id | 需要按人分账/分账单 |
| `least_loaded` | 选当前实例数最少的账号 | 高并发，榨干配额 |

**配额乘法效应（账号池最大的商业价值）**

智云 Level1 **单账号 5 台**。账号池 = 配额线性叠加：

| 账号数 | 并发实例 | 满载成本 |
|---|---|---|
| 1 | 5 | ¥10.75/h |
| 3 | 15 | ¥32.25/h |
| 5 | 25 | ¥53.75/h |
| 10 | 50 | ¥107.50/h |

你现在是单账号串行（全局 `.job.lock`），**这就是多人使用时互相堵死的根因**。

### 1.3 资产池（assets）

**职责**：镜像 + 权重，跨账号复用。

**好消息（这条决定了三池方案能不能成立）**：

```
/model 共享库 = UPFS 40T 只读，平台级挂载，与账户无关
```

`instance_setup.sh:112` 写死了 `base_path: /model/comfyui/`，**任何账号开出的机器都能挂**。权重（424 个 unet / 66 clip / 47 vae）零成本共享。

**坏消息（这条是最大的工程量）**：

自定义镜像 `compshareImage-1xdh3lcu5dvu`（**70GB**）是**账号私有**的。

- `DescribeCompShareImages` 只返回本账号可见的镜像
- 代码里**没有镜像共享 API**（搜 `Share` 零匹配）
- `resolve_image()` 在找不到时不报错，而是返回原 ID：

```python
for i in self.images():
    if i.get("CompShareImageId") == spec:
        return i
return {"CompShareImageId": spec, "Name": spec}   # ← 找不到也返回
```

**后果**：账号 B 用账号 A 的镜像 ID 建机 → `resolve_image` 静默通过 → `create()` 时炸 → **而且不会回落到基础镜像**（因为 `resolve_image` 没抛异常，`_pick_image` 的 `except` 不触发）。

**三条出路**

| 方案 | 代价 | 说明 |
|---|---|---|
| **A. 每个账号各烘一份 70GB** | 70GB × N | 最省事，但镜像存储费叠加 |
| **B. 回落到平台基础镜像** | 起机 120-160s（vs 105-117s） | 零额外成本，慢 15-40s |
| **C. 只用平台镜像 + setup 脚本** | 每次建机多跑 1 次 `instance_setup.sh` | 已有脚本，但是 setup 本身要 ~30s |

> 建议：**方案 B**。`_pick_image` 已有回落链（`--image` → `image.json` → `IMAGE_KEYWORD`），只要把 `resolve_image` 找不到 ID 时改成抛异常，回落就自然生效。改动 ~5 行。

## 2. 多云联动：Provider Protocol

### 2.1 最小接口（实测得出，不是拍的）

扫了 `run.py` 和 `pool.py` 里所有 `cs.xxx()` 调用，并集是 **14 个方法**：

```python
class Provider(Protocol):
    def balance(self) -> dict: ...
    def create(self, image_id, gpu_type, gpu, cpu, memory_gb, name, charge_type, disk_gb, ...) -> list[str]: ...
    def get(self, ident: str) -> dict: ...
    def instances(self, ids=None, refresh=True) -> list[dict]: ...
    def password_of(self, inst: dict) -> str: ...
    def price(self, gpu_type, gpu, cpu, memory_gb, ct, disk_gb, ...) -> dict: ...
    def public_ip(self, inst: dict) -> str: ...
    def resolve_image(self, spec: str) -> dict: ...
    def start(self, ident: str) -> dict: ...
    def stock(self, gpu_type, spot=False, zone=None) -> int: ...
    def stop(self, ident: str) -> dict: ...
    def stop_at(self, ident: str, ts: int) -> dict: ...
    def terminate(self, ident: str) -> dict: ...
    def wait_state(self, ident: str, states, timeout=900, ...) -> dict: ...
```

智云 `cs.py` **已经有了全部 14 个**。接新云只需实现这 14 个方法。

### 2.2 各家的硬约束差异（必须抽象掉的）

| 维度 | 智云 | 典型差异 |
|---|---|---|
| SSH 端口 | `"23"`（非 22！） | 多数云是 22 |
| 登录方式 | 密码（`password_of`） | RunPod 用 SSH Key |
| 镜像 | 账号私有，无共享 API | RunPod 用 Docker 镜像名 |
| 关机兜底 | `stop_at` 要求 ≥ now+300s | 有的没有定时关机 |
| 现货 | Spot 不支持 `stop_at` | 各家的 spot 语义都不同 |
| 计费 | Postpay ¥2.15/h | 按秒/按分钟/按小时 |

**这 14 个方法里，`stop_at` 和 `password_of` 是最需要抽象的两个**——它们编码了强烈的平台特性。没实现 `stop_at` 的云，得用「本地 cron 扫一遍超时实例」补偿。

### 2.3 用户视角：一次注册，多云端跑

这正是你问的核心。正确做法：

```
用户注册一次 ──▶ 只需要邮箱/密码
                      │
                      ▼
              系统挑一个可用账号（账号池）
                      │
              ┌───────┼───────┐
              ▼       ▼       ▼
           智云A    智云B    智云C     ← 用户完全无感
```

**用户永远不需要知道后端用的是哪个云、哪个账号。** 跨云切换对用户是透明的调度决策，不是注册流程的一部分。

如果某个用户想「自带 Key 省点钱」，加一个可选的 `BYOK` 通道：

```sql
ALTER TABLE "user" ADD COLUMN byok_provider TEXT;
ALTER TABLE "user" ADD COLUMN byok_public_key TEXT;
ALTER TABLE "user" ADD COLUMN byok_private_key TEXT;
```

提交时若 `byok_public_key` 非空 → 用他的凭证建机 → **直接扣他自己的平台余额，成本 ¥0 到你**。这时资金池可以只收「调度服务费」。

## 4. 关键风险（不好听但要先说）

### 4.1 资金池的法律性质变了

一旦「用户 A 充钱到你这里，你替他付 GPU 租金」，你就不再是「工具提供者」，而是**代收代付的清算方**。这涉及预付卡/资金沉淀的合规问题。纯 BYOK 模式（用户自带 Key，钱不经过你）没有这个问题。

### 4.2 账号池的封号连锁反应

智云单账号 5 台配额。用多账号绕配额，如果平台判定为「拆分规避限额」，可能**同时封掉整个池**。这条要在协议里说清楚，不要对用户承诺 SLA。

### 4.3 镜像复用是硬约束

70GB × N 账号。如果 10 个账号各烘一份 = 700GB 镜像存储。按方案 B（回落基础镜像）可以规避，但起机慢 15-40s。

### 4.4 串行锁不解决 = 多人体验崩坏

现在 `QUEUE_WAIT_S = 14400`（4 小时）。两个人提交，第二个静默排队，**UI 显示「提交成功」但实际 4 小时后超时才失败**。这是比钱更紧急的问题。

## 5. 我的建议顺序

**别一次做五阶段。** 按「单位工作量收益」排：

```
1. 修 max_cost 校验        ← 资金池唯一地基，30 分钟
2. UI 开 --batch           ← 多人并行，30 分钟，收益最大
3. 账号池 + env 注入       ← 配额叠加，2 小时
4. 用户表 + 登录           ← 1 天
5. 资金池                  ← 1 天
6. Provider 抽象           ← 半天
7. 第二家云                ← 2-3 天
```

**前 3 条加起来不到 3 小时**，就能把一个「单人、串行、共用钱包」的系统，变成「多账号、并行、可归因」的系统。登录和资金池反而是后话——因为**没有账号池，登录之后所有人还是一个钱包**，先做登录没有意义。

## 6. 一句话回答你的问题

> 能不能固定用户一个资金池和账号池，资金池承担 GPU 租金，账号池获取各家 API Key，联动多云？

**能，而且架构上比「每个用户注册一个云账号」简单得多。** 用户只需要在你这注册一次，账号池在后台替他选云选账号，资金池负责结算。

技术上唯一的真障碍不是多云——是**镜像账号私有 + 没有共享 API**，以及**串行锁**。前者用「回落基础镜像」绕开，后者改一个 flag。

真正难的是一旦资金池收钱，你的角色从「工具」变成「代收代付」，这个定性要先想清楚。

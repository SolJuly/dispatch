## 2. 关键是机制，不是这一次删对

2026-11-09~10 **连续三次**把功能加到用户看不见的那一套上：

```
① 质量卡  → web/dist（用户在 /app/，看不到）
② NEW 标签 → web/dist（同样看不到）
③ 修上面两次时才发现仓库里有两套前端
```

根因不是谁粗心，是**仓库允许"改错地方"这件事发生**：两套都返回 200、都有测试通过，改哪套都"看起来对"。

### 建的机制一：`tools/console_guard.py`

声明唯一入口，检查 6 类违例：

| 违例 | 说明 |
|---|---|
| 废弃文件被重新创建 | `webui/pages.py` 又出现 = 有人改错地方了 |
| fileserver 仍有 `_app_page` / `kind=="app"` | A 套路由没删干净 |
| Python 里出现 >4KB HTML/CSS 字面量 | 又往 Python 里塞前端 |
| 工作流卡的 graph 指向不存在的文件 | 卡与图脱节 |
| compat.json 标 verified 但缺 checked_at | 手改冒充 |
| .gitignore 吞掉 web/dist | 历史上真发生过，导致改动进不了库 |

**挂进测试**（18 条），改错地方会在 CI 阶段失败，而不是等用户发现界面没变。

### 建的机制二：`tools/wfctl.py`

工作流由四样东西构成，必须一起变：

```
graph     workflows/<key>.api.json
params    registry/workflows/<key>.json
compat    真机证据
index     registry.db（派生，可重建）
```

历史上所有事故都来自"只改了一部分"。收敛成 4 个动词：

```bash
python3 -m tools.wfctl new     # 新增（自动从图推断 slots 与 bindings）
python3 -m tools.wfctl update  # 改（自动 +1 版本，校验后导入）
python3 -m tools.wfctl verify  # 真机跑完 → 写证据（唯一能标 verified 的入口）
python3 -m tools.wfctl check   # 全量体检（守卫 + 配置 + 预检，¥0）
```

**`verify` 强制三条硬校验**：作业 DONE + manifest PASS + 元数据对得上。
手改 `compat.json` 冒充 verified 走不通。

### 写 wfctl 时踩到并修掉的两个真问题

**① 按 input 名推断 model.slots 会撞车**

一条工作流常有两个 LoRA（主 LoRA + 文本编码器 LoRA），input 都叫 `lora_name`。只按名字找会让两个角色绑到同一节点，另一个永远没人填 —— 渲染不报错（值都填上了），但实际用错 LoRA，成片里看不出来。

改成「input 名 + 图里当前值」双重匹配 + `used` 集合防一节点多角色。

**② key 规则与 bindings 没有前置校验**

第一次跑 `new` 时图都拷进去了才报错，留下半成品。改成建卡前先校验，bindings 自动从图推断，推断不出就明确报错并列出可绑的输入。

## 3. P4：4 条转正，修掉四类根因

### 结果

```
19 条 experimental → 15 条
```

| 工作流 | 质量 | 耗时 |
|---|---|---|
| `pack_video_ltx2_3_i2v` | 66.5 B | 146s |
| `pack_video_wan21_scail2_character_replacement` | 68.6 B | 400s |
| `pack_video_wan21_scail2_character_replacement_int8` | 62.2 B | 467s |
| `pack_video_ltx2_3_flf2v` | 61.2 B | 120s |

花费 ¥3.12（¥23.83 → ¥20.71）。

### 根因 1：自动补链不读 compat_links.txt

`assets.link_model_files()` 只用 `find /model` 按名字找，**从不读**那张人工确认的改名映射表。

两套机制各干一半，谁也不认谁：表里登记过的改名（`qwen_std_vae` → `qwen_image_vae`）在实例上依然报"模型资产不可见"。

### 根因 2：`LatentUpscaleModelLoader` 的目录不是 `upscale_models`

`folder_paths.py:43` 把它注册成独立的 `latent_upscale_models`。

链到 `upscale_models` 后节点候选列表仍是 **0 项**，而软链看着完全正常（`ls` 有文件、路径也对）。这类"链对了但放错目录"最难查 —— 我查了两轮才发现。

### 根因 3：DYNAMICCOMBO 的三种失败形态

`graph_check` 原来只判断"有没有以 `字段名.` 开头的键"，漏掉两种：

| 形态 | 例子 | 后果 |
|---|---|---|
| **平铺写法** | `TextGenerateLTX2Prompt` 的 `top_k` 直接放 inputs | 选了 `sampling_mode="on"` 不给 6 个子参数 → 提交被拒 |
| **有子键缺主键** | `resize_type.width` 有但 `resize_type` 没有 | ComfyUI 报 missing positional argument |
| 运行时才定 | 主键子键都没给 | dynamic，不算硬缺失 |

现在三条规则独立。子参数两种写法都认：点号 `resize_type.width` / 平铺 `top_k`。

### 根因 4：批量模式失败保留实例会撞并发上限

每次失败都保留实例 15 分钟给人续跑。单条跑很划算，批量跑时很快撞上「云端已有 2 台在跑（上限 2）」，后面全建不了机 —— **而这时人不在旁边，机器在烧钱等自动关机**。

修法：`--batch` 下失败即释放，要保留显式加 `--keep-on-fail`。

### 顺带修的图问题

```
pack_video_ltx2_3_flf2v        表达式 a+b 缺 values.b；帧数 30 → 81
pack_video_wan21_scail2_*      ImageFromBatch.length 写死 1 → 只能出 1 帧
3 条 LTX 2.3 工作流             text_encoder 要 fp4_mixed（库内没有）→ int8
```

### 新增：`--live` 值校验

校验字段值是否在**当前机器**的候选列表里。必须配真机快照（静态快照不含运行时软链会全线误报）。

扫全量发现 **13 条**有 `value_not_in_list` 风险，包括已 verified 的 `detail_polish`。这是"跑到一半才发现"的最大来源。

### 没跑通的

| 工作流 | 原因 |
|---|---|
| `pack_video_fasth3_ominiref_r2v` | `tensor a (24) must match b (768)` — 24=768/32，latent 通道布局不匹配，与分辨率无关，改参数无效 |
| `pack_video_ltx2_3_id_lora` | 需参考音频，合成正弦波测不出真实效果 |
| `pack_video_ltx2_3_ic_lora` / `ic_lora_ingredients` | 需更多输入 |

## 1. L5-A：Provider Adapter

### 改造前的问题

```bash
$ grep -rn "CS()" --include='*.py' tools/ | grep -v tests | wc -l
34
```

34 处直接 `CS()`，散落在 run / scheduler / pool / cost_snapshot / riskmon /
checkpoint。这套代码在智云上能跑，**换任何一家云都要改 34 个文件**。

### 结构

```
tools/p2/providers/
    base.py        契约：Provider / InstanceView / Capabilities / ProviderError
    compshare.py   智云适配器（薄封装 compshare.cs，547 行原样保留）
    local.py       本地机 + FakeProvider（测试用）
    registry.py    工厂 get_provider() / 能力矩阵 / available()
```

### 三个设计决定

**① 不做自动降级。** 选哪家云是显式决策，不是「这家挂了偷偷换一家」——
那会让成本账算不清楚。

**② 不隐藏价格口径。** `price()` 返回（算力, 系统盘, 数据盘）三元组，不折算。
因为各家免费额度完全不同（智云系统盘 ≤100GB 免费，RunPod 停机照收
$0.20/GB/月），折算会把差异抹平从而算错钱。

**③ 做不到就 `NotSupported`，不返回空结果冒充"查询成功但没数据"。**
这是上一轮审计里最贵的错误类型。

### 能力声明（这是跨云决策的依据）

```
provider    停机 外网 OCI 共享权重 定时关机 竞价 自定义镜像 免费系统盘
compshare    ✓    ✗   ✗    ✓       ✓      ✓    ✓        100GB
local        ✗    ✓   ✓    ✗       ✗      ✗    ✗        0GB
fake         ✓    ✓   ✓    ✓       ✓      ✓    ✓        100GB
```

`compshare` 的 `外网=✗` 和 `OCI=✗` 是**实测结论**，写在 `notes` 里：

```python
instance_has_internet=False,
notes={"instance_has_internet": "DNS 解析失败，provision.sh 在此不可用"}
```

上层用 `provider.require("instance_has_internet")` 在下决定**之前**就知道
这条路走不通，而不是跑到一半报 `docker: command not found`。

### 错误分类（可测）

```python
classify("226604 无现货")          → (OUT_OF_STOCK, retryable=True)
classify("8903 in the task")       → (BUSY,         retryable=True)
classify("quota limit exceeded")   → (QUOTA,        retryable=False)
classify("Signature failed")       → (AUTH,         retryable=False)
classify("something weird")        → (UNKNOWN,      retryable=False)  ← 默认不重试
```

**未知错误默认不重试**：宁可停下让人看，也不盲目重试烧钱。

### BYOK 口子（顺带解决商业模式问题）

上一轮确认你的模式是 BYOK + 服务费。代码上唯一的差别是「用谁的凭证建机」。
`CS(cfg)` 本来就接受 isolated credentials，所以：

```python
def _cs(creds=None):
    """creds 非空时走 BYOK，不读本地 credentials.env。"""
    if creds and creds.get("CS_PUBLIC_KEY"):
        return CS(creds)
    return CS()
```

`run.py` 里 6 处 `CS()` 全部改成 `_cs(...)`，**不改调用签名**，加两个 CLI 参数：

```bash
python3 tools/p1/run.py JOB_ID --public-key PK --private-key SK
```

客户端凭证不进进程环境、不落 credentials.env。

## 2. L5-B：资产缓存

### 改造前的问题

文档 §7.4 要求五步（解析/校验/原子移动/索引/淘汰），实际一行没有。
真实痛点（缺口清单 §3）：

> **不是缺权重，是名字不对**（占大头）
> `/model` 是只读 UPFS，平台镜像里的文件名五花八门

### 五步实现

| 步 | 函数 | 说明 |
|---|---|---|
| 1 解析 | `resolve(model, available, can_link, can_download)` | 三态：hit / linkable / download / missing |
| 2 校验 | `verify_file(path, expect_size, expect_sha256)` | 先查大小再算哈希（40GB 算一次要几分钟） |
| 3 落位 | `place_script()` / `download_targets()` | 下载用 `.part` 临时名 + 原子改名 |
| 4 索引 | `record()` / `save_index()` | 原子替换，`.part` 不留在盘上 |
| 5 淘汰 | `evict_plan()` | LRU + 只删可删项 |

### 三条硬规则

**① 共享挂载永不淘汰。** `/model` 是平台级跨账号共享库，删它等于删别人的数据。

```python
cand = [(n, e) for n, e in entries.items() if e.get("evictable")]  # 硬过滤
```

**② 删光也不够时必须报错。** 不能静默继续：

```python
return {"reached": freed >= need, ...}   # False → 上层必须报"磁盘要爆了"
```

**③ 不猜名字。** 只用模型卡里的 `match`（equals/contains/regex），与
`assets.py` 远端脚本同一套语义。模糊匹配会把 A 模型的文件链给 B 模型用，
这种错误在成片里根本看不出来，只会得到"莫名其妙的糊图"。

### 证据强度分级（本项目真实踩过的坑）

`reports/p2/p21/evidence/missing-weights.txt` 只有 95 行，是当初"查了几个
常见目录没找到"的**抽样**，不是完整盘点。

把它当成完整清单的后果：**31 条 verified 工作流全部被报成 `no_weight`**，
而它们明明昨天还在真机上跑通过。

所以 Probe 分两档：

```python
weights_known: bool = False       # 没给 → 整个维度跳过
weights_complete: bool = True     # 给了但是抽样 → 只能确认"在"，不能确认"不在"
```

抽样未命中的进 `unverified_weights`（可能跑得起来），不是 `missing_weights`
（一定跑不起来）。

**这是审计那句「查询成功但没数据被当成一切正常」的镜像错误：
有数据但不完整被当成了完整。**

### compat_links.txt 升级为强证据

那 30 行是**真机验证过能加载的**，含改名映射（`qwen_std_vae` →
`qwen_image_vae`）。所以标 `source="verified"`，与 mount/cache 区分：

```python
why = {"verified": "已确认的名字映射（compat_links）", ...}
```

## 3. L5-C：跨云一致性

### 解决什么

`provision.sh` 装完只做四项粗检。四项全过但环境已偏了的场景有：

- ComfyUI commit 悄悄不是 manifest 那个（有人手动 `git pull` 过）
- torch 被某次 pip 装成别的版本
- 某节点 import 失败但名字还在 object_info 里
- 权重文件名换了（平台更新 `/model`，旧链接指向老名字）

这些**不会让当前作业失败**，但会让「换云后结果不一致」——
而换云后不一致是最难查的 bug：代码一样、图一样、参数一样，片子不一样。

### 设计：只吃两份数据，不联网

```
manifest  环境描述（deploy/env/*.env.json）
probe     机器自述（collect_script() 在目标机现场采集）
```

所以既能真机跑（`--collect HOST`），也能编排机离线复放（`--probe FILE`）。
**离线复放是刻意的**：部署机与 GPU 机之间只有 SSH，去掉这个能力就只能
每次开一台 4090 来校验配置。

### 严重度

| 级别 | 例子 |
|---|---|
| **ERROR** | commit 不符、torch 版本不符、节点缺失、import 失败、`unet_visible=0` |
| WARN | 节点 commit 不同但节点在、外网状态与记录不符 |
| INFO | 各项一致 |

`ok` 只在没有 ERROR 时为真。**WARN 不阻止部署，但必须打印出来。**

### 实测

用真实 manifest + 模拟 probe：

```
跨云一致性：comfyui-wan-p21
结论：✓ 一致（ERROR 0 / WARN 0 / INFO 5）
```

## 4. L6-A：质量判定

### 改造前的问题

审计原文：

> **没有质量判定（只有"文件成功"，没有"质量成功"）**

`verify.py` 七项全是技术有效性判据。七项全过只证明"这是一个能播放、尺寸对、
不是黑屏的 MP4"。抓不住：

- 画面有内容但整体糊成一片
- 动作迁移跑完了但人物没动
- 出图是纯色块/抽象噪点

### 为什么不用审美模型

不引入 CLIP/审美打分，三个理由：

1. 分数不可解释，阈值只能拍脑袋
2. 换云换卡后同一张图分数会变（浮点差异），**"换云结果一致"这个目标会被
   打分器自己破坏**
3. 更重要的是：**对用户来说"糊"和"没动"是能说清的**，用不着审美模型

### 四维指标（每个都有物理含义）

| 指标 | 算法 | 含义 |
|---|---|---|
| sharpness | 拉普拉斯卷积后的 YAVG 均值 | 糊 / 抽象 / 噪点 |
| motion | signalstats YDIF 均值 | 有没有真的动 |
| luma_mean / range | 原始 YAVG / YMAX-YMIN | 过暗 / 过曝 / 发灰 |
| sharpness_cv | 边缘序列变异系数 | 闪烁 / 抖帧 |

### 阈值是真实样本标定的，不是抄的

31 条真实产物/素材逐条算一维指标后排序：

```
v4-wan-i2v.mp4         6.32 / 19.84 / 129.7   ← 最佳
h3 系列                1.28–2.40 / 3.0–21 / 78–150
wan_i2v.mp4            0.93 / 14.13 / 191.4   ← 合法成功样本
seedvr2-video-1080.mp4 0.90 /  2.31 /  99.0   ← 合法放大结果
ltxv attempt2.mp4      0.56 /  2.98 /  51.8   ← 已知失败样本
```

**关键教训：`verify.py` 的 `WARN_EDGE=1.0` 不能直接搬过来。**
那是"只抽 3 帧"的口径（h3 I2V 在那里是 2.40，全片采样是 1.41），
两个数不可混用。照搬会把两条合法成果判成糊的。所以按全片采样重定线到 0.8。

### 加权分会骗人，所以加木桶封顶

第一版是纯加权（清晰 40 / 运动 25 / 曝光 20 / 稳定 15），结果：

```
attempt2.mp4（已知失败样本）  58.4 分  ← 靠高运动+好曝光拉起来
wan_i2v.mp4（合法成功）       60.2 分  ← 只差 1.8
```

用户看到"58 分"会以为"还行"，但那片子是花的。**糊不会因为动得好而变好。**

改成木桶封顶后：

```
attempt2.mp4          32.0 D  capped_by=sharpness 0.56 < 0.8
in-7af16da6.mp4       52.0 C  capped_by=motion 0.50 < 0.6
wan_i2v.mp4           60.2 B
...
v4-wan-i2v.mp4        99.1 A
```

排序正确了。封顶值都取在 B 的下沿（55）以下，让致命项一定落到 C/D。
静帧的封顶（52）比"糊"（32）宽松——因为静帧可能是用户要的（定格/照片风）。

### 默认不改 PASS/FAIL

```python
mode="report"   # 只记录分数进 manifest，不动七项结论
mode="gate"     # 显式打开才可能 FAIL
```

理由：现存 30 条 verified 都是按七项判的，把质量分设成默认门禁等于全部
重判一次，那需要人一条条看，不是一次改动能决定的。

## 6. 顺带修的漏洞

### `arch.py` 把真 token 写进 HTML

```
$ grep -o '3501cd88' reports/architecture.html | wc -l
4
```

每跑一次 `arch` 就把当前 token 拼进 href。虽然该文件被 `.gitignore` 排除，
但它会被 `sync_share.sh` 同步到 `/pub/` 和 `/files/`——**等于把口令主动发布出去**。

`test_no_token_in_repo_files` 一直在报这个，之前没修。

修法：落盘写占位符 `{TOKEN}`，`fileserver._file()` 在返回时替换成本次请求的 token。

```python
raw = p.read_bytes()
if b"{TOKEN}" in raw:
    raw = raw.replace(b"{TOKEN}", TOKEN.encode())
```

这样 HTML 落盘永远是干净产物，可以安全地同步、归档、比对 diff。

### 测试抓到的 3 个真实 bug

**① `ProviderError.__init__` 抛 NameError**

```python
retryable = kind in (OUT_OF_STOCK, TRANSIENT)   # 类体内不可见！
```

Python 类作用域不会自动查外层，裸名在类体方法里取不到。改成
`ProviderError.OUT_OF_STOCK`。

这个 bug 会让**每一个带 kind 的异常在构造时就崩掉**，比不分类更糟。

**② 外网状态检查从来没触发过**

manifest 记 `platform_notes.compshare.instance_has_internet`，
probe 报 `platform.has_internet`——字段名不一样，一开始直接拿同名键去查。

改成显式名称映射表，不靠"看起来同名"。

**③ 测试视频生成器静默失败**

`f"{pattern}=size=..."` 对 `color=c=black` 拼出 `color=c=black=size=...`，
ffmpeg 当成颜色名解析失败。5 个测试因此静默 skip，看起来"通过"。

这正是"测试通过但没测到东西"的典型——比失败更危险。

# 失败后停机保留（¥0）+ 续跑自动唤醒

日期：2026-11-12 17:25
成本：¥0（纯代码 + 单元验证，未启动机器）
测试：1010 全绿（p1 221 +15 / 其余不变）
决定来源：你拍板的"第二种"

---

## 一句话

失败保留实例从「**开机**等 15 分钟」改成「**立刻停机**（¥0），要续跑再花 12 秒开机」。

## 改之前 vs 之后

| | 老设计 | 新设计 |
|---|---|---|
| 失败后机器状态 | Running（计费） | **Stopped（¥0）** |
| 等人来的代价 | 4090 ¥0.54 / **H20 ¥1.88** / A100 ¥2.69 | **¥0** |
| 来了续跑 | 立刻（模型在显存里） | 先开机 12s + 装模型 21~53s |
| 没人来 | 15 分钟后自动关 | 2 小时后 reaper 自动销毁 |
| 占并发槽位 | **占着**（并发闸数 Running）15 分钟 | **不占**，立刻让给下一个作业 |
| 进程死了 | 平台侧定时器仍生效 | 停机失败时回落到定时器（见下） |

**为什么停机不收费**：实测（`24-存储成本与跨云装置.md`）——停机实例
算力 ¥0 + 系统盘 ≤100G ¥0 = ¥0/月。

顺带修掉一个隐藏问题：老设计那台 Running 机器**占着并发槽位**
（并发闸数的是 running 实例数），失败一条就顶掉一个槽 15 分钟。
停机不占槽，槽立刻让出来。

## 三处改动

### ① `_keep_instance`：立刻停机

```python
# 老：cs.stop_at(uid, now + 15*60)   ← 定时关机，15 分钟内照常计费
# 新：cs.stop(uid) → wait_state(stopped) → lifecycle.record_stopped(uid)
```

**停不下来必须回落到定时关机**。这是这次改动里最重要的一条安全线：

老设计的好处是**平台侧**有定时器，我们进程死了机器也会到点关。
改成立刻停之后，如果 `cs.stop()` 失败（8903 过渡态 / 平台抖动）而我们就
这么算了，那台机器就**没有任何兜底**地一直计费——**比老设计还糟**。
所以 `_stop_now()` 停不下来就退回 `stop_at`，最坏也只是回到老行为。

真机验证过一次这条回落路径（模拟里故意让 stop 抛错，`stop_at` 被正确调用）。

### ② 停机会杀死 ComfyUI → 断点标记要跟着失效

停机 = 断电 = ComfyUI 进程死 = **内存里的 prompt_id / history 全没了**。
如果断点在 submit/wait，续跑会去轮询一个已不存在的 prompt_id，
挂在原地直到超时。

`_invalidate_inmemory_steps()` 按断点位置决定：

```
断点在 submit/wait → setup/ready/submit/wait 全部作废（重走推理链）
断点在 fetch 之后 → 一个都不作废（产物在磁盘上，停机不丢）
```

第二条是刻意的：fetch 之后作废等于逼着重跑推理，白花一遍 GPU 钱。

### ③ `--resume` 自动唤醒

`_rebuild_ctx(wake=True)`，三步缺一不可：

```
① start + 等 Running（平台 ~12s）
② sshd 探活（Running ≠ ssh 能连，不探的话第一个 ssh 步骤必失败）
③ lifecycle.clear_stopped —— 不清的话 reaper 拿旧停机起点算
   "已停 2 小时"，唤醒后下一轮巡检就把它销毁（误销毁不可逆）
```

这三步和 `_try_borrow_slot` 唤醒停机槽位是**同一套**——那边真机验证过可行。

**`--abort` 不唤醒**：销毁对 Stopped 实例照样有效，
为销毁一台机器先花 12 秒开机是纯浪费。

## 批量模式保持不变

批量失败仍然**直接销毁**（不是停机保留）。停机虽然 ¥0，但占着账户
5 台的配额，批量失败一条留一台很快就建不了新机。要保留加 `--keep-on-fail`。

15 条锁的都是改这条路径最容易出的事：

| 测试 | 防什么 |
|---|---|
| `test_stop_failure_falls_back_to_timer` | 停不下来时没有兜底 → 机器无限计费（比老设计还糟） |
| `test_submit_breakpoint_invalidates_chain` | 续跑去轮询已死的 prompt_id → 挂到超时 |
| `test_fetch_breakpoint_preserves_everything` | 作废磁盘上还活着的断点 → 逼着重跑推理白花钱 |
| `test_resume_wakes_stopped_instance` | 唤醒后不清登记 → reaper 误销毁（不可逆） |
| `test_abort_does_not_wake` | 为销毁而开机 → 纯浪费 12 秒 |
| `test_sshd_probe_required` | Running 就当能连 → 第一个 ssh 步骤必失败 |
| `test_unknown_state_refuses` | 把"销毁中"当可唤醒 → 猜错方向 |

外加 2 条源码级接线断言（`--resume` 传 wake、`--abort` 不传）——
行为测试 mock 的是同一层，接线错了它们看不出来。

## 真机待验

停机 → 唤醒这条链在槽位复用路径上真机验证过（同一套三步），
但 `--resume` 唤醒**停机保留的失败实例**没真机跑过。
下次有作业失败时顺手 `--resume` 一下即可验证，约 ¥0.1（开机 12s + 装模型）。

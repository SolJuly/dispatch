## 六、今天新发现的三条问题

### ① 花费归因失真（钱上的账算错了）

```
今日 settle ¥4.68 · job ¥0.18
```

看起来"96% 是空转"，**实际是我今天的验证开销**。根因：

```python
# tools/cost_snapshot.py:122
"attribution": "job" if any(k in ("job","create","terminate","cost") for k in kinds)
               else "idle"
```

**`ssh_exec` 事件不在判定列表里。** 手动 ssh 做实验期间没触发
`job/create/terminate`，于是全被归成 `idle`。

后果：交接单 §4 那个"65% 空转"的结论**可能被高估**——手工操作期全算成空转了。

### ② `01:10` 的 ¥0.55 是镜像存储费，不是空转

它每天固定出现，`attribution=idle`。这没错（确实是"没跑作业时的费用"），
但分类上应该和"机器开着烧钱"区分开——一个是可省的，一个是必然的。

### ③ 并发上限和余额没联动

余额从 ¥19 降到 ¥14.44，但 `MAX_PARALLEL` 一直是 2，没有任何调整。
真要动态化，应该是 `min(配额, floor(余额 / 单机小时价 / 安全倍数))`。

## 2. 资产预演

### 判据：模拟建成软链后的结果

真机上顺序是：

```
find /model 扫库 → 按模型卡找文件 → 按 LOADER_DIRS 建软链
→ ComfyUI 按目录列候选 → 图里的名字必须在候选里
```

预演模拟前半段，判据用**最后一步**：链建成后候选里会不会出现这个文件名。

### 两个设计错误（都靠实测抓出来）

**① 试图"反推 loader 读哪个目录"→ 42 条误报**

第一版从 object_info 反推"某个 loader 读哪些目录"。但权重库里同名文件散落在多个目录，反推出的"期望目录"只是候选里恰好能定位到的那几个，**不代表 loader 真的只读那儿**。

改法：候选列表本身是最终判据，不再反推。目录对不对用 `_loader_reads_dir()` 做交叉验证，判断不了就返回 `None`（unknown），**绝不当成通过**。

**② 拿错快照 → 35 条 verified 全被报"必失败"**

用 `objectinfo-live-v4.json` 判断时，35 条真机跑通过的工作流全报失败。

原因：快照是**某台机器某一时刻**的，只含那一条作业建过的软链。拿它判断别的工作流必然误报。

修法：判据改成「模拟建成软链后会怎样」，快照只用于交叉验证。重采了一份 `objectinfo-linked.json`（软链建全后的状态）。

### 结果

```
54 条 · 能过 37 · 会失败 14 · 证据不足 3
```

14 条失败里：12 条真缺权重、2 条节点不齐。**全部是真问题，零误报。**

### 怎么用

```bash
# 单独预演一条
python3 -m tools.p2.asset_preflight --workflow pack_video_wan_vace_14b_ref2v

# 接入总检查（第 ③ 步）
python3 -m tools.wfctl check --key <wf>
```

查单条时，预演失败会让退出码变成 1 —— 可以直接写进 CI。

## 3. 图参数自动补全

### 问题

`--live` 值校验扫出 10 条工作流、**44 个「必填但没写」字段**。逐条手填要半天，而其中绝大多数是「ComfyUI 有默认值、导出模板时丢了」。

### 刻意做得很保守

| 补 | 不补 |
|---|---|
| 有 `default` 的 | 模型名 / 文件名 |
| 枚举取第一个候选 | 提示词 / 文本类 |
| DYNAMICCOMBO 主键及子参数 | 连线型 |
| `ComfyMathExpression.expression` | `string_a` / `value` |

**不补的理由：补错不会报错，只会静默出错结果。**

- 模型名补错 = 用错权重，**成片里看不出来**
- 提示词补空串 = 出废片，但作业会 PASS（文件合法、内容为空）

`NEVER_AUTOFILL` 名单写在代码里，每个条目都有原因注释。

### `expression` 为什么可以补

`ComfyMathExpression` 的默认表达式（`a + b`）是**节点自带的语义**，不是用户内容。补它和补 `steps=20` 一个性质。

这个区分我改了两版：第一版把 `expression` 也放进不补名单，结果 `ltx2_3_flf2v` 的表达式问题修不了。

### 结果

```
可补 187 处 · 跳过 16 处
44 个问题 → 8 个真问题
```

剩下的 8 条：

| 类型 | 条数 | 处理 |
|---|---|---|
| 缺节点（要换镜像） | 2 | QwenImage21Cache / TextEncodeQwenImage21 |
| 模型名确实不存在 | 6 | 要下载权重 |

### 怎么用

```bash
# 演练，看清楚要改什么
python3 -m tools.p20.graph_fill --object-info OI.json

# 真的写回（自动留 .bak）
python3 -m tools.p20.graph_fill --object-info OI.json --apply
python3 -m tools.p20.p20ctl import
```

## 4. 顺带修的两个误判

**① 占位符被当成"值不在候选列表"**

`{{UPSCALE_MODEL}}` 是渲染时替换的，值校验拿它比候选列表必然不中。因此把 verified 的 `detail_polish` 误判成必失败。

**② 空候选被当成"目录对"**

候选是 `[""]` 或 `[]` 时，说明快照里这个 loader 一个文件都没看见，不能据此说目录是对的。测试抓到的。

## 5. 这个工具的边界（必须说清）

**查（都是"开完机才知道"的高频原因）：**

- 权重文件在不在库里（含 `compat_links` 改名映射）
- 链到 ComfyUI 会不会看不见（目录映射错）
- 图里必填字段有没有值、值在不在候选列表里

**不查（本地算不出来）：**

- **张量形状是否匹配** — 如 `fasth3_ominiref_r2v` 报 `tensor a (24) must match b (768)`。预演说"能过"，真机仍然失败
- 显存够不够
- 推理会不会 OOM / NaN / 卡死

所以预演通过 **不等于** 一定能出片，只是"不会卡在资产检查这一步"。

实测印证：37 条预演通过里，`fasth3_ominiref_r2v` 真机仍因张量不匹配失败 —— 这类问题本地没有求解器。

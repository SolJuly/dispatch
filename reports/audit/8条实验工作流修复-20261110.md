## 1. 最重要的一条：一个「假能跑」的工作流

`qwen_image_edit_2511_int8` 在预检里是 `ready`（节点类齐、权重齐），但真机跑出来是**糊的废图**：

| | 修前 | 修后 |
|---|---|---|
| 推理耗时 | 285s | **72s**（快 4 倍） |
| 质量分 | 32 / D | **96.1 / A** |
| 产物 | 脸和手糊成一片 | 花纹锐利、手部正常 |

### 1.1 根因一：图里混进了 Flux 节点

```
1198  FluxKontextMultiReferenceLatentMethod
1199  FluxKontextMultiReferenceLatentMethod
```

这两个节点属于 **flux** 分支（`category: model/conditioning/flux`），却出现在 **Qwen Image Edit** 工作流里。它们把 Qwen 的 conditioning 按 Flux 的方式处理，导致输出被扭曲。

**判定依据**：对照已验证的 `qwen_image_edit_2509`（同系列，real-run 验证过），它的节点列表里**没有**这两个节点：

```
qwen_image_edit_2509 全部节点：LoadImage / FluxKontextImageScale / UNETLoader /
LoraLoaderModelOnly / ModelSamplingAuraFlow / CFGNorm / CLIPLoader / VAELoader /
TextEncodeQwenImageEditPlus ×2 / VAEEncode / KSampler / VAEDecode / SaveImage
```

**修法**：删掉 `1198/1199`，KSampler 的 positive/negative 直连 TextEncode。

### 1.2 根因二：三个 switch 全关，跑的是慢速路径

```python
1210 ComfySwitchNode: switch=False → 走 CFGNorm，**绕过 Lightning LoRA**
1214 ComfySwitchNode: switch=False → cfg = 4    （on_true 是 1）
1215 ComfySwitchNode: switch=False → steps = 40 （on_true 是 4）
```

图里挂了 `Qwen-Image-Edit-2511-Lightning-4steps` LoRA，但开关没打开，等于用 40 步 + cfg 4 跑一个 4 步蒸馏模型。

**修法**：三个 `switch` 改 `true`。

### 1.3 顺带发现：导出时丢了 5 个必填输入

这条工作流原本回 400 `required_input_missing`，缺：

| 节点 | 缺的字段 | 补的值 |
|---|---|---|
| `TextEncodeQwenImageEditPlus` ×2 | `prompt` | `{{PROMPT}}` / `{{NEG_PROMPT}}` |
| `FluxKontextMultiReferenceLatentMethod` ×2 | `reference_latents_method` | （节点已删） |
| `SaveImageAdvanced` | `format.bit_depth` / `format.input_color_space` | 换成 `SaveImage` |
| `CFGNorm` | `strength` | `1.0`（objectinfo 的默认值） |

同时给 registry 补了 `prompt` / `neg_prompt` 两个参数 —— 原来 schema 里只有 `image` 和 `seed`，**连提示词都没法给**。

## 2. 新建工具：`tools/p20/graph_check.py`

**问题**：这类问题只有在真机上花 ¥0.1 建机才能发现一次。第一版检查器还自己出了 bug。

### 2.1 判据（三段分类）

| 分类 | 含义 | 下一步 |
|---|---|---|
| `missing` | 真缺，不补就 400 | 补值 |
| `dynamic` | `AUTOGROW`/`DYNAMICCOMBO`，API 格式键名运行时生成 | 需实测 |
| `has_default` | 带默认值 | 默认放过，`--strict` 时算缺 |

### 2.2 修掉判据自己的两个 bug

**bug 1：子键写法没认出来**

```python
# 图里写的是：
"ComfyMathExpression": {"expression": "...", "values.a": 5}
# 第一版只查 `"values" in inputs` → 判成缺
```

结果 8 条工作流报了 **53 个假问题**，其中 `fasth3` / `minimax_h3` 明明能跑却被标红。修法：检查有没有 `f"{name}."` 开头的键。

**bug 2：「有默认值就能省」是错的**

第一版认为 `default` 表示服务端会补，于是放过了 `EmptyFlux2LatentImage.batch_size`。结果 ComfyUI 真回 400。

实测发现：**能否省取决于该节点是否被执行路径求值**。`flux2_klein` 里有三个写法完全相同的 `ImageScaleToTotalPixels`，ComfyUI 只对**真被求值**的那个报 `megapixels` 缺失。

静态判断不了 → 加 `--strict` 模式，上机前彻底体检时用。

### 2.3 效果

```
python3 tools/p20/graph_check.py            # 24 条 experimental：9 条有硬缺失
python3 tools/p20/graph_check.py --strict   # 12 条有硬缺失（含带默认值的）
python3 tools/p20/graph_check.py --group    # 按同源组归并，修一顶多条
```

**12 条测试**（`tools/p20/tests/test_graph_check.py`），钉死三条判据本身，包括那两次 bug 的回归。

## 4. 没跑通的两条：原因已定位

### 4.1 `qwen_image_layered` 只出 1 层

跑通了（PASS / 59.8 / B），但**只产出 1 张图**，而这个工作流的意义是拆分层（预期 3 层）。

`LatentCut.dim` 我填了 `"t"`：

```json
1148 LatentCut:        {"samples": [...], "dim": "t"}
1149 LatentCutToBatch: {"samples": [...], "dim": "t"}
```

结果 3 层被合并成了 1 张。**`dim` 的语义需要对照官方示例确认** —— 候选值只有 `x` / `y` / `t` 三个，但组合方式（`LatentCut` 切 + `LatentCutToBatch` 摊平的配对）有多种可能。

### 4.2 `fasth3_ominiref_r2v` 张量维度不匹配

```
SamplerCustomAdvanced: The size of tensor a (24) must match the size of tensor b (768)
    at non-singleton dimension 1
```

图里这个节点：

```json
131 ComfyMathExpression: {
  "expression": "max(5, round(a * 24)) + (5 - (max(5, round(a * 24)) % 17)) % 17",
  "values.a": 5
}
136 MiniMaxH3ReferenceToVideo.length <- 131
```

表达式假设 `a` 是**秒数**，算出 `length=24` 帧。但实际 latent 是 768 维 —— 说明 `a` 应该由输入尺寸或时长推导，不能填死 5。

**关键对照**：`minimax_h3_r2v` 有**完全相同的 `ComfyMathExpression` 节点、同样的 `values.a=5`**，却跑通了（305s / 66.5B）。所以问题不在这个节点本身，而在这条工作流下游对 `length` 的期望不同。

## 6. 一个被判错的质量分（诚实记录）

`qwen_edit` 的前两次我用了 `stylize as a soft watercolor painting`（水彩风格），质量分 **32/D**，issue 是「边缘能量 0.74 < 0.8：图片糊/抽象」。

**这不是误判** —— 图确实糊。但根因是**水彩风格本来就该糊**。质量判据按边缘能量打分，没有「风格豁免」：

| 风格 | 边缘能量 | 会被判 |
|---|---|---|
| 写实 / 摄影 | 高 | A / B |
| 水彩 / 油画 / 胶片 | 低 | **D（假阳性）** |

所以这批作业的参数里，我把提示词改成了中性描述（`detailed kimono fabric, sharp facial features`），并在脚本里写明了原因。

**这是一个独立的产品缺口**：美术风格类工作流会被质量分系统性判低。本轮没修。

## 7. 剩余工作的性质（不是「补字段」）

剩下 4 条（2 条 ltx、2 条 scail2）参数已按 `--strict` 补齐，**没有任何硬缺失**，但没跑过。它们的难点在参数语义：

| 节点 | 需要搞懂的 |
|---|---|
| `ManualSigmas.sigmas` | LTX 的采样 sigma 序列格式（字符串，可能是逗号分隔的 float） |
| `LTXVAddGuide.frame_idx` / `strength` | 首尾帧在序列中的插入位置与权重 |
| `VAEDecodeTiled.tile_size` / `overlap` | 分块解码的显存/质量权衡 |
| `SAM3_VideoTrack.detection_threshold` | 视频主体跟踪的检测阈值 |
| `SCAIL2ColoredMask.object_indices` / `sort_by` | 角色替换时遮罩对象的选择 |
| `WanSCAILToVideo.pose_strength` / `pose_start` / `pose_end` | 姿态迁移强度与时间窗 |

这些都有强语义，盲试容易烧钱且学不到东西 —— **正确做法是从 ComfyUI 官方示例的 workflow.json 里对照原值**，而不是猜。

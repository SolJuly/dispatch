## 0. 结论先行

三档的经济含义不一样，**不是"随便选一个"**：

| 档位 | 空转成本 | 复用净省 | 净收益 | 给人看的定位 |
|---|---|---|---|---|
| **60s** | ¥0.0358 | ¥0.0364 | **+¥0.0006** | **刚好打平**（再长就亏） |
| **90s** | ¥0.0537 | ¥0.0364 | −¥0.0173 | **均衡** |
| **120s** | ¥0.0717 | ¥0.0364 | −¥0.0352 | **体验优先** |

**默认档建议 90s**（你之前定的就是 90s），理由见 §4。

## 1. 基准数据（23 条实测）

```
建机            59s
setup           47s  → 烘焙快路径只需 5s
ComfyUI 重启    40s  ← 停机后省不掉
────────────────────
复用净省 = 59 + (47-5) - 40 = 61s = ¥0.0364

空转单价 = ¥2.15/h = ¥0.0358/分钟 = ¥0.000597/秒
```

**为什么复用净省只有 61 秒**：不是省掉全部 106 秒建机+setup，
而是省掉「建机 59s + setup 的 42s」，但要付「ComfyUI 重启 40s」。

## 2. 三档的详细账

### 2.1 60 秒 —— 省钱最优

```
空转 60s = ¥0.0358
复用净省 = ¥0.0364
净收益   = +¥0.0006   ← 几乎精确打平
```

**这是数学上的盈亏平衡点（61 秒）。** 超过这个数的每多一秒，都是在拿钱换时间。

**什么时候选它**：
- 你不确定会不会接着跑
- 你想把成本压到最低
- 你有"跑完就走"的习惯

**代价**：60 秒只够"看一眼图 → 改一个参数 → 点提交"。

这个动作要多久？**我没有真实用户数据**（详见 §2.2 末尾的说明），
只能说我自己的用法大约 30–90 秒。所以"60 秒够不够"是真机验证项。

### 2.2 90 秒 —— 均衡（建议默认）

```
空转 90s = ¥0.0537
复用净省 = ¥0.0364
净收益   = -¥0.0173      ← 亏 ¥0.017
```

**亏 ¥0.017 换来什么**：多 30 秒的"想一下"时间。

**什么时候选它**：
- 常规使用，不知道下一单会不会来
- 这个工作流你比较熟，改参数快

**为什么建议默认**：¥0.017 大约是一张 27 秒图的 20%，感知不到。

**但"超窗率"这个数字我没有依据。** 我查了现有数据：

```
reports/p1/jobs 下 5 条作业，created_at 全部是同一秒（2026-11-08T13:52:58）
—— 那是我做 UI 验证时克隆的夹具，不是真实使用记录
```

**所以「用户跑完后多久又提交」这条数据现在是空的。**

这意味着：

| 想说的事 | 有没有数据 |
|---|---|
| 用户跑完后 60 秒内回来多少比例 | ❌ 没有 |
| 90 秒够不够 | ❌ 没有 |
| 120 秒超窗率多少 | ❌ 没有 |

**三档的"该选哪个"现在只能靠经济账推，不能靠行为数据。**
真实数据要等 P6 真机验证 + 一段时间实际使用才能积累。

### 2.3 120 秒 —— 体验优先

```
空转 120s = ¥0.0717
复用净省  = ¥0.0364
净收益    = -¥0.0352     ← 亏 ¥0.035
```

**什么时候选它**：
- 这是长任务（本身花 ¥0.36–0.45），¥0.035 只占 8%
- 你要反复试同一组参数出多个变体
- 你不想被"重等 113 秒"打断节奏

**代价**：如果这一单 120 秒内没来，¥0.072 是纯损失。

## 3. 一个必须先想清楚的事：空转白等的损失

三档真正的差别在**「窗口内没等到下一单」**这笔钱：

| 档位 | 白等损失 |
|---|---|
| 60s | ¥0.0358 |
| 90s | ¥0.0537 |
| 120s | **¥0.0717** |

**但注意：白等之后是停机（¥0），不是继续烧。** 所以单次损失是有界的，不会累积。

### 3.1 白等损失占任务成本的比例

| 任务推理时长 | 任务总成本 | 60s 白等占比 | 90s | 120s |
|---|---|---|---|---|
| 30s（短图） | ¥0.085 | 42% | 63% | **84%** |
| 60s | ¥0.103 | 35% | 52% | 69% |
| 120s | ¥0.139 | 26% | 39% | 52% |
| 300s（动画） | ¥0.247 | 15% | 22% | 29% |
| 600s（长视频） | ¥0.426 | 8% | 13% | **17%** |

**这张表说明**：
- 短任务给 120s 窗口 = 白等成本占它成本的 84%，**绝对不该**
- 长任务给 120s 窗口 = 占 17%，**给得起**

**这就是为什么"短任务不空转"是硬规则，而三档只对长任务开放。**

## 4. 三档怎么给用户选

### 4.1 建议：只对长任务开放，且默认 90s

```
☐ 这是长任务
   └─ 跑完后保留实例多久等下一单？
       ○ 60 秒   —— 省钱最优（几乎不花钱，但可能来不及）
       ● 90 秒   —— 均衡（默认）
       ○ 120 秒  —— 体验优先（多花 3 分钱，不用重等）
```

**短任务不给这个选项**（永远 0 秒），因为：
- 短任务白等 120s 占它成本 84%，是纯亏
- 选项越多越容易选错

### 4.2 为什么不建议做成"随便填个数"

给个输入框让用户填 300 秒会出事：
- 300s 白等 = ¥0.179，占 600s 长任务的 42%
- 用户不知道这笔账，会填个"我觉得够用的数"

**三档的好处是每一档都有明确的经济含义**，用户能理解"我在为什么付费"。

### 5.2 90 秒（默认）

## 6. 一个技术细节：档位要可配但不要开放

```python
# tools/p2/concurrency.py
IDLE_TIERS = (60, 90, 120)          # 只允许这三个值
DEFAULT_LONG_IDLE_S = 90            # 默认档

def long_idle_s(task_class: str, chosen: int | None = None) -> int:
    """长任务空转秒数。短任务恒 0。

    `chosen` 不在 IDLE_TIERS 里就回落默认 —— 不做"任意值"支持。
    理由：三档每一个都有明确经济含义，任意值会让用户填出
    "300 秒"这种占长任务成本 42% 的数而不自知。
    """
    if task_class != "long":
        return 0
    if chosen in IDLE_TIERS:
        return int(chosen)
    return DEFAULT_LONG_IDLE_S
```

**为什么写死元组而不是环境变量**：环境变量一开，就会出现
`P2_LONG_IDLE_S=600` 这种配置，绕过所有经济约束。

## 7. 完整规则（合并上一轮）

| 项 | 值 | 可配 |
|---|---|---|
| 短任务空转 | **0 秒**（不空转） | ❌ 不开 |
| 长任务空转 | **60 / 90 / 120 三档，默认 90** | 仅限三档 |
| 停机保持 | **2 小时** | `P2_STOPPED_TTL_MIN` |
| 停机到期 | 销毁 | — |

### 状态机（三档不改变结构，只改②的时长）

```
作业 DONE
   │
   ├─ 短任务 → 立即进停机判定
   │
   └─ 长任务 → 空转 N 秒（N ∈ {60,90,120}）
                 ├─ N 秒内来新单 → 复用（~10s）
                 └─ 没来 → 停机（62s 唤醒）
                              │
                        停机保持 2h（¥0）
                              │
                     ┌────────┴────────┐
                  2h 内来          2h 无作业
                     │                 │
                  start 唤醒        销毁
```

## 9. 一个我建议你考虑的点

**默认档选 90s，但可以考虑"自适应"**：

```
最近 10 次作业里，用户跑完后在多久内又提交？
  → 中位数 45 秒 → 默认给 60s
  → 中位数 75 秒 → 默认给 90s
  → 中位数 110 秒 → 默认给 120s
```

这样默认档会跟着用户习惯走，而不是所有人吃同一个值。

**但我建议先不做**，理由：
- 数据不够（现在只有 23 条作业，且大部分是我手工跑的）
- 自适应会让人困惑（"为什么昨天的默认值不一样"）
- 三档手动选已经够简单了

等累积到几百条真实作业再看。

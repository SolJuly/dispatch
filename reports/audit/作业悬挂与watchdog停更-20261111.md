# 作业不消失 + watchdog 不实时：三处根因与修复

日期：2026-11-11
触发：用户截图，两条作业挂在「进行中的作业」里，watchdog 没有实时数据。

---

## 一句话

三个独立问题叠在一起：**页面冻了两小时**（前端轮询锁死）、**作业根本没人启动**
（缺「执行」按钮，后端接口却一直在）、**采样停了 52 小时**（撤 `csctl watch`
时把采样一起撤了）。外加一个隐藏更深的：**静态资源发 `immutable` 一年**，
让「UI 改了看不到」被误判成"前端没同步"。

---

## 一、页面静默冻结（最严重，用户看到的直接现象）

### 现象

截图里 `p1-20261111T2038-7f562f` 显示「执行中 44%」，`44%` 后面的进度条走了
一格半。但这条作业 **20:45:52 就已经 DONE 了**，截图时间是 22:43。

`44%` 不是巧合：进度表里 `RUNNING` 的位置正是
`index(4) / (10-1) × 100 = 44%`。所以页面从「RUNNING 那一次渲染」之后
**一次都没再更新**，冻了将近两小时。

### 根因链

```
fetch 默认永不超时
  ↓
请求挂住 → await 既不 resolve 也不 reject
  ↓
tick(): busy = true; try { await refresh() } finally { busy = false }
  ↑ finally 只在返回/抛出时执行，永挂时两者都不是
  ↓
busy 永久 true
  ↓
此后每次 tick 走 `if (busy) return schedule();` → 一个请求都不再发
```

### 为什么难查

- 没有报错、没有红字
- 连接指示器还亮着（它保留着上一次成功的时间）
- 最后一次渲染的内容原样贴在屏幕上

看着像"后端没更新"，实际是前端停了。这次是靠比对 `44%` 和 job.json 的
真实状态才定位的。

### 修复

1. **所有请求带超时**：新增 `_fetch()` 包装，`AbortController` + 15s
   （上传 120s，下载 60s）。超时转成 `status=0` 的错误抛出 ——
   与网络错误同口径，能触发 tick 的退避重试。
2. **tick 加看门狗**：40s 后强制 `busy = false; failN += 1; schedule()`。
   这是最后一道保险 —— `_fetch` 只能覆盖走它的请求，看门狗覆盖一切。
3. `get` / `post` / `getBlob` 全部改走 `_fetch`，不再有裸 `fetch(`。

## 二、作业没被启动（「不消失」的主因）

### 现象

截图里 `p1-20261111T2012-8ba75f` 显示「已创建 / 排队」，20:12 提交，
到 21:15 才被对账脚本判成 FAILED。

### 根因

它**从来没被 spawn 过** —— 目录里只有 `events.jsonl` 和 `job.json`，
没有 `run.log`（真正跑过的作业都有）。因为提交时并发已满，
后端按设计**降级成「只建作业不执行」**（deferred），把作业留在 CREATED。

问题在后面：

- 系统里**没有常驻调度器**。`p2-dispatch.service` 是 `disabled/inactive`。
- 前端**没有「执行」按钮**。`grep jobs/run app.js` = 0 处，
  但后端 `POST /api/p2/jobs/run` 一直存在（`fileserver.py:804`）。
- 提交后的提示却写着「等前面的跑完到任务页点「执行」」——
  **让用户去点一个不存在的按钮。**

于是作业永远停在 CREATED，占着任务栏，直到对账脚本（`*/15`）在两小时后
按「无实例、无产物」判它失败。

### 修复

1. **补「执行」按钮**：`CREATED` 状态的作业在任务栏右侧显示「执行」，
   走已有的 `POST /jobs/run`。用**事件委托**绑定（`qlist` 每次刷新都重建
   innerHTML，直接绑 onClick 下一轮就丢）。
2. **改掉误导文案**：说清「已保存但**没有启动**」，以及两个真实入口。
3. **提示条不再自我隐藏**：`renderDispatchBar` 原来 `if (!d) { box.hidden = true }`
   —— `dispatch` 接口是 404，于是整条提示消失，
   「作业不会自己跑」这个最该说的话也一起没了。现在拿不到 dispatch
   就按"没有调度器"处理，照样把话说出来。

## 三、watchdog 不实时（采样停更 52 小时）

### 现象

`.compshare/watch.log` 最后一条是 **11-09 18:30**，停更 52 小时。

### 根因

`b1d70e7`（上线 `p2-reaper.timer`）撤掉了 cron 里的 `csctl.py watch`。
撤得对 —— 它按 GPU 利用率 15 分钟停机，装模型阶段 GPU 也是 0%，会误关；
而 reaper 用的是更准的判据（作业状态 + 生命周期窗口）。

**但 watch 顺手还干了另一件事**：每 5 分钟往 `watch.log` 写一行采样。
那是全系统唯一的运行时观测数据源：

- 实例页的 GPU% / CPU% / 空闲时长 / 累计花费（`tools/p2/instances.py` 解析它）
- 看板「watchdog」那张表的时间线
- `arch.py` 架构图的实例状态

撤掉 watch = 这三处同时断粮。

### 还有一个"沉默的帮凶"

`instances.py` 只在 `watch.log` **完全为空**时才提示。
文件里有 11-09 的老数据，所以 `notes` 是空的，页面看起来一切正常，
实际一个样本都没在更新。用户报"不实时了"，代码这边**一句告警都没有**。

### 修复

1. **拆开两件事**：判据（谁停机）归 reaper，采样（谁记录）归新工具
   `tools/p2/sampler.py`。它**只读** —— 不停机、不销毁、不改任何状态。
   有测试专门守着这一点（扫源码确认没有 `.stop(` / `.terminate(`）。
2. `install_cron.sh` 改为装 sampler，并**主动清理**历史遗留的
   `csctl.py watch` 条目。
3. `instances.py` 新增 `STALE_MIN = 20`（= 漏 4 轮）。超过就在 `notes` 里
   明确告警「采样已停更 N 分钟，cron 里的 sampler.py 可能没在跑」。
4. `gpu=n/a` 解析成 `None` 而不是 `0` —— `0` 会被当成"GPU 确实闲着"，
   而真相是"读不到"。

## 四、顺手抓到的：静态资源 `immutable` 一年

`_ui_asset` 原本对非 HTML 发：

```
Cache-Control: public, max-age=31536000, immutable
```

注释写的理由是「Vite 产物名带内容 hash，可以放心长缓存」。

**但 `web/dist` 是源码，不是构建产物。** 文件名固定是 `app.js` / `app.css`，
永远不带 hash。后果：

- 改一次前端，用户浏览器整整一年看不到
- `immutable` 连**强制刷新都跳过校验**，所以"刷新一下"也没用
- 表现成「UI 改了还是老样子」，排查时被误判成"前端没同步"

**这很可能就是之前"UI 没同步"那次投诉的真正原因。**

改成 `no-cache`（可以缓存，但每次必须回源校验）+ 强 `ETag`（mtime+size），
命中就回 304 空响应。

## 验证

测试：**Python 828（p20 211 / p1 99 / webui 163 / p2 355）+ JS 6 个文件**，全绿零跳过。

真机验证（fileserver 重启后）：

```
Cache-Control: no-cache          ← 不再 immutable
ETag: "1794409635-10c22"
带 If-None-Match → 304            ← 回源校验生效
app.js 含 runPending/_fetch       ← 新代码已上线
notes: ["采样已停更 3162 分钟…"]   ← 会自己说原因了
POST /api/p2/jobs/run → 400/正常   ← 「执行」按钮指向的接口可用
```

## 仍然没解决的

1. **没有常驻调度器**。`p2-dispatch.service` 仍是 `disabled`。
   现在靠「手动点执行」+ 对账兜底。要不要开、开几个槽，是需要单独决定的
   —— 它涉及自动建机和钱的边界。
2. **作业超时后仍需人工/对账收尾**。用户如果一直不点「执行」，
   作业会在 60 分钟后被对账判 FAILED（这是有意的：不伪造成功）。
3. **采样器每 5 分钟一轮**，实例页最坏有 5 分钟延迟。要秒级得改成
   实例页直接调云 API（有费用、有限流），另议。

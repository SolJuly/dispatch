### 2.3 两层镜像架构（D2）

CompShare 没有 Docker 式 layer，`save-image` 只能「从一台实例打包成镜像」。所以「叠加」的落地方式是**镜像链**：

```
L0 平台基础镜像（ComfyUI 0.36 纯净版，30GB，不动）
 └─ L1  p2-comfy-base-v1   ← 烘焙：start.d patch / Manager 禁用 / 挂载配置 / 软链
 │                            node map 缓存 / rsync(+jq) / 离线 wheels / marker
 │                            【不装 ffmpeg】
 └─ L2  p2-comfy-media-v1  ← 从 L1 起机 → apt install ffmpeg → 清理 → save-image
                              marker: layer=media, base=p2-comfy-base-v1
```

**关键取舍（延续 v1 计划，不变）**：权重不进镜像。`/model`（UPFS 40T 只读）已实测跨 stop/reboot/save-image/terminate 全保留，所以「模型预置」= **预置它的挂载与可见性 + 软链**，而不是复制文件。

| 层 | 内容 | 体积 | 用途 |
|---|---|---|---|
| L1 base | 环境固化 + rsync | 30 → ~31GB | **图片 job（Qwen）**：无 ffmpeg 需求，镜像更小更快 |
| L2 media | base + ffmpeg | +~200MB | **视频 job（H3/LTXV/Wan）**：实例内跑 freezedetect/黑帧**预筛**，废片不拉省带宽；`rm --archive` 走 rsync；拼接/诊断可上机 |

**ffmpeg 放 media 层的实际收益**：批量并发后，一张 200MB 的废片如果先在实例内判掉（freeze/黑帧），就不用回传再判，省带宽 + 省 3–5 分钟传输等待。这是 media 层区别于 base 层的真正价值。

## 3. 目标二：质检逻辑升级（freezedetect 替换亮度静止检测）

### 3.1 旧逻辑为什么在「动作集中」的视频上误报（本机实测，¥0）

`verify.py` 的静止判定是 `signalstats.YAVG` 逐帧亮度均值的窗口最大差（阈值 0.10）。**亮度均值差 ≠ 内容变化**：画面里的人一直在走，但只要整体曝光稳定，YAVG 几乎不动。

刚在本机跑的对照（`testsrc2` 是持续运动、边缘能量 3.76 的高细节画面）：

| 样本 | 窗口最大帧差 | 亮度 σ | 边缘能量 | freezedetect 事件 | 旧逻辑判定 |
|---|---|---|---|---|---|
| `testsrc2` 持续运动（合成） | **0.067** | **0.19** | 3.76 | **0** | ❌ 误报「几乎静止」+「曝光异常」 |
| 纯色静态（合成） | 0.000 | 0.00 | 0.00 | 1（freeze_start=0，冻到片尾） | ✅ 正确 |
| H3 T2V 成功样本 | 0.278 | 正常 | 1.56 | 0 | 无告警（侥幸） |
| LTXV 噪点失败样本 | 0.380 | 正常 | **0.49** | **0** | 只报「缺细节」 |

两个硬结论：

1. **误报是真的**：运动最剧烈的合成样本，在旧指标下同时触发「静止」和「曝光异常」两条告警。
2. **freezedetect 不是万能的**：噪点/抽象色块样本 freeze 事件为 0（它不冻结，它在抖）。**所以这条不能删 edge_energy**，否则会丢掉 P1 唯一抓住 LTXV 失败的指标。

### 3.2 新指标定义

| 指标 | 定义 | 语义 | 来源 |
|---|---|---|---|
| `freeze_ratio` | Σ冻结时长 / 总时长 | 全片有多少比例是「真冻住」 | `freezedetect` |
| `freeze_longest_s` | 单次冻结最长秒数 | 有没有「卡住好几秒」 | `freezedetect` |
| `freeze_events` | 冻结段数 + 起止时间 | 可追溯（写进 details） | `freezedetect` |
| `motion_score` | 窗口内 `signalstats.YDIF` 最大值 | 内容变化强度（比 YAVG 差贴近内容） | `signalstats` |
| `edge_energy` | 拉普拉斯平均亮度 | **保留**：抓噪点/抽象/糊片 | 现有实现 |

`freezedetect` 是**逐像素帧差**判定的（tolerance `n` + 最短时长 `d`），不是亮度均值，所以天生不吃「曝光稳定」的亏。

### 3.3 实现要点（踩坑预警）

```bash
ffmpeg -v error -i IN.mp4 \
  -vf "freezedetect=n=0.003:d=0.3,metadata=print:file=-" -f null -
```

本机 4.4.2 实测输出形态（**必须按这个解析**）：

```
# 冻结后恢复运动：两个事件都出现
lavfi.freezedetect.freeze_start=0
lavfi.freezedetect.freeze_duration=1
lavfi.freezedetect.freeze_end=1

# 冻结到片尾：只有 freeze_start，没有 end/duration  ← 极易漏算
lavfi.freezedetect.freeze_start=0
```

三个坑：
1. **无 `freeze_end` 的尾段**：必须用 `duration - freeze_start` 补齐，否则「整片静止」会被算成 0 秒冻结（正好是最该拦的情况）。
2. **事件配对**：按 `freeze_start` 顺序压栈，遇 `freeze_end` 弹栈配对，最后残留的用片长收口。
3. **耗时**：一次全解码，5s / 121 帧的片子 <1s；沿用现有 `limit` 思路（超长片只取前 N 帧）并标注 `partial: true`。

### 3.4 判定口径：门禁 + 严格管控（D3，已实现）

**D3 已定：做门禁且严格管控。** 落地方式（代码已就位）：


### 4.1 `csctl pull` 目录探测 bug

**根因复核**（对照 `reports/p1/csctl-pull-目录探测bug.md`，代码确认）：

| 层 | 位置 | 问题 |
|---|---|---|
| 触发 | `tools/transfer.py:344` `_classify()` | 满载实例上一条 `test -d` 也可能超 30s |
| 无重试 | `tools/transfer.py:92` `ssh()` | `subprocess.run(timeout=)` 超时抛 `TimeoutExpired`，**无 try** |
| 无兜底 | `pull()` 第 154 行起 | `probe()` / `_classify()` 都在 `try` **之外** |

**采用方案 B+（B 加一层重试）**，补丁形状：

```python
# 1) ssh() 捕获超时，返回 124（调用方已全部按 (rc, out) 使用，无异常依赖）
def ssh(self, cmd, timeout=120, retries=1):
    for i in range(retries):
        try:
            r = subprocess.run(self._ssh_base() + [cmd], capture_output=True,
                               text=True, timeout=timeout)
            return r.returncode, (r.stdout or "") + (("ERR:" + r.stderr) if r.returncode else "")
        except subprocess.TimeoutExpired:
            if i + 1 < retries:
                time.sleep(3); continue
            return 124, f"TIMEOUT({timeout}s)"

# 2) _classify 遇 124 明确降级 + 提示，探测超时 30s → 60s
rc, out = self.ssh(f"if [ -d {remote} ]; then echo DIR; else echo FILE; fi",
                   timeout=60, retries=2)
if rc == 124:
    print(f"    ⚠ 目录探测超时（已重试），按单文件处理: {remote}")
    return "file", [posixpath.basename(remote)], posixpath.dirname(remote)

# 3) pull() 把 probe()/_classify() 收进 try，超时不再终止整个 pull
```

**这是主链文件**（`tools/transfer.py` 在冻结清单里）。按 §0.2 的规矩，走**已声明改动**：单 commit + 在 `reports/p1/主链冻结清单.md` 增补一行 + 机械核对命令里显式豁免 `tools/transfer.py`。回滚：`git checkout main -- tools/transfer.py`。

**测试（¥0，`tools/p2/tests/test_transfer_timeout.py`）**：

1. monkeypatch `subprocess.run` 抛 `TimeoutExpired` → `ssh()` 返回 `(124, "TIMEOUT(60s)")`，不抛
2. 同样注入 → `_classify()` 返回 `("file", [name], dir)`，且不崩
3. 注入到 `probe()` → `pull()` 返回 False 而不是抛异常
4. 正常路径回归：文件 / 目录 / 通配符三种分类不变

**真机验证**（搭 M1 烘焙实例，¥0 额外）：满载（跑着推理）时 `csctl pull` 目录 → 不崩；`pull` 单文件 → 不崩。

### 4.2 视频/图片自动拼接（`tools/p2/concat.py`）

**能力矩阵**：

| 场景 | 方案 | 说明 |
|---|---|---|
| 同参数多段视频（同 codec/尺寸/fps） | `concat` demuxer + `-c copy` | 无损、秒级；H3 4 段 → 长片首选 |
| 异参视频（H3 24fps 768×512 + Wan 16fps 832×480） | 重编码归一 | `scale+pad` → `fps` → `libx264 -crf 18 -pix_fmt yuv420p` |
| 图片多张 → 拼版 | PIL 网格（hstack/vstack 等价） | `--cols` / `--gap` / 编号标注 |
| 图片序列 → 视频 | `-framerate N -i %04d.png` | 顺手支持（画廊/预览用） |

**兼容性判定**（先探测再决定，不猜）：

```python
key = (codec, w, h, fps, pix_fmt, time_base)
fast = len({key_of(p) for p in inputs}) == 1      # 全同 → copy
```

**CLI**：

```bash
python3 tools/p2/concat.py video --inputs a.mp4 b.mp4 c.mp4 --out long.mp4 \
        --mode auto --fps 24 --size 768x512 --xfade 0        # auto = 能 copy 就 copy
python3 tools/p2/concat.py image --inputs 1.png 2.png 3.png 4.png \
        --out sheet.png --cols 2 --gap 8 --label
python3 tools/p2/concat.py probe --inputs a.mp4 b.mp4        # 只打印兼容性判定
```

**必做的三件事**（否则拼出来的片子是废的）：

1. **时间基线**：`-fflags +genpts`，重编码路径加 `-vsync cfr`；copy 路径若 `time_base` 不同直接降级重编码。
2. **音轨**：现有产物**无音频**（H3 只用了视频分支）→ 统一 `-an`；若某段有音轨，copy 路径取第一段音轨并显式 `-map`，重编码路径 `-c:a aac`。
3. **拼完必校验**：复用 `verify.probe()` 断言 `总时长 ≈ Σ输入 ±1 帧`，并把输入文件的 sha256 + 拼接参数写进 `manifest.derived`（可追溯，符合 P1 的 provenance 习惯）。

**集成位点**：不做新的 job kind（`run.py` 的九步是围绕 GPU 建机设计的，硬塞本地步骤会把状态机搞脏）。改成 **post 步骤**：

```jsonc
// job.json（可选）
"post": [{ "op": "concat", "inputs": ["…/01-a.mp4", "…/02-b.mp4"], "out": "long.mp4" }]
```

在 `PERSISTED` 之后、`RELEASING` 之前执行（本地、零 GPU、零成本），产物进 `artifacts/`，`manifest` 追加 `derived` 段。守卫 G1 不受影响（依然先落盘再销毁）。

**验收**：

- [ ] 同参 3 段 copy 拼接：时长 = 3 段之和 ±1 帧，`decode` PASS，**速度 ≥100× 实际时长**
- [ ] 异参（24fps + 16fps）auto 降级重编码：输出 fps/尺寸符合 `--fps/--size`，时长正确
- [ ] 图片 4 张 → 2×2 拼版，尺寸 = 2w+gap，含编号
- [ ] 拼接失败（某段损坏）→ 明确报错并指出是哪一段，不产出半片
- [ ] `manifest.derived` 记录输入 sha256

### 5.2 目标架构

```
            ┌────────────────────────────────────────────────┐
            │  batchctl (CLI)  submit / show / list / cancel │
            └───────────────┬────────────────────────────────┘
                            │ 写 queue.db（事务）
            ┌───────────────▼────────────────────────────────┐
            │  queue.db (SQLite WAL)                          │
            │  batch │ item │ worker │ event                  │
            └───────────────┬────────────────────────────────┘
                            │ claim / heartbeat / finish
            ┌───────────────▼────────────────────────────────┐
            │  scheduler.py                                    │
            │  ① 平台对账（cs.list → 僵尸/失联）                │
            │  ② 槽位 = min(cfg.max_concurrency, 剩余配额)      │
            │  ③ 预算熔断（日/批/单 job）                       │
            │  ④ 放置：卡型有货 + 价格上限 + 错峰                │
            └───────────────┬────────────────────────────────┘
                            │ 每槽一线程
            ┌───────────────▼────────────────────────────────┐
            │  executor.run_one(job_id)  ← 从 run.py 抽出       │
            │  九步不变：provision→…→release                    │
            │  per-job 锁；步骤/事件/账本与 P1 完全一致          │
            └───────────────┬────────────────────────────────┘
                            │ 产出
         job.json / manifest.json / run.log / artifacts / ledger
                            │
            ┌───────────────▼────────────────────────────────┐
            │  status2 / gallery / arch H 区（多作业视图）       │
            └────────────────────────────────────────────────┘
```

**关键设计决策（3 条，都是为了让 P1 的资产零风险复用）**：

1. **job 状态机不动**。队列状态（`queued/claimed/running/done/failed/cancelled`）活在 `queue.db`，job 的 15 态只描述「这台机器上发生的事」。`CREATED` 之前不存在 GPU 语义，天然适合排队。→ G1/G2/CAS/`events.jsonl` 一行不改。
2. **一实例一 job**。P2 不做「一实例多 job 流水」（ComfyUI 的队列串行、显存不可分割，混跑只会互相拖慢）。批量 = N 台实例并行 N 个 job。
3. **`run.py` 保留**。批量出问题时，单任务路径必须还能跑——这是回滚保险。

### 5.3 队列数据模型（`reports/p2/queue.db`）

```sql
PRAGMA journal_mode=WAL;
PRAGMA busy_timeout=5000;
PRAGMA foreign_keys=ON;

CREATE TABLE batch (
  batch_id     TEXT PRIMARY KEY,
  name         TEXT,
  created_at   TEXT NOT NULL,
  spec_glob    TEXT,
  max_concurrency INTEGER,          -- 本批并发上限
  budget_cny   REAL,                -- 本批预算上限
  max_minutes  INTEGER,
  state        TEXT NOT NULL DEFAULT 'open'   -- open/paused/closed
);

CREATE TABLE item (
  job_id       TEXT PRIMARY KEY,     -- 复用 P1 的 p1-YYYYMMDDTHHMM-6hex
  batch_id     TEXT REFERENCES batch(batch_id),
  spec_sha256  TEXT NOT NULL,
  params_hash  TEXT NOT NULL,
  priority     INTEGER NOT NULL DEFAULT 0,
  model_key    TEXT,
  required_gpu TEXT,                 -- JSON 数组
  est_cost     REAL,
  state        TEXT NOT NULL DEFAULT 'queued'
               CHECK (state IN ('queued','claimed','running','done','failed','cancelled','skipped')),
  worker       TEXT,
  lease_until  INTEGER,              -- unix ts
  attempts     INTEGER NOT NULL DEFAULT 0,
  max_attempts INTEGER NOT NULL DEFAULT 2,
  enqueued_at  TEXT NOT NULL,
  started_at   TEXT, ended_at TEXT,
  cost         REAL, last_error TEXT
);

-- 去重：活跃态下同一 params_hash 只允许一条（§5.1 #9）
CREATE UNIQUE INDEX ux_item_params_active
  ON item(params_hash) WHERE state IN ('queued','claimed','running');

CREATE INDEX ix_item_pick ON item(state, priority DESC, enqueued_at);
CREATE INDEX ix_item_batch ON item(batch_id, state);

CREATE TABLE worker (
  worker_id    TEXT PRIMARY KEY,
  pid          INTEGER, slot INTEGER,
  job_id       TEXT, instance_uid TEXT,
  heartbeat_at INTEGER, started_at INTEGER,
  state        TEXT                           -- idle/running/dead
);

CREATE TABLE event (
  ts INTEGER, item_id TEXT, from_state TEXT, to_state TEXT, detail TEXT
);
```

选 SQLite 的理由：stdlib 自带（环境无网络装包）、事务级原子 claim、崩溃可恢复、查询方便。`queue.db` 只放**队列事实**，job 的事实仍在 `job.json`（单一事实来源不打架）。

### 5.4 claim / heartbeat / requeue 协议

```python
# 领取（单语句事务，天然防双领）
BEGIN IMMEDIATE;
  SELECT job_id FROM item
   WHERE state='queued'
   ORDER BY priority DESC, enqueued_at ASC LIMIT 1;
  UPDATE item SET state='claimed', worker=:w,
         lease_until=:now+LEASE, attempts=attempts+1
   WHERE job_id=:j AND state='queued';
COMMIT;   -- 影响行数=1 才算领到
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `LEASE` | 180s | 租约；worker 每 30s 心跳续约 |
| `max_attempts` | 2 | `FAILED_PROVISION`（无货/226604）与实例失联可重试；`FAILED_VERIFY` 不重试（参数问题，重跑只是烧钱） |
| 重试退避 | 60s × attempts | 抖动退避 ±20% |
| 僵尸判定 | 心跳 > 180s | 标 `worker.state='dead'`，其 `claimed/running` 项复位为 `queued`（attempts 已计数） |
| 实例回收 | 名称 `p2-*` 且创建 > TTL(45min) 且无租约 | `terminate` + 写 `event`（防止幽灵实例） |

### 5.5 调度策略

1. **并发上限**：`min(cfg.max_concurrency, 账面配额 - 活跃实例数)`。配额来源：`DescribeCompShareInstance` 实时计数（不写死 5）；`cfg.max_concurrency` 默认 **2**（首轮联调保守值，跑稳再提 3–5）。
2. **卡型放置**：`required_gpu` 按顺序试；`cs.stock()` 为 0 → 该项**留在队列**（不是失败），退避 60s 重试；`--wait-stock` 语义沿用 run.py。
3. **创建串行化**：所有 `create` 走一把进程内锁 + 15s 最小间隔（`--stagger 15`）。理由：`226604` 竞态 + 平台创建限流，并发下单只会互相抢。
4. **价格闸门**：`--max-hourly`（沿用 csctl 语义），超价跳过该卡型而不是硬上。
5. **Spot**：`charge_type=Spot` 时自动 `max_attempts=1`（回收即重排一次，防无限重试）；
   注意 `Spot 不支持手动关机` 与 `定时关机` —— 批量用 Spot 只能靠「结束即 terminate + TTL reaper」，这一点写死在调度器里。
6. **失败分流**（决定重排还是收工）：`FAILED_PROVISION` → 重排；`FAILED_RUN`（含实例消失）→ 重排（attempts<max）；`FAILED_FETCH` → 重排 1 次后放弃；`FAILED_VERIFY` → 不重排，落 `failed` 供人看。
7. **收工**：每项结束都保证「实例已 terminate」（executor 的 `release` 步骤），reaper 再兜一层。

### 5.6 预算熔断（`tools/p2/budget.py`）

并发把烧钱速度乘 N，所以熔断必须是**中心化**的：

```
当日已花（ledger 按日聚合） + 在跑实例的实时燃烧（hourly × elapsed） + 本批已花
  > cap  →  停止 claim（不杀在跑的），写 event，CLI 红字提示
```

三档 cap：`--daily-budget`（默认 ¥8，沿用 lab 的安全阀口径）、`--batch-budget`、单 job `budget.max_cost`（P1 已有）。

| R9 | 实例泄漏 | worker 崩、Spot 回收、终止失败 | 按小时白烧 | 心跳 TTL + reaper + 每实例 `stop_at` 兜底 + `doctor` 对账 |

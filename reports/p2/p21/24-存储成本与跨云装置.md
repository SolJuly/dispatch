# 存储成本：三条路、一个受控实验、一套跨云装置

> 2026-11-09。目标三个：**降存储成本 + 任务时长不变长 + 为跨云铺垫**。
> 本文说明为什么最终选「停机实例」而不是「裸跑」，以及跨云为什么必须走脚本而不是镜像。

---

## 0. 一句话结论

| 目标 | 做法 | 状态 |
|---|---|---|
| 降存储成本 | 停机实例当环境模板（¥0 vs 镜像 ¥16.5/月） | ⏳ 24h 实验进行中 |
| 任务时长不变长 | 停机 `start` 91s vs 建机 105-117s，**反而快 15-25s** | 有 M5 实测支撑 |
| 跨云铺垫 | `deploy/env/provision.sh` + 声明式 manifest | ✅ 已交付 |

**裸跑方案被否决**：省 ¥16.5/月，但每作业多 30-90 秒，且对跨云毫无帮助。

---

## 1. 为什么「裸跑」不满足目标

### 1.1 它确实能省存储费

平台公有镜像（61 个 App 类型）是平台资产，不占用户账单。
用 `ComfyUI基础镜像纯净版0.43.0` 替代 70GB 自定义镜像，存储费 ¥16.5/月 → ¥0。

### 1.2 但它让任务变长

真实作业时间线（`p1-20261108T1352-3d1616`）：

```
+  0s  已创建，等 Running
+ 52s  sshd 就绪                    ← 平台建机
+ 47s  setup 完成                    ← 镜像已烘焙，走快路径
+  9s  ComfyUI 就绪
+300s  推理（真正的活）
```

那 47 秒之所以能这么短，是因为镜像里已经固化好：`/root/.p2_image.json` marker 一命中，
`instance_setup.sh` 直接跳到轻量核对。

裸跑要跑完整 setup 路径（推 yaml → sed 打补丁 → 建软链 → 杀进程 → 重启 → 轮询），
M1 实测会多花 **25-40 秒**。再叠加侧载 8.9MB 包（320KB/s ≈ 0.5 分钟）→ **每作业多 30-90 秒**。

### 1.3 它对跨云毫无帮助

镜像（`compshareImage-*`）是智云私有格式，换云就不存在。
用哪个平台的镜像，都改变不了这件事。

**所以裸跑只满足 1/3 个目标，否决。**

---

## 2. 真正的解法：停机实例当模板

### 2.1 依据

平台计费规则（`README.md:66-68` 与在线文档）：

> - 按量后付费 = 秒级计费，整点出账单；**关机后 CPU/GPU/内存停止收费，只保留云盘**。
> - **系统盘 SSD ≤100GB 免费**（工具默认就是 100G），超出部分才收。

价格接口也直接印证：

```
system_disk=100GB → instance=¥2.15/h  disk=¥0.00/h  total=¥2.15/h
system_disk=120GB → instance=¥2.15/h  disk=¥0.02/h
system_disk=200GB → instance=¥2.15/h  disk=¥0.05/h
```

**一条推论**：一台停机实例（系统盘 100GB）= 算力 ¥0 + 磁盘 ¥0 = **¥0/月**，
而它的磁盘上就是完整环境（ComfyUI + 10 个 custom_nodes + torch 2.8）。

### 2.2 而且它更快

M5 预热池实测（`reports/p2/M5-预热池-设计与验收.md`）：

| 方式 | `create`/`start` → Running | → ComfyUI 就绪 |
|---|---|---|
| 新建实例 | 65-74s | **105-117s** |
| 停机实例 `start` | 57.6-62.3s | **91.2-91.5s** |

**快 15-25 秒。** 停机的磁盘是热的，不需要重新拷贝镜像层。

### 2.3 代价：占配额

智云 Level1 = 5 台。池里留 1 台 = 并发上限降到 4。

这个代价在单任务串行模式下（当前状态）等于没有 —— 本来就用不到 5 台。

### 2.4 但这只是推论，必须实证

`README` 说的「关停收费」和「系统盘 ≤100GB 免费」是两条独立规则，
**没有任何地方明确说过「停机实例的系统盘不收费」**。
两条规则加起来应该推出 ¥0，但平台的实现可能有别的口径（比如停机时按数据盘收费、
或者镜像快照单独计费）。

所以启动了受控实验。

## 3. 受控实验：`tools/p2/idle_billing_probe.py`

### 3.1 设计

```bash
# 1) 创建一台实例（v4 镜像，4090，100GB 系统盘）
python3 csctl.py up --gpu-type 4090 --image p2-comfy-media-v4 --disk 100

# 2) 确认环境完整，然后停机（不销毁）
python3 csctl.py stop uhost-xxx

# 3) 开始观测
python3 tools/p2/idle_billing_probe.py start --uid uhost-xxx

# 4) 每小时采样（已加 cron: 7 * * * *）
python3 tools/p2/idle_billing_probe.py sample

# 5) 一天后看结论
python3 tools/p2/idle_billing_probe.py report
```

**独立账本**：`.compshare/idle_probe.jsonl`，不污染主 ledger 的 settle 推断。
这是受控实验，不该和日常成本混在一起。

### 3.2 判定逻辑

```
停机期间余额下降 Δ，期间无其它实例在跑  →  停机计费 = Δ
停机期间余额下降 Δ，但期间有作业开销 S  →  停机计费 = Δ - S
停机期间余额不变                        →  停机计费 = 0  ✅ 方案成立
```

采样时同时记录 `others_running`，任何一台别的实例在跑都会标脏，
避免把作业费误算成停机费。

**必须跑满 24 小时**，因为镜像费是 **01:10 日结**（见 `23-镜像存储费与零成本路线.md`）。
不到一天根本看不到那笔扣费。

### 3.3 当前状态

```
════════════════════════════════════════════════════════════
停机计费实验 · uhost-1xhk1c21vlfw (exp-offline-24h)
磁盘 100 GB · 卡 4090
开始 2026-11-09 11:36:56  余额 ¥8.38
════════════════════════════════════════════════════════════
采样 2 次，跨度 0.0 小时
2026-11-09 11:37:05  Stopped          8.38
2026-11-09 11:37:08  Stopped          8.38  (+0.00)
────────────────────────────────────────────────────────────
余额变化  ¥8.38 → ¥8.38   Δ = -¥0.00
⏳ 才 0.0 小时，不足 24h。要覆盖一次 01:10 日结才准。
```

**明天 11-10 11:37 之后跑 `report` 才有结论。**

### 3.4 三种结局

| 结局 | 含义 | 动作 |
|---|---|---|
| Δ = 0 | 方案成立 | 切换：删掉 v4 镜像（省 ¥16.5/月），改用停机实例 |
| Δ ≈ ¥0.55/天 | 停机也收磁盘费（等同镜像） | 方案作废，继续用镜像 |
| Δ 很大（¥51/天） | 停机仍在收算力费 | **立刻销毁**，平台规则与文档不符 |

## 4. 跨云：为什么要写脚本而不是选镜像

### 4.1 智云上做不了跨云

```python
# reports/p2/M1-镜像提速-验收.md:30
1. **实例无外网**：DNS 都解析不了（`Name or service not known`）
   → apt / pip / GitHub 全部不可用
```

实测确认（`provision.sh` 在本机直接拒绝）：

```
[01] 检查前置条件
     ! github.com 不可达 —— 拉不了 ComfyUI / custom_nodes
✗ 实例无外网。这是智云的特征：本脚本在智云上不可用。
```

`create()` 也只接受 `CompShareImageId`，没有 registry 字段；
也没有镜像导入 API（10 个候选 Action 全部 `not found`）。

**所以：智云上用镜像/停机实例，别家云上用脚本。同一份环境描述，两种执行方式。**

### 4.2 交付物

#### `deploy/env/comfyui-wan-p21.env.json` — 声明式环境

这是**唯一真相源**。镜像只是它在智云上的一个快照。

```json
{
  "schema": "p2.env/v1",
  "base": { "python": "3.10", "cuda": "12.8", "system_packages": [...] },
  "python": {
    "pins": { "torch": "2.8.0+cu128", "torchaudio": "2.8.0+cu128", "torchvision": "0.23.0+cu128" },
    "constraints_file": "docker/constraints.txt",
    "exclude": { "xformers": "与 torch 2.8 ABI 不匹配" }
  },
  "comfyui": { "commit": "3c80da7f...", "version": "0.36.0" },
  "custom_nodes": [ 10 个，每个带 repo + 40 位 commit ],
  "models": { "strategy": "external", "search_roots": ["/model/..."] },
  "platform_notes": { "compshare": { "can_pull_oci": false, "instance_has_internet": false } }
}
```

#### `deploy/env/provision.sh` — 从空机器装到可跑

7 个步骤，幂等：

| 步 | 做什么 |
|---|---|
| 01 | 前置检查（**没外网就明确拒绝**，而不是半途失败） |
| 02 | 系统依赖（git/wget/ffmpeg/编译工具） |
| 03 | torch（版本不符才装；卸掉 xformers） |
| 04 | ComfyUI（clone + checkout 钉版） |
| 05 | ComfyUI 依赖（按 constraints 锁 183 个包） |
| 06 | 10 个 custom_nodes（逐个 clone + checkout + 装依赖，过滤 git+/sam2） |
| 07 | 验证（`/object_info` 能开、21 个第三方节点抽样、模型可见） |

```bash
bash deploy/env/provision.sh --dry-run        # 打印计划
bash deploy/env/provision.sh                  # 真装
bash deploy/env/provision.sh --skip-torch     # torch 已装
bash deploy/env/provision.sh --verify-only    # 只验证
```

### 4.3 与 `instance_setup.sh` 的分工

| | 做什么 | 依赖什么 |
|---|---|---|
| `provision.sh` | **安装**：torch / ComfyUI / custom_nodes / pip | 需要外网 |
| `instance_setup.sh` | **配置**：推挂载 yaml / 禁 Manager / 建软链 / 启动 / 自检 | 假设上面都装好了 |

`instance_setup.sh` 之所以能在智云上跑，是因为镜像已经把「安装」做完了。
换云时先跑 `provision.sh`，再跑 `instance_setup.sh` —— 两步走通即复现。

## 5. 顺带修掉的真 bug：Dockerfile 版本错了一年

`docker/Dockerfile` 里写的是 **torch 2.10.0+cu130**，但 v4 实机是 **2.8.0+cu128**。

实机证据（在跑着的 v4 实例上读出来的）：

```json
// /root/.p2_image.json
{
 "name": "p2-comfy-media-v4",
 "comfyui": "3c80da7f87ee359b2d06f107cb3c0797079dfbbb",
 "torch": "2.8.0+cu128",
 "classes": 1757
}
```

而 `22-v4镜像构建.md` 第 16 行也写着：

> Python / torch | 3.10.15 / **2.8.0+cu128**（v3 是 2.10+cu130）

**Dockerfile 是从 v3 抄的，没跟着 v4 更新。**

### 更麻烦的是 `constraints.txt` 同时锁了两套 CUDA

```
nvidia-cublas-cu12==12.8.4.1        ← torch 2.8 需要
nvidia-cudnn-cu13==9.15.1.9         ← torch 2.10 需要
nvidia-nccl-cu13==2.28.9            ← 同上
nvidia-nvshmem-cu13==3.4.5          ← 同上
...
```

**16 个 cu13 包和 14 个 cu12 包并存。** 用这个 constraints 装 torch 2.8 会直接冲突。

### 修了什么

| 文件 | 改动 |
|---|---|
| `docker/Dockerfile` | torch 2.10+cu130 → **2.8.0+cu128**，index URL 同步 |
| `docker/constraints.txt` | torch/torchaudio/torchvision 改到 cu128；**删掉 16 个 cu13 与无后缀 nvidia 包** |
| `docker/constraints.txt` | 保留 `nvidia-ml-py`（它是 pynvml 的实现，不是 CUDA 运行时） |

现在 constraints 是纯 cu12 系列，183 个包，与 v4 实机一致。

> 这个 bug 是写测试时被抓出来的：`test_constraints_match_v4` 断言
> `assertNotIn("cu13", text)`。如果没有这条测试，下次真去烘镜像会卡在依赖冲突上，
> 而且不一定能看出是 constraints 的问题。

## 7. 待决策：要不要继续追「零镜像」

如果停机实验证明 ¥0，那么：

```
删掉 v4 镜像 → 省 ¥16.5/月
保留一台停机实例 → ¥0/月
起机还快 15-25s
```

**这是唯一同时满足「省钱 + 不变长」的方案。**

但有两个前提：

1. **实验必须证明停机真的 ¥0**（明天见分晓）
2. **得留一台常驻停机实例**，占 1/5 配额。如果哪天要多账号并行，这 1 台要腾出来

如果实验证明停机也收钱（¥0.55/天 ≈ 镜像价），那结论就变成：
**镜像和停机实例成本相同，但停机实例更快、更省事**，依然应该选停机实例。

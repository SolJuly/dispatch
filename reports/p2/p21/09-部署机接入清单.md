> 目标：把「图片控制台 + `/api/p2` + 文档/产物」从这台开发机搬到一台独立服务器对外服务。
> 状态：**待你提供 SSH 与三个选择项**；运行时包已就绪（`dist/p21-deploy-*.tar.gz`，19 MB / 633 文件）。
> 相关：`scripts/deploy_bundle.sh`、`scripts/p21_restore_share.sh`、`deploy/systemd/cs-files-restore.service`

## 2. 三种部署形态（先选一个）

| 形态 | 目标机要装什么 | 能做什么 | 不能做什么 | 工作量 |
|---|---|---|---|---|
| **A. 纯静态** | nginx | 文档、openapi、产物图片、Mock 演示 | 控制台页面、API、建作业 | 10 分钟 |
| **B. 控制台只读** | nginx + python3.10 + systemd | `/app/*` 页面、`/api/p2/*` 查询、产物下载 | 建作业（缺 GPU 凭证与执行链） | 30 分钟 |
| **C. 完整控制台** | B + `sshpass`/`scp` + 出网到 CompShare + `credentials.env` | 上面全部 + 建作业、起 GPU、20 连测 | — | 1 小时 + 凭证交接 |

我的建议：**先 B 后 C**。B 模式对外可看可查，不碰凭证；确认页面/接口没问题，再把 `credentials.env` 放上去切 C。

## 4. 迁移内容与体积

| 内容 | 大小 | 是否必须 | 说明 |
|---|---|---|---|
| 运行时包 `p21-deploy-*.tar.gz` | **19 MB** | ✅ | 代码 + registry 配置 + registry.db + queue.db + 任务台账（JSON）+ 文档；**不含** `.git`、`share/`、连测图、凭证 |
| `share/` | rsync 生成 | ✅（B/C） | 目标机解包后跑一次 `bash scripts/sync_share.sh` 即可，用于 `/files/<token>/` 文件浏览 |
| `.share_token` | 4 字节 | ✅ | 从开发机复制过去，保持公网链接不变；不复制则首次启动会生成新的 |
| `/srv/dsh-pub/{api,p20,p21,jobs}` | ~55 MB | ✅（要看图就必须） | `artifact.url` 指向 `/pub/jobs/...`，由 nginx 从这里读；控制台缩略图也走这个 URL。只迁 `jobs/` 也能显示图片，文档链接另需 `api/ p20/ p21/` |
| `credentials.env` | 极小 | C 模式 | GPU 平台凭证，**单独 scp，不进包**；权限 600，属主为运行用户 |
| crontab（watchdog/status2/arch/cost/risk） | — | C 模式 | 见第 7 节；B 模式只装 `status2` 也不需要 |

## 5. 我连上之后做什么

1. 预检（第 3 节），确认 8081 空闲、python ≥ 3.10、nginx 在跑；
2. scp 运行时包 → 解包到 `/root/智云视频工作流`，`mkdir share && bash scripts/sync_share.sh`；
3. 复制 `.share_token`（B/C）；
4. 装 systemd 单元 `cs-files.service`（`SHARE_ROOT=<repo>/share`、`SHARE_PORT=8081`、`SHARE_BIND=127.0.0.1`、`SHARE_BASE=/files`，`Restart=always`），`enable --now`；
5. nginx：加 `location /files/ → 127.0.0.1:8081`（`auth_basic off`，长连接、上传 `client_max_body_size 200m`）+ 可选 `location /pub/ → /srv/dsh-pub`；
6. 证书：`certbot --nginx -d <域名>`（有域名时）；否则先用自签 + `http`；
7. 健康检查（第 6 节），确认 `/api/p2/version` 的 `build.commit` 与包内 `BUILD` 一致；
8. B→C 时：放 `credentials.env`、装 `sshpass`、装 crontab，跑一次「建作业但不 `run`」的 dry-run；
9. 双跑观察 1 天（开发机只读，切流前不再建作业，避免 `queue.db` 分叉）；
10. DNS 切换 + 观察，保留回滚命令。

## 8. 风险与注意事项

- **CORS**：`/api/p2/*` 目前没有 CORS 头。前端如果和 API 不同源，必须用 nginx 同域反代（推荐），否则要后端加 CORS —— 告诉我一声我改。
- **鉴权面**：`/files/<token>/` 是唯一凭证，拿到链接就能看全部文件（含任务台账）。对外建议再加一层 nginx `auth_basic` 或 IP 白名单。
- **凭证**：`credentials.env` 只放 C 模式目标机，600 权限；不要进包、不要进 git（`.gitignore` 已排除）。
- **双写分叉**：`queue.db` + `reports/p1/jobs` 是本地状态。双跑期间两边都建作业会分叉，切流前只在一侧写。
- **GPU 出网**：C 模式需要目标机能出网到 CompShare API 与 GPU 实例的 SSH（默认 22 出站）；纯展示不受影响。
- **nginx 冲突**：目标机若已有站点，我只加 `location`，不动现有 `server`；改前备份，`nginx -t` 通过才 reload。

## 9. 回滚

- 目标机：`systemctl disable --now cs-files`，删 nginx 的两段 `location`，`nginx -t && systemctl reload nginx`；
- DNS 切回开发机；
- 开发机的 `cs-files` 仍在，随时可以继续当主站（`systemctl restart cs-files`）。

## 10. 现在就差你三个决定

1. **形态**：A（纯静态）/ B（控制台只读，推荐先这个）/ C（完整，含 GPU 凭证）；
2. **域名与 HTTPS**：有域名吗？DNS 能指过来吗？没有就先 `http://IP:8080`；
3. **目标路径**：沿用 `/root/智云视频工作流`（省事，脚本不用改）还是换 `/opt/zhiyun`（我会批量改路径）。

给到 IP / 端口 / 用户 + 公钥已授权，我这边 30–60 分钟能出 B 模式可访问的地址。

实际发生的事：

1. 上传 19 MB 包（637 文件）→ 解包到 `/root/智云视频工作流`，`.share_token` 原样带过去（`23e00ec2`）；

5. rsync `/srv/dsh-pub/{jobs,api,p20,p21}`（约 56 MB）→ 图片与文档链接可访问。

| `/files/23e00ec2/app/create` `/app/jobs` | 200 |
| `/files/23e00ec2/api/p2/jobs` | 200，20 条历史任务（台账已迁） |
| `/pub/jobs/p1-20261103T1219-b2df1a/01-…png` | 200（864 KB） |
| `/pub/api/openapi.json`、`/pub/p21/` | 200 |

部署中发现并修掉的两个真问题（两处都会让"看起来装好了"变成白屏/404）：

- `sites-enabled/default` 改名备份仍留在 `sites-enabled/` 里，`include sites-enabled/*` 会把它一起加载 → `duplicate default server`，nginx -t 失败；改为备份到 `/var/backups/nginx/`；
- 控制台「最近作业」缩略图用的是 `/files/<token>/pub/jobs/...`，但 fileserver 从来没有这条路由（开发机也一直 404，只是没人注意）；新增 `PUB_ROOT` + `_pub_file`，等价 nginx 的 `/pub/`。

已知差异（B 模式）：

- **不能建作业**：没有 `credentials.env`，`POST /api/p2/jobs` 会因缺少 GPU 执行链失败；升级 C 模式时补凭证 + `sshpass` + crontab；
- 没有 DNS/HTTPS，目前是 `http://47.236.143.49/files/<token>/`；有域名后 `certbot --nginx -d <域名>` 即可；
- 只读部署时作业目录里没有 `artifacts/`（包内已排除），`webui/api._artifacts` 会回退到 `/srv/dsh-pub/jobs/<id>`，缩略图仍可用（`d5a…` 提交引入）。

## 12. 回滚

```bash
# 目标机
systemctl disable --now cs-files
rm -f /etc/nginx/sites-enabled/cs-p21
mv /var/backups/nginx/default.disabled.* /etc/nginx/sites-enabled/default
nginx -t && systemctl reload nginx
```

开发机不受影响，`/files/` 仍在 `123.207.74.155` 正常运行。

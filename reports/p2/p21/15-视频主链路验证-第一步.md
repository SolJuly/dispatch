两条都已 `compat verify`，registry 的 `verified` 从 16 升到 18。

### 修掉的问题

1. **Wan2.2 权重名在子目录**：模板写 `wan2.2_i2v_low_noise_14B_fp8_scaled`，实际是 `wan2.2/wan2.2_i2v_low_noise_14B_fp8_scaled`；LoRA 在 `Wan_2.2_ComfyUI_Repackaged/` 下。资产检查用 `contains` 会误过，提交才 400。
2. **`ComfyMathExpression` 缺 `expression`**：官方 UI 图里是 `floor (a * b + 1)`（a=5,b=16 → 81 帧），API 图把 widget 丢了。已补进图。
3. **FLF2V 的 `image_2` 原来传不上**：`_normalize_image` 和 `run.py` 只处理 `image`/`mask`；已扩到 `image* / mask* / audio / video`，并加单测（现在 p20 90 个测试）。

## 2. S2V：不是权重问题，是图转换坏了

`pack_video_wan2_2_14b_s2v` 提交 400，逐节点错误：

- `AudioEncoderLoader` 缺 `audio_encoder_name`
- `KSampler.scheduler` 被连到了 `LoadAudio` 的输出（AUDIO），类型不匹配
- `WanSoundImageToVideoExtend` 缺 `video_latent`
- `LatentCut` 缺 `dim/amount/index`，`LatentConcat` 缺 `dim/samples1`，`ImageFromBatch` 缺 `length`
- `sampler_name: 77` 不是合法枚举

对比包里的 `workflows/api/...s2v.api.json` 和 `workflows/dsh/...s2v.dsh.json`，**两份图是同样的坏结构**，说明不是我们转换时丢的，是这套官方模板的 API/DSH 导出本身没把子图/控件值展开正确。

结论：**S2V 不能靠改权重名/补参数修好**，需要重新导出官方 UI 图或手工重建这 30+ 节点；当前不值得为它继续烧开机费。

## 3. Animate2：未跑，同类风险

`pack_video_wan_animate2` 的输入是：

- `image`（参考人物图）
- `LoadVideo.file = street_dance_drive.mp4`（驱动视频）
- `prompt` / `prompt_2`

原配置把 `image_2` 错标成 image 类型并绑到 `LoadVideo.file`；已改成 `video`（string，CLI 传本地路径，运行器归一化/上传）。但它的图里同样有 `ComfySwitchNode`、`WanAnimate2Cache`、`GetVideoComponents` 等复杂节点，**很可能和 S2V 一样有控件值/连线丢失**；没有再花一次开机费去撞。

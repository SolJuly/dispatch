## 4. 20 连测方案（验收标准 6）

**判定阈值（先定后测，不允许测完再改）**

| 指标 | 阈值 | 采集方式 |
|---|---|---|
| 成功率 | ≥ 19/20（95%），20 条全 DONE 且 `verify` PASS | `job.json` 状态机 + `bench-20.json` |
| 耗时 | 记录 submit→fetch 的 P50/P95；t2i P95 ≤ 90s（Qwen）/ ≤ 30s（SDXL） | `steps` 时间戳 |
| 显存 | 峰值 ≤ 22 GB（4090 24G 留余量）；Flux 类 ≥ 24G 的只用 48G 卡 | 实例内 `nvidia-smi --query-gpu=memory.used --format=csv` 每 2s 采样 |
| 成本 | 单张 ≤ ¥0.15（Qwen）/ ≤ ¥0.05（SDXL） | `hourly × 实际计费时长`，与 compshare 账单对账 |
| 一致性 | 同 seed 两次输出 sha256 一致 | 产物 sha256 |

**执行方式**：一次起机 → 预热池复用 → 20 条串行（不是 20 次起机）。20 次起机光开机费就 ¥1.5，串行只需 ¥0.5 左右。

**Prompt 集**：20 条从 4 类里分层取（人像 5 / 场景 5 / 文字排版 3 / 风格化 7），含 2 条故意踩边界（超长 prompt、极端宽高比），验证失败路径。

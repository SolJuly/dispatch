# 5.1 基础文生图 · 选型与工作流设计（基线方案）

> 版本 v1 · 2026-11-02 · 对应里程碑 M0 定稿、M1 落地
> 任务书要求：接入**一套经验证**的基础文生图工作流，支持 Prompt、Negative Prompt、Seed、宽、高、Steps、CFG、Sampler、Scheduler、Batch Size 和模型选择；优先稳定可复现、质量合格，不追求模型数量。

---

## 1. 结论

| 决策 | 内容 | 理由 |
|---|---|---|
| **基准模型** | **Qwen-Image**（`qwen_image`，fp8_e4m3fn_scaled） | 唯一在 P1/P2.0 两个阶段都真机验证过质量的工作流（4 次出图、3 次 PASS），细节优于 SDXL；任务书要的是"质量合格的基准"，不是最便宜 |
| **第二模型** | **SDXL / juggernautXL** | 4090 上 3.0s/张、10GB 显存；更关键的是 **5.2/5.3/5.4 的生态（inpaint、ControlNet、IP-Adapter、LoRA）几乎都长在 SDXL 上**，Qwen-Image 目前只有 t2i |
| **工作流版本** | `qwen_image_t2i@v2` + `sdxl_t2i@v1` | v1 缺 3 个参数（sampler/scheduler/batch），v2 补齐；SDXL 是新图 |
| **参数面** | 10 项全开 + `denoise`（给 5.2 复用） | 见 §3 覆盖矩阵 |
| **模型选择语义** | UI 的"模型"下拉 = 选择 **workflow**（每个 workflow 声明自己的 model key） | 不同模型族的图结构不同（UNETLoader vs CheckpointLoaderSimple），不能只换权重文件名 |

**不做**：Flux 作基准（冷启 60s、23.6GB 贴边 24G、单张成本 5 倍），SD1.5（质量不达"质量合格"线）。

## 2. 候选对比（数字均来自本项目实测）

| 候选 | 质量 | 预热后出图 | 冷启 | 显存 | 生态（inpaint/CN/IPA/LoRA） | 资产状态 | 证据 |
|---|---|---|---|---|---|---|---|
| **Qwen-Image** | ★★★★★ | **~35s** / 1024²·20步 | 装载 ~40s | ~12GB | ✗ 只有 t2i | ✅ 已入库、已出图 | `reports/p1/h3-qwen/README.md`、P2.0 三个作业 |
| **SDXL (juggernautXL)** | ★★★☆ | **3.0s** / 1024²·20步 | 16.6s | ~10GB | ✓ 全套 | ✅ 共享库命中，未入库 | `reports/fixes-20261026-1720.md`、`reports/audit-storage-2026-10-26.md` |
| Flux (dev/schnell) | ★★★★ | 15.0s | **60.2s** | **23.6GB**（贴边） | 部分 | ⚠️ 仅 lab 基准用过 | `reports/lab/REPORT.md` |
| SD1.5 | ★★☆ | 1.5s | — | 3.3GB | ✓ | 未盘点 | 同上 |

**为什么两个都要**：任务书要求"模型选择"和"模型/LoRA 兼容性检查"。只接 Qwen 就只有一个选项，无法验证选择链路；只接 SDXL 则质量基准不够。两个模型族刚好覆盖"质量优先"和"速度/生态优先"两条路径，也是后续 5.2–5.4 的公共底座。

## 3. 参数覆盖矩阵

| 参数 | 任务书 | `qwen_image_t2i@v1`（现状） | `@v2` 目标 | 落点 |
|---|---|---|---|---|
| prompt | ✓ | ✅ 已绑定 `pos.text` | ✅ | 不变 |
| negative prompt | ✓ | ✅ 已绑定 `neg.text` | ✅ | 不变 |
| seed | ✓ | ✅ 已绑定 `ks.seed` | ✅ | 不变 |
| 宽 / 高 | ✓ | ✅ `lat.width/height`，256–2048、16 对齐 | ✅ | 不变 |
| steps | ✓ | ✅ `ks.steps` 1–60 | ✅ | 不变 |
| cfg | ✓ | ✅ `ks.cfg` 0–30 | ✅ | 不变 |
| **sampler** | ✓ | ❌ 图里写死 `euler` | ✅ enum 绑定 `ks.sampler_name` | **新增** |
| **scheduler** | ✓ | ❌ 图里写死 `simple` | ✅ enum 绑定 `ks.scheduler` | **新增** |
| **batch size** | ✓ | ❌ 图里写死 `batch_size=1` | ✅ int 1–4 绑定 `lat.batch_size` | **新增** |
| **模型选择** | ✓ | ❌ 只有 `qwen_image` 一个模型 | ✅ 新增 `sdxl_t2i` + `sdxl_juggernaut` | **新增** |
| denoise | （5.2 用） | 图里 `1.0` | 不改 t2i，5.2 单独暴露 | 预留 |

**Sampler / Scheduler 取值来源**：以实例 `/object_info` 的 `KSampler.sampler_name[0]`、`KSampler.scheduler[0]` 列表为准（运行时缓存进 Registry `meta` 表），配置里只允许白名单子集，避免用户填了引擎不认的值。首批白名单：

- sampler：`euler`、`euler_ancestral`、`dpmpp_2m`、`dpmpp_2m_sde`、`uni_pc`
- scheduler：`simple`、`normal`、`karras`、`beta`

白名单之外的组合一律 `incompatible`（例：`uni_pc + karras` 在部分版本会报错，需实测后定）。

## 4. 工作流图变更（节点级）

### 4.1 `qwen_image_t2i@v2`（在 v1 的 9 节点上改 3 处）

| 节点 | 输入 | v1 | v2 | 说明 |
|---|---|---|---|---|
| `ks` KSampler | `sampler_name` | `"euler"` | `"{{SAMPLER}}"` | 占位符 → 参数绑定 |
| `ks` KSampler | `scheduler` | `"simple"` | `"{{SCHEDULER}}"` | 同上 |
| `lat` EmptyLatentImage | `batch_size` | `1` | `{{BATCH}}` | 同上 |

其余节点不动。**结构指纹会变**（`workflow_sha256` 变），所以 `params_hash` 也随之变——这正是版本快照该做的事，旧作业不受影响。

### 4.2 `sdxl_t2i@v1`（新图，7 节点）

```
ckpt  CheckpointLoaderSimple   ckpt_name={{CKPT}}
pos   CLIPTextEncode           text={{PROMPT}}      clip<<ckpt>>
neg   CLIPTextEncode           text={{NEG_PROMPT}}  clip<<ckpt>>
lat   EmptyLatentImage         width/height/batch_size
ks    KSampler                 seed/steps/cfg/sampler/scheduler/denoise=1.0
dec   VAEDecode                samples<<ks>>  vae<<ckpt>>
save  SaveImage                filename_prefix={{OUTPUT_PREFIX}}
```

和 Qwen 的差别只有加载器：SDXL 用 `CheckpointLoaderSimple`（一个 ckpt 三件套），Qwen 用 `UNETLoader + CLIPLoader + VAELoader`。**Registry 的 `model.slots` 已经能表达两种形态**，不需要改 schema。

## 5. 配置草案

### 5.1 `registry/workflows/qwen_image_t2i_v2.json`（节选）

```json
{
  "schema": "p20.workflow/v1",
  "key": "qwen_image_t2i",
  "version": 2,
  "kind": "image",
  "graph": "workflows/qwen_image_t2i_v2.api.json",
  "model": {"key": "qwen_image", "slots": {
    "unet": {"node": "unet", "input": "unet_name"},
    "clip": {"node": "clip", "input": "clip_name"},
    "vae":  {"node": "vae",  "input": "vae_name"}
  }},
  "params": {
    "sampler":   {"type": "enum", "default": "euler",
                  "values": ["euler", "euler_ancestral", "dpmpp_2m", "dpmpp_2m_sde", "uni_pc"],
                  "bindings": [{"node": "ks", "input": "sampler_name"}]},
    "scheduler": {"type": "enum", "default": "simple",
                  "values": ["simple", "normal", "karras", "beta"],
                  "bindings": [{"node": "ks", "input": "scheduler"}]},
    "batch_size": {"type": "int", "default": 1, "min": 1, "max": 4,
                   "bindings": [{"node": "lat", "input": "batch_size"}]}
  },
  "output": {"node": "save", "input": "filename_prefix",
             "kind": "image", "ext": "png", "pick": ["images"], "count": "{{BATCH}}"},
  "expect_defaults": {"ext": "png", "min_bytes": 20000, "images": "{{BATCH}}"}
}
```

需要 `config_schema.py` 新增：`type: enum`（带 `values`）、`output.count`、`expect.images`。

### 5.2 `registry/models/sdxl_juggernaut.json`（草案）

```json
{
  "schema": "p20.model/v1",
  "key": "sdxl_juggernaut",
  "name": "SDXL juggernautXL",
  "family": "sdxl",
  "files": [
    {"slot": "ckpt", "kind": "checkpoints", "name": "<盘点确认，如 juggernautXL_v9.safetensors>",
     "match": ["juggernaut"], "required": true}
  ],
  "constraints": {"width": [512, 1536], "height": [512, 1536], "batch_max": 4},
  "setup": {"need": "image-sdxl"}
}
```

`ckpt` 的确切文件名 **必须由 M0 盘点确认**，不能猜——P1 阶段已经踩过"VAE 断链"的坑（`reports/p1/...`：`qwen_image_vae.safetensors` 在列表里但读不到）。

## 6. 结果契约与校验

| 项 | v1 | v2 |
|---|---|---|
| 产出文件 | 固定 1 张 | `batch_size` 张，命名 `{job_id}_{seq:05d}_.png` |
| 回传 | `fetch` 拉 1 个文件 | 按 `outputs.<save>.images` 全量拉，缺一张即 `FAILED_FETCH` |
| 校验 | 尺寸 + 黑图比例 | 每张都校验；数量不符即失败；`batch=4` 时 4 张 sha256 必须互不相同（防"同种子退化"） |
| 幂等 | `params_hash` | 不变（batch 进 params，自然进 hash） |
| seed 复现 | 未纳入 | 同 seed/同参数两次作业，每张 sha256 一致（同卡同驱动下确定性） |

## 8. 测试计划

| 层 | 内容 | 通过标准 |
|---|---|---|
| 单测 | `enum` 参数校验（越界值/非法值）、`batch` 边界（0/5）、`output.count` 渲染 | 新增 ≥ 12 条，全绿 |
| 集成（mock ComfyUI） | fake `/prompt` 返回 4 张图 → fetch/verify 全流程 | 4 张全部落盘、数量校验生效 |
| 真机 | Qwen v2 × {sampler euler/dpmpp_2m} × {batch 1/4} × {1024²、768×1024}；SDXL v1 × {1024²、512×512} | 全部 DONE + PASS，图肉眼合格 |
| 失败场景 | 非法 sampler、batch=5、SDXL ckpt 缺失、batch=4 但只回 3 张 | 分别对应 `INVALID_PARAMS` / `FAILED_READY` / `FAILED_FETCH`，实例必销毁 |
| 20 连测 | 见 `01` §4 | 成功率 ≥ 95%、P95 达标、显存 ≤ 22GB、成本达标 |
| seed 复现 | 每模型 1 组（同 seed 跑 2 次） | sha256 逐张一致 |

## 10. 开放问题（M0 必须关掉）

1. **SDXL 权重确切文件名**：共享库里 `juggernaut*` 命中，但命中不等于可读——P1 的 VAE 断链就是教训，必须 `/object_info` 实测可见性。
2. **Sampler 白名单**：以实例 `/object_info` 为准，配置里的 5+4 是候选，实测后再定最终清单。
3. **Qwen + 非 euler sampler 的质量**：qwen 官方推荐 euler/simple，换 `dpmpp_2m` 是否掉质量需抽样看，若掉则白名单收窄到 euler 系并写进兼容矩阵。
4. **batch=4 的显存**：1024²×4 的 latent 与 attention，4090 24G 是否够，M0 冒烟时一并测。
5. **是否给 SDXL 也开 `denoise`**：5.2 图生图用哪套做基准（建议 SDXL，因为 5.3 inpaint 也要它，链路统一省一次资产盘点）。

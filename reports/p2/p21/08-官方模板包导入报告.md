## 3. 参数契约怎么来的（不做猜测）

包里的 `workflows/build_report.json → items[].input_slots` 已经声明了「哪个节点、哪个输入、什么用途」，
导入脚本只按它生成 `params`，其余输入一律原样保留：

| 槽位 kind | 生成的参数 | 说明 |
|---|---|---|
| prompt | `prompt` / `neg_prompt` / `prompt_2` | 包里 label 全是「提示词 / 编辑指令」，按默认文本的负面词（过曝/模糊/low quality…）判定负向；都不像就按惯例「第 1 正向、第 2 负向」 |
| seed | `seed`（int, 0–2³¹−1） | Wan2.2 双专家有两个 KSamplerAdvanced → **合并成一个 seed，绑多个节点** |
| asset/image | `image` / `image_2` | 首尾帧、参考图这类多图工作流会出现 `image_2` |

输出节点自动识别 `SaveImage / SaveImageAdvanced / PreviewImage / SaveVideo / SaveWEBM / VHS_VideoCombine`，
并把它的 `filename_prefix` 绑定成作业前缀（`p20.render.apply_output`）。

模型槽位按「同一文件 + 同一 loader」去重，角色命名 `ckpt / unet / unet_2 / clip / vae / lora / upscale`；
**每个工作流一套模型配置**（不跨工作流共用），避免把 A 图的 LoRA/放大模型串到 B 图里。

## 5. 顺手修掉一个既有 bug

`tools/p1/jobctl.py` 的 `SPEC_DEFAULTS` 把视频专属期望（`duration_s` / `freeze`）用 `setdefault`
塞进了**所有**作业——image 作业的 png 产物会被拿去测时长，复验必挂。已修：

```python
VIDEO_ONLY_EXPECT = ("duration_s", "freeze")
if k == "expect" and kind_hint != "video" and kk in VIDEO_ONLY_EXPECT:
    continue
```

修前：`expect` 里带着 `duration_s:[4.8,5.2]`；修后 image 作业只剩 `ext/min_bytes/black_ratio_max`。

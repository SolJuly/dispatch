# 镜像存储费实测 + 零存储成本路线（2026-11-09）

> 结论先行：
> 1. **镜像确实收费**：¥0.236/GB/月，每天 01:10 日结。我们之前漏算了 —— 它不产生任何 API 事件，只表现为余额阶跃。

### 1.2 为什么之前漏算

`tools/cost_snapshot.py` 原来只记 `balance` 快照，**不记差值**。镜像费不产生 `create`/`terminate`/`job` 任何事件，所以：

- 按事件统计成本 → 完全看不见
- 按余额曲线看 → 只看到「余额掉了」，不知为何

2026-11-08 的成本分析因此结论错误（当时判定「镜像不计费」）。

### 1.3 单价反推

最干净的测量是 **11-08**：实例数 0（最后一次 terminate 是 11-07 21:10:30），唯一自定义镜像 v4 = 70GB，01:10 扣 −¥0.55。

```
¥0.55 / 70GB = ¥0.00786/GB/天 = ¥0.236/GB/月
```

与 [22-v4镜像构建.md](p21/22-v4镜像构建.md) 记录的「70GB ≈ ¥0.56/天 ≈ ¥17/月」吻合。

### 1.4 关键佐证：11-04 全天零实例活动，仍扣 ¥3.59

```
11-04 全天 create/terminate/job/stop 事件数 = 0
11-04 01:10 扣 -¥3.59 → 反推 457GB
当时 v3 = 210GB → 多出 247GB 是 v1/v2 历史残留未删
```

**只有镜像存储能解释这笔扣费。**

## 2. 修复：日结扣费显性化

### 2.1 `tools/cost_snapshot.py`

新增 settle 事件：每次采样时对比上次余额，下降超过 ¥0.005 就写一条。

```json
{"ts":1794071402,"at":"2026-11-08 01:10:02","event":"settle",
 "amount":0.55,"from":9.78,"to":9.23,
 "prev_at":"2026-11-08 01:00:02","gap_s":600,
 "activity":[],"attribution":"idle"}
```

字段说明：

| 字段 | 含义 |
|---|---|
| `amount` | 本段余额下降额 |
| `attribution` | `idle`（期间无活动→只可能是日结）/ `job`（期间有作业）|
| `activity` | 期间出现过的事件类型 |
| `gap_s` | 距上次采样秒数；超过 3 小时打 `gap: true` |

改进点：
- `_last_balance()` 从文件尾部倒读，账本上万行也不整文件入内存
- 余额 `round(4)`，避免 `8.459999999999999` 这种浮点尾巴
- `--no-settle` 保留旧行为，`--dry-run` 只打印

### 2.2 `scripts/backfill_settle.py`

把历史 balance 差值回填成 settle 事件，一次性迁移。

```
$ python3 scripts/backfill_settle.py
账本 4004 行，检出 369 笔余额下降，合计 ¥57.93
  归因=job  ¥20.72（含作业开销）
  归因=idle ¥37.21（无活动，只能日结/存储费）
```

幂等：按 `(at, event)` 去重，跑两次不重复写。

> 已执行 `--apply`，账本从 4004 行 → 4373 行（+369 settle）。原文件备份为 `ledger.jsonl.bak`。

### 2.3 idle 归因的分布

297 笔 `idle`、合计 ¥37.21，按小时分布：

| 时段 | idle 金额 |
|---|---|
| 01 时 | **¥13.37**（日结主力）|
| 22 时 | ¥5.98 |
| 17 时 | ¥2.68 |
| 02 时 | ¥2.44 |

**01 时占 idle 总额的 36%** —— 与「01:10 日结」完全吻合，验证了归因逻辑。

## 3. 那两个节点：官方原生，不是第三方

### 3.1 直接查上游

`comfy_extras/nodes_wan.py` 里：

```python
class WanAnimate2ToVideo(io.ComfyNode):
    ...

class WanAnimate2Cache(io.ComfyNode):
    @classmethod
    def define_schema(cls):
        return io.Schema(
            node_id="WanAnimate2Cache",
            description=("Caches the pose-video's per-block activations so it runs once "
                         "instead of on every sampling step. Roughly halves generation time..."),
```

### 3.2 版本链路

| ComfyUI | `nodes_wan.py` 大小 | 有 WanAnimate2？ |
|---|---|---|
| `8402c870`（平台 0.3.75 底座） | 66169 B | ❌ |
| **`3c80da7f`（你的 v4）** | **87711 B** | ✅ |
| `v0.36.0`（平台公有镜像） | **87711 B** | ✅ |
| `v0.43.0`（平台公有镜像） | 88289 B | ✅ |

**`v0.36.0` 与 `3c80da7f` 的 `nodes_wan.py` 字节级完全相同**（已做 `==` 比对，`True`）。

### 3.3 全量验证：27/27 节点都是官方原生

抓取 `v0.36.0` 全部 142 个 `comfy_extras/*.py` + `nodes.py`，统计出 **661 个官方节点名**。

动作迁移工作流 `pack_video_wan_animate2_distilled`（作业 `p1-20261108T1352-3d1616`）用到的 27 个节点：

```
BasicScheduler  BatchImagesNode  CLIPLoader  CLIPTextEncode  CLIPVisionEncode
CLIPVisionLoader  ComfyMathExpression  ComfySwitchNode  ContextWindowsManual
CreateVideo  GetImageSize  GetVideoComponents  ImageFromBatch  ImageStitch
KSamplerSelect  LoadImage  LoadVideo  ModelSamplingSD3  ResizeImageMaskNode
SamplerCustom  SaveVideo  TrimVideoLatent  UNETLoader  VAEDecode  VAELoader
```

**命中 27/27，缺失 0。** 不需要任何 custom_node。

> 附：`BatchImagesNode` 和 `ResizeImageMaskNode` 定义在 `comfy_extras/nodes_post_processing.py`，不在 `nodes_*` 直觉位置 —— 一开始误判为缺失，实际存在。

## 4. 系统里真正的第三方节点：21 个，来自 8 个包

全部 54 个工作流共用到 **162 种节点**，其中 21 种非官方：

| 包 | 节点数 | 典型节点 |
|---|---|---|
| ComfyUI-FaceParsing | 9 | `FaceParse(FaceParsing)` 等 |
| ComfyUI-SeedVR2_VideoUpscaler | 3 | `SeedVR2LoadDiTModel` 等 |
| ComfyUI-KJNodes | 2 | `ImageResizeKJv2`、`GrowMaskWithBlur` |
| ComfyUI-essentials | 2 | `SimpleMath+`、`BOOLConstant` |
| ComfyUI-Impact-Pack | 1 | `ImpactCompare` |
| was-node-suite | 1 | `LayerUtility: If` |
| ComfyUI_UltimateSDUpscale | 1 | `UltimateSDUpscale` |
| ComfyUI 未包含的 Qwen 新节点 | 2 | `QwenImage21Cache`、`TextEncodeQwenImage21` |

**估算代码体积 ≈ 63MB**（不含权重 —— 权重全在 `/model` 共享库）。

**这就是 v4 镜像装 10 个 custom_nodes 的原因**：不是为了动作迁移，是为了这 21 个节点。

## 5. 三条路线

| 路线 | 镜像存储 | 侧载 | 起机 | 适用 |
|---|---|---|---|---|
| **1. 现状**（v4 自定义） | **¥16.5/月** | ¥0 | 105s | 全 54 个工作流 |
| **2. 平台 0.36.0 + 侧载 63MB** | **¥0** | ¥0.12/作业 | 105-117s + 3.4min | 全 54 个 |
| **3. 平台 0.36.0 裸跑** | **¥0** | ¥0 | 105-117s | **仅动作迁移等纯官方节点工作流** |

路线 2 的盈亏平衡（相对路线 1 的 ¥16.5/月）：

```
¥16.5 / ¥0.12 = 137 作业/月 ≈ 4.6 作业/天
```

按 11-07 的实际强度（18 作业/天），**路线 2 更贵**；按现在的强度（1-2 作业/天），**路线 2 更便宜**。

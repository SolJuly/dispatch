## 2. 三个根因

### 2.1 缺自定义节点（21 个 class）

| class | 影响 |
|---|---|
| `BBoxDetect(FaceParsing)`、`BBoxDetectorLoader(FaceParsing)`、`FaceParse(FaceParsing)`、`FaceParsingModelLoader`、`FaceParsingProcessorLoader`、`FaceParsingResultsParser`、`ImageCropWithBBox`、`ImageInsertWithBBox`、`BBoxListItemSelect` | facegen 皮肤细节（18 个 class 一起缺） |
| `SeedVR2LoadDiTModel`、`SeedVR2LoadVAEModel`、`SeedVR2VideoUpscaler` | SeedVR2 图片/视频放大 + facegen |
| `QwenImage21Cache`、`TextEncodeQwenImage21` | Qwen-Image 2.1 编辑/去背 |
| `UltimateSDUpscale`、`ImageResizeKJv2`、`GrowMaskWithBlur`、`ImpactCompare`、`LayerUtility: If`、`SimpleMath+`、`BOOLConstant` | SUPIR / facegen / 部分后处理 |

当前镜像的 `custom_nodes` 只有 Crystools、DD-Translation、GGUF、websocket_image_save；上面这些都不在。**节点缺失不是改 JSON 能解决的**，要么装节点，要么换镜像。

### 2.2 权重文件名不在候选列表（55 处）

按模板声明的文件名，`/object_info` 的 loader 候选列表里找不到，例如：

- Qwen 2.1：`qwen_image_2.1_int8_convrot`、`qwen3vl_8b_int8_convrot`、`qwen_image_2.1_vae_bf16`
- Qwen Edit：`qwen_image_edit_2509_fp8_e4m3fn`、`qwen_image_edit_2511_int8_convrot`、`Qwen-Image-Edit-2511-Lightning-4steps` LoRA
- SeedVR2：`seedvr2_3b_int8_convrot`、`seedvr2_7b_int8_convrot`、`seedvr2_ema_vae_fp16`
- VACE：`wan2.1_vace_14B_fp16`
- SCAIL2：`wan2.1_14B_SCAIL_2_int8_convrot`、`sam3.1_multiplex_fp16`
- LTX：`ltx-2.3-22b-dev-fp8`、`ltx-2.3-22b-distilled-fp8`、LTX spatial upscaler
- MiniMax H3：`minimax_h3_video_vae_int8_convrot`、`minimax_h3_ref2v_turbo_4step` LoRA
- 图片：SUPIR checkpoint、facegen 的 Juggernaut/8xNMKD/皮肤 LoRA、`illustration-1.0-qwen-image` LoRA、`RealESRGAN_x4plus`

> 注意：这是“按模板声明的名字”找不到，不排除共享库里有不同量化/目录/别名的版本；需要人工建映射，不能直接判定“没有”。

### 2.3 断链（29 处：22 个精确命中 + 7 个 contains 命中）

最典型的是我们已经踩过的：

- `ae.safetensors` → 指向不存在的 HiDream 路径（影响 `pack_image_z_image_turbo`、`_controlnet`、`_2k_upscaler`）
- `flux2-vae.safetensors` → 指向不存在的 `ModelScope/Comfy-Org/flux2-dev/...`（影响 Flux2 图片）
- `qwen_image_vae.safetensors`、`qwen_2.5_vl_7b_fp8_scaled.safetensors` → 影响 Qwen Edit/Layered/Illustration
- `ltx-2.3-spatial-upscaler-x2-1.1`、`wan_animate_2_distill_int8_convrot`、`void_pass1/2` 等

这些是“候选列表里有、`get_full_path` 返回 None / 不是文件”，必须在实例上重链或补文件。

## 4. 代码缺口：`image_2` 多图

以下工作流声明了 `image_2`：

- 图片：`pack_image_flux2_klein_image_edit_4b_distilled`、`pack_image_qwen_image_2_1_image_edit`
- 视频：LTX FLF2V/IC-LoRA/2.5、MiniMax H3 R2V/Multiframe、Wan Animate、SCAIL2、VACE 多条

但 `p20ctl._normalize_image` 和 `p1/run.py` 的上传循环只处理 `image` 和 `mask`。**`image_2` 不会被推到实例 `input/`**，`LoadImage` 会找不到文件。要跑这些工作流，先补 `image_2`（以及通用 `image_*`）的归一化/上传。这是代码问题，不是配置问题。

## 5. 建议的下一步

### 视频（优先，因为已有 4 条全绿）

1. 先验证 4 条：Wan2.2 I2V / FLF2V / S2V、Wan Animate2。建议 4090_48G，单条约 ¥0.3–0.6。
2. VACE / SCAIL2 / LTX / MiniMax 暂缓：缺 VACE、sam3、LTX 22B、MiniMax VAE/LoRA，属于“补权重”阶段。
3. SeedVR2/void 后处理：缺节点/权重，暂缓。

### 图片

1. **不建议**先跑 15 条；先把 4 条“只差断链”的验证掉（如果要在 pack 格式上留证据），否则直接跳过——legacy 6 已覆盖能力。
2. 真正值得投入的是 **Qwen Edit 2509/2511 + Layered + SeedVR2 放大 + FaceGen**；需要先补：
   - `image_2` 上传代码；
   - Qwen Image VAE / qwen2.5vl / 2511 UNET / Lightning LoRA；
   - SeedVR2、FaceParsing、SUPIR 节点（建议做一版新镜像）。
3. SUPIR/FaceGen 节点依赖多，性价比最低，最后做。

### 不建议

- 不要为了“38 条全绿”逐条盲跑；当前 34 条里大部分缺的是**节点/权重**，跑一次只会得到一条 `FAILED_PROVISION`，还花开机费。

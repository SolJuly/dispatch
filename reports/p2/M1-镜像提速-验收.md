## 2. 建机耗时基准（`bench-boot.json`，各 3 轮）

| 层 | create→Running | sshd 就绪 | **t_ready(ComfyUI up)** | P50 | max |
|---|---|---|---|---|---|
| base | 71–74s | +0–15s | **103.9 / 110.5 / 117.3s** | 110.5s | 117.3s |
| media | 65–71s | +0–1s | **105.0 / 109.5 / 112.0s** | 109.5s | 112.0s |

**对照基线（P1 实测）**：单次闭环 120–160s = 建机 70–85s + setup 25–40s + 冷启 26–38s。

**M1 的效果 = 消灭了 setup 的 25–40s**（烘焙进镜像，快路径只做 ~5s 核对），ComfyUI 冷启因 node 缓存预热也略降。其余时间全是平台侧，脚本动不了。

## 3. 关键实测发现（写进计划，避免以后重踩）

1. **实例无外网**：DNS 都解析不了（`Name or service not known`）→ `apt` / `pip` / GitHub 全部不可用。**rsync 无法安装**（D2 里「rsync 装 base」物理做不到，已放弃，传输仍走 scp/tar）。
2. **ffmpeg 7.1.1 镜像里本来就有**：`/usr/local/ffmpeg/bin/ffmpeg`，只是不在 PATH。media 层 = 软链进 `/usr/local/bin`，无需安装。
3. **`pkill -f 'main.py --listen'` 会误杀执行它的 ssh/shell**：必须用 `[m]ain.py` 方括号技巧（P1 的 `instance_setup.sh` 一直是这么写的）。裸写法导致前 3 次烘焙在 pkill 处崩。
4. **`-c aes128-gcm@openssh.com` 在 fresh 实例上偶发握手失败**：scp/长 ssh 会「Connection closed by remote host」。已从 P2 新代码移除；`instance_setup.sh` 的 scp 也去掉了该 cipher。
5. **Manager 卡启动已根治**：bake 时 patch `/start.d/comfyui.sh` 去掉 `--enable-manager` + 加 `COMFYUI_MANAGER_OFFLINE=1`，Manager 目录改名 `.disabled`。
6. **setup 快路径生效**：`instance_setup.sh` 开头探测 `/root/.p2_image.json`，有标记就只做轻量核对（6 项资产自检），跳过 sed/scp/ln/重启。

## 4. 关于「≤1.5 分钟」的诚实结论

| 阶段 | 耗时 | 能否压缩 |
|---|---|---|
| 下单 → Running | 65–75s | ❌ 平台硬下限 |
| ComfyUI 冷启（entrypoint 自动起） | 30–50s | ⚠️ node 缓存已预热，仍剩模型/节点初始化 |
| setup | ~0s（快路径核对 ~5s） | ✅ 已归零 |
| **合计 t_ready** | **~105–117s** | 较基线 120–160s 提升，但 **90s 不可达** |

**真正能到十几秒级的只有一条路：复用已停机实例（stop→start 实测 12s）**，即已按 D6 缓议的 M5 预热池。镜像提速已到平台物理上限，再往下要动的是「不建机」而不是「更快建机」。

# 智云（优云智算 CompShare）转售条款核查

> 核查时间：2026-11-09
> 核查对象：`compshare.cn` 的四份协议原文
> 核查目的：确认能否"以服务形式向终端用户提供算力驱动的生成服务"

---

## 0. 结论

**有一条明确条款禁止，而且是"未经许可不得"。**

> **《优云智算云平台安全规则》第七条**：
> 「您提供的信息或服务不得侵犯任何第三方知识产权；**未经许可，您不得对
> compshare优云智算产品及服务再次转租**。」

**关键判断：**

| 问题 | 答案 |
|---|---|
| 有禁止条款吗？ | ✅ **有**，安全规则第七条 |
| 是绝对禁止还是"未经许可"？ | ⚠️ **"未经许可"** —— 留了授权通道 |
| 有处罚吗？ | ✅ 有，冻结账户、封禁、清退 |
| 有正规转售/代理体系吗？ | ❌ **公开文档里没有** |
| 违反了会怎样？ | 账户冻结 + 单方终止所有合作 + 不承担违约责任 |

**这条不影响 BYOK 模式**（用户自己开户、自己付费、你只提供软件），
**会影响"你的账号 → 卖给终端用户"的模式**（也就是文档 §9.2 的按任务支付）。

## 1. 条款原文（四份协议逐份核）

智云一共有五份协议，实际相关的三份：

| 协议 | 是否含转售条款 |
|---|---|
| 优云智算服务框架协议 | ❌ 无 |
| 优云智算用户协议 | 🟡 只禁止账户转让 |
| **优云智算云平台安全规则** | ✅ **有禁止转租** |

### 1.1 《云平台安全规则》第七条 —— 核心条款

**原文：**

> 第七条
> 您提供的信息或服务不得侵犯任何第三方知识产权；未经许可，您不得对
> compshare优云智算产品及服务再次转租。

**拆解：**

| 成分 | 内容 |
|---|---|
| 主语 | "您"（实名认证主体）|
| 客体 | "compshare优云智算产品及服务" |
| 行为 | "**再次转租**" |
| 前置条件 | "**未经许可**" |
| 处罚依据 | 第八条 |

**"再次转租"的覆盖范围**——按通常理解，包含：

- 把 GPU 实例直接转给别人用 ❌
- 按小时/按次卖算力给终端用户 ❌
- 以"生成服务"包装但底层是转卖算力 ❌

**不完全等同于**：

- 你自己用算力做服务、卖**结果**（如"给我一张图，我交付一张图"）—— 若定价与算力用量**无关**，更接近"自用+自营服务"
- 用户自带账号（BYOK）—— 用他自己的凭证、扣他自己的钱

**但这条界线的法律解释权在平台，不在你。** 见 §3。

### 1.2 约束力：用户协议明确并入

《用户协议》原文：

> 如您实际接受Compshare优云智算云服务的，则表明您已仔细阅读、理解并同意接受
> Compshare优云智算网站文档中心的"Compshare优云智算服务框架协议"、
> "**Compshare优云智算云平台安全规则**"。

**接受服务 = 已同意安全规则。** 所以第七条对你现在有效，不需要另外签字。

### 1.3 处罚：不是"警告"，是"冻结 + 清退"

《安全规则》第八条原文：

> 为维护compshare优云智算产品使用环境的清朗以及用户的正当权益，
> compshare优云智算有权对违反本规则或滥用compshare优云智算产品及服务的情况
> 采取必要处理措施，同时**保留追究民事或刑事责任的权利**，并
> **有权单方选择终止与您的所有合作**。如compshare优云智算采取相应措施，
> **不视为compshare优云智算违约，无须为此承担任何责任**。

具体措施（表格原文）：

```
（一）屏蔽产品中的违规内容
（二）停用含有违规内容的产品
（三）冻结用户账户，使其无法使用compshare优云智算所有的产品

网络行为类：封禁端口、封禁网络、机器关停、冻结用户、清退
UHost     ：页面禁止访问 → 网站禁止访问 → 关停主机、冻结账户
```

**注意最后一句**：「不视为违约，无须承担任何责任」——意味着：

- 账户被冻结时，**余额不一定要退**
- 正在跑的作业被关停，**损失自担**
- 你没有追索权

### 1.4 用户协议第七条：只禁账户转让，不禁服务转售

**原文：**

> Compshare优云智算允许一个法律主体拥有多个Compshare优云智算账户，但一个
> Compshare优云智算账户仅能对应唯一的法律主体（即实名认证的主体）。
> 除非有法律规定或生效法律文书确定，或者符合Compshare优云智算公布的条件，
> 否则您**不得以任何方式自行转让、赠与或让他人继承您的Compshare优云智算账户**。

**这条禁的是"账户"层面，不是"服务"层面。** 两者别混。

### 1.5 框架协议：没有转售条款，但有一条要注意

框架协议通篇没有转售限制。但有：

> 4.1.1 用户保证具有合法的资质从事本服务条款项下所有经营，同时保证用户所
> 提供的所有信息真实有效，否则因违反上述陈述保证造成的一切后果，由用户自行承担。

**"具有合法的资质从事本服务条款项下所有经营"** —— 如果你做经营性服务，
需要自己有相应资质（含 ICP、增值电信业务许可等，看你做什么）。

## 2. 有没有正规授权通道

### 2.1 公开文档里没有

我查了这几个地方，**都没有找到"转售授权/代理申请/分销合作"的入口**：

| 位置 | 结果 |
|---|---|
| 协议概览页 | 只有 5 份协议，没有商务合作 |
| 服务框架协议 | 无代理/分销条款 |
| 用户协议 | 无 |
| 安全规则 | 无 |
| 网站导航 | 无"合作伙伴/渠道/分销"入口 |

### 2.2 但条款写的是"未经许可"，不是"不得"

这个措辞**留了口子**。有两种可能：

1. **平台有内部授权流程**，但没公开（企业客户走商务，一对一定）
2. **平台写这条只是兜底**，实际不主动查，但保留随时引用的权利

**你不能假设是第 2 种。** 因为处罚是"单方终止 + 不承担任何责任",
而且你有实测证据：**账户里确实还有钱的余额 ¥8.38**。

### 2.3 建议的确认方式

```
1. 提工单 / 找客服，问题写清楚：
   "我们计划基于贵平台的 GPU 实例，做一个 AI 创作服务平台，
    终端用户在我们的平台上传素材、按任务付费，我们不直接售卖 GPU 算力，
    而是交付生成好的图片/视频。请问这种模式是否需要在贵平台做额外授权？"

2. 关键：要**书面回复**（工单记录 / 邮件），不要口头承诺。

3. 如果对方说"需要商务谈"，就进入商务流程 —— 这本身是好消息。

4. 如果对方说"不允许"，那你只有两条路：
   - 转 BYOK（用户自己开户）
   - 换平台（找明确允许转售的）
```

**建议在写第一行订单代码之前就做完这件事。**

## 3. 三种商业模式，逐个过条款

| 模式 | 描述 | 条款风险 | 判断 |
|---|---|---|---|
| **A. 纯自营生成服务** | 你用自己账号跑，卖"生成好的图/视频"，定价与算力用量无关 | 🟡 **灰区**。若被认定"以生成服务之名行转租之实",触第七条 | 需要书面确认 |
| **B. 按任务卖算力** | 明码标价"¥0.26 跑一次动作迁移"，价格随帧数/分辨率变 | 🔴 **高危**。价格与算力用量直接挂钩 = 事实上的算力转租 | 不建议，除非拿到授权 |
| **C. BYOK** | 用户自己开户、填自己的 Key、扣自己的钱，你只提供软件 | 🟢 **无风险**。用的是他自己的账号，不涉及你的转租 | 推荐 |

**你文档 §9.2 描述的"DSH 估算价格 → 用户支付 → 按任务计费"就是 B。**
这是最直接踩线的一种。

而你文档 §9.3 的 **BYOC**（企业自有算力，DSH 收软件服务费）是 C 的变体，
**完全没问题**。

## 4. 这一条对现有系统的影响

### 4.1 不受影响的（继续做）

| 项 | 为什么不受影响 |
|---|---|
| 单人自用创作台 | 纯自用，不涉及转租 |
| BYOK 模式 | 用户自己的账号 |
| BYOC 企业方案 | 企业自有算力 |
| Provider Adapter 抽象 | 纯技术，与条款无关 |
| L1 用户系统 | 技术层，与商业模式解耦 |
| 工作流商品化（自用）| 你自己整理工作流自己用 |

### 4.2 受影响的（要做就得先拿授权）

| 项 | 为什么 |
|---|---|
| **按任务定价收费** | 价格与算力用量挂钩 = 事实转租 |
| **通用钱包/充值** | 代收代付 + 转租双重风险 |
| **多用户在你这付费跑作业** | 直接把你的算力卖给第三方 |
| **第三方开发者分成** | 你在卖别人的算力，还抽成 |

### 4.3 一个具体的判断方法

**看你的定价是否与算力用量脱钩：**

```
❌ 踩线：  "动作迁移 ¥0.26/次（按 4 秒视频）"
           → 价格随帧数/秒数变 = 在卖算力

🟡 灰区：  "动作迁移 ¥9.9/次（不限时长）"
           → 价格固定，但成本随用量变，平台可能仍认为你在转租

🟢 安全：  "BYOK：用你自己的智云账号，我们只收软件订阅费 ¥99/月"
           → 算力费用他自己付给平台，你收的是软件钱
```

## 5. 我的建议

### 5.1 立刻做（今天）

**发一份工单问清楚。** 不要问"能不能转售"（容易被一刀切拒绝），
按 §2.3 的措辞问具体场景。

### 5.2 短期（1-2 周）

**把 MVP 的商业模式从 B 改成 C。**

具体改动：

| 原计划 | 改成 |
|---|---|
| 用户在你平台充值 → 你代付 GPU | **用户填自己的智云 Key** |
| 按任务收费（价格随用量） | **软件订阅费（固定）** |
| 通用钱包 | 不做 |

**技术上更简单**（我上一条已经验证：3 处 spawn 加 `env=` 就行），
**商业上更安全**（不碰代收代付，不碰转售）。

### 5.3 如果授权拿到了

那 B 模式可以做，但要注意：

- 拿到的是**书面授权**，不是客服口头同意
- 授权范围写清楚：能不能定价、能不能分账、能不能给第三方开发者
- 保留授权文件，万一后来换客服口径

### 5.4 如果授权被拒

**三条路：**

1. **转 BYOK**（推荐）—— 用户自己开户，你卖软件
2. **换平台** —— 有的平台明确允许转售（要逐个查）
3. **自建算力** —— 成本太高，不现实

## 6. 一个容易忽略的点

**条款里"许可"的主体是平台，不是你。**

即使你拿到了某个销售人员的微信确认，也不等于"许可"。安全规则第八条写的是
"Compshare优云智算"这个主体。**口头同意在争议时基本没用。**

要的是：
- 工单/邮件里的书面回复
- 或者正式合同补充协议
- 最好有盖章

## 8. 一句话

**有禁止条款：《云平台安全规则》第七条，"未经许可，不得再次转租"。**

它不是绝对禁止，留了"许可"的通道，但**平台没有公开的授权入口**，
而且处罚是"冻结账户 + 单方终止 + 不承担任何责任"。

**这条不影响 BYOK，影响的是"你用自己账号卖算力"的模式。**
而你文档 §9.2 的按任务支付正是后者。

**建议：今天发工单问清楚，同时把 MVP 的技术方案改成 BYOK。**
BYOK 技术上更简单（3 处 spawn 加 env），商业上不碰红线，等你拿到授权再考虑要不要转回按任务计费。

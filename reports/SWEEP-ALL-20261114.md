## 四、本次修掉的 4 个真缺陷

### 1. `jobs_reconcile` 误杀排队作业（最严重）

**现象**：批量提交 22 条图像，19 条瞬间 FAILED，报 `IllegalTransition: FAILED → PROVISIONING`。

**根因**：cron 每 15 分钟跑的 `jobs_reconcile.py` 把 `CREATED`（排队等并发槽）判成僵尸：

```
判据：run.py 已退出 + 无实例 + 无产物 + 步骤未走完 → FAILED
但 CREATED 本来就没有进程和实例 —— 它是在等执行
```

**修法**：加一条前置判断 —— `CREATED` 且无任何步骤记录 → `keep`。

```python
if st == CREATED and not steps:
    return v("keep", "CREATED 且未启动过 —— 在等执行，不是僵尸")
```

**影响**：这条 bug 让任何并发提交都被团灭，是批量测试的致命阻塞。测试 18 项全绿。

### 2. 54 张卡的预算自相矛盾（52 张中招）

**现象**：作业在建机**之前**就被自己的预算闸拒绝。

```
✗ 预估 ¥1.07（2.15/h × 30 分钟）超过作业预算上限 ¥1.00
```

**根因**：两个数字按**两张不同的卡**算：

```
required_gpu: ["4090", "4090_48G"]   ← 两个都可能被挑中
max_minutes:  30                    ← 按 4090  ¥2.15/h 算 = ¥1.07
max_cost:     ¥1.00                 ← 却按更便宜假设定的
```

4090 无货时 4090_48G（¥3.80/h）顶上，同样 30 分钟要 ¥1.90 → 合法作业被拒。

**修法**：按**最贵可能挑中的卡**抬 `max_cost`（这本来就是「我最多愿意花多少」）。
52 张卡全部修正，并加测试 `test_budget_consistency.py`（6 项）。

### 3. `WanSoundImageToVideo` 缺必填输入

**现象**：`pack_video_wan2_2_14b_s2v` 提交被拒，`required_input_missing: width / height / batch_size`。

**修法**：图里补上三个字段。修完后质量 **97.5 A**，是全批最好的视频之一。

### 4. 可选音频槽位残留模板示例文件名

**现象**：`LoadAudio: Invalid audio file: ltx23_reference_audio.mp3`。

**根因**：`ref_audio` 是 `required: false`，调用方不给时图里保留模板作者的文件名，实例上不存在。

**修法**：图里清空为 `""`，`render.prune_empty_loaders()` 会自动删节点。

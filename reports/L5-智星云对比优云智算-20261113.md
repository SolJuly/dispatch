# 智星云 vs 优云智算：作业流程差异与复用评估

> 2026-11-13 13:15 · 基于真机实测（9 台实例，净花费 ¥0.2604）
> 结论先行：**状态机和建机/销毁能复用；"停机"这一层不能照搬，但智星云有等价物
> —— 「留盘停放」¥0.0431/h（运行的 1/4），所以不是"只能跑完就销毁"。**

---

## 一、一句话结论

| 问题 | 答案 |
|---|---|
| 作业流程有区别吗？ | 有，在**状态经济学**上：优云智算「停机=¥0 保内存」，智星云「关机=照算钱，留盘=1/4 价保磁盘」 |
| 状态机能复用吗？ | 能，映射表已写完；`stopped` 一档两家含义不同 |
| 建机 → 销毁能复用吗？ | 能，真机已验证（create → ssh_ready → terminate） |
| 跑完能直接销毁吗？ | **能**，而且是真的停止计费（Status→0、磁盘释放）。但建机后约 310s 内退租必然失败 —— 短作业要多付约 5 分钟尾巴 |
| 还有别的退出方式吗？ | 有「留盘停放」：¥0.0431/h 保住磁盘，恢复后文件原样都在 |
| 整个流程能原样搬过去吗？ | 不能照搬。`stop()` 要换成 `suspend_to_disk()`，语义从"保内存"降级为"保磁盘" |

---

## 二、最关键的区别：停机的经济含义相反

这是本次实测挖出来的、也是决定复用方案的唯一因素。

### 优云智算（现在的生产路径）

```
Running  → 计费
Stopped  → 算力 ¥0 + 系统盘 ≤100GB ¥0  = 持仓成本 0
```

代码里写得很明白（[run.py:1937](tools/p1/run.py)）：

> 停机实例是 **¥0**（实测：算力 ¥0 + 系统盘 ≤100G ¥0）。所以改成失败就立刻停，
> 要续跑先花 ~12 秒开机。

整个上层流程建立在这条上：

- **失败保留实例**（`--keep-on-fail`）：失败就 `stop()`，2 小时内可 `--resume`
- **预热池**（[pool.py](tools/p2/pool.py)）：常驻 N 台 stopped，来活 `start()` 省掉 70-85s 建机
- **reaper 三态判定**：keep / stop / terminate，其中 stop 是"零成本缓存"
- **并发槽**：停机实例让出槽位，但占账户配额（5 台上限）

### 智星云（实测）

我做了完整探针，结论分三层：

**① 平台没有关机 API**

```
instance/stop_instance            → 404
instance/shutdown                 → 404
instance/power_off                → 404
instance/close / halt             → 404
instance/stop_kvm_instance        → 404
instance/shutdown_instance        → 404
（9 个候选全部 404）
```

**② 但关机态确实存在** —— 这点推翻了我第一版报告的结论

```
guest 内 poweroff -f  →  云端 Status=1 & IsAbnormal=2  →  provider 认出 state=stopped
restart_instance_from_shutdown  →  16s 回到 running，18s sshd 就绪
```

所以"没有关机态"是错的。准确说法是：**有态，没有触发手段**（只能让作业自己在机器里 `poweroff`）。

**③ 关机期间租期照常烧** —— 这才是致命的

```
11:53 建机，Due_time = 12:53:32（1 小时租期）
12:03 关机（IsAbnormal=2），租期剩 43.5 分钟
12:04 退租询价：可退 ¥0.1211，剩余 0.726 小时
12:05 再查：可退金额仍在下降
```

关机 6 分钟、`rentCost` 一分没少、`Due_time` 纹丝不动、可退金额线性下降。

**结论：智星云上「停机」不省一分钱，只是让机器躺着把租期烧完。**
智云的停机是"零成本缓存"，智星云的停机是"把钱存在机器里继续蒸发"。

## 一·补 "跑完立刻销毁"行不行？能，但要等约 5 分钟

实测 3 台，规律是**平台固定冷却窗**而不是偶发：

```
建机 → running
           ↓ 尝试退租
t=0s    操作频繁#10001   ← 立刻退，必失败
t=60s   操作频繁#10001
t=160s  操作频繁#10001
t=274s  ✓ 成功              ← 第 1 台
t=290s  ✓ 成功              ← 第 2 台
t=312s  ✓ 成功              ← 第 3 台（前 9 次连续失败）
```

**结论：建机后约 310 秒内退租必然失败。** 三次实测都落在 270~315s 之间。

这对"跑完就销毁"意味着什么：

| 作业时长 | 实际计费时长 | 说明 |
|---|---|---|
| 5 分钟就跑完 | **约 6 分钟** | 多付的 5 分钟是冷却窗，退不掉 |
| 30 分钟 | 约 32 分钟 | 冷却窗摊薄，影响小 |
| 2 小时 | 约 2 小时 | 基本无感 |

所以**能销毁，销毁也是真销毁**（Status→0、磁盘释放、停止计费），
但"短作业跑完立刻退租"这条路在智星云上会多付一个固定约 5 分钟的尾巴。

CPU 实例这笔尾巴约 ¥0.014，4090 约 ¥0.13 —— 不长，但叠加在批量短作业上要算进去。

`terminate()` 已经按这个事实把重试窗口设成 420s（3 次实测都在内），
并会在超时报告里提醒"机器可能仍在计费"。这一条也写进了 `capabilities().notes`
的 `terminate_lock_s`，上层可以在下决定前就查到。

## 二·补 智星云其实有等价物：留盘停放

上面说"停机省钱不可复用"，但**不等于智星云只能跑完就销毁**。
我实测了另一条路：**退租但保留磁盘**（Status=8），需要时从盘恢复。

### 实测结果

```
建机（due_mode=1）→ 写标记 MARKER_1794573186 到 /root/disk_probe_marker
  ↓ terminate(release_disk=0)
Status=8，磁盘保留
  ↓ create_kvm_instance_from_keepped_disk
新实例 _c0 → _c1，Status=1，直接可用
  ↓ SSH 读盘
MARKER_1794573186   ← 原样还在
```

### 三种状态的持仓成本（实测）

| 状态 | 单价 | 相对运行 |
|---|---|---|
| 运行中 Running | ¥0.1668/h | 100% |
| 关机态 IsAbnormal=2 | ¥0.1668/h | **100%（白停）** |
| **留盘停放 Status=8** | **¥0.0431/h** | **26%** |

所以智星云上的正确做法不是"跑完就销毁"，而是：

- **短间隔（< 1 小时就要再用）** → 留盘停放，¥0.0431/h
- **长间隔（隔夜/几天）** → 直接销毁，下次重建 + 重新装环境
- **关机** → 永远是错的选项（和运行同价）

### 恢复的两个坑

1. **恢复会新建实例**，`Container_name` 的 `_c0` 递增成 `_c1`，**旧名失效**。
   必须用 `resume_from_disk()` 返回的新名，否则找不到机器。
   → 已实现 `suspend_to_disk()` / `resume_from_disk()` / `find_kept_disk()` 三件套。
2. **恢复价格 = 新建价格**（¥0.1668/h），恢复动作本身不额外收费。

### 等价性对照

| 优云智算 | 智星云等价物 | 差别 |
|---|---|---|
| `stop()` 保状态，¥0，~12s 唤醒 | `suspend_to_disk()` 保磁盘，¥0.0431/h，恢复 ~0s | 保留期要付磁盘钱；唤醒更快 |
| 内存/显存里的模型还在 | **内存丢失**，进程要重起 | 恢复后 entrypoint 会重新拉起 |
| 停机不占并发槽 | 留盘实例算 terminated，也不占槽 | 一致 |

**关键差别：智云停机保留的是"内存状态"（模型还在显存里，唤醒 12s 就能跑）；
智星云留盘保留的是"磁盘状态"（文件都在，但要重新启动进程、重新加载模型）。**

## 四、复用障碍清单（按改动成本排序）

### 障碍 1：SSH 端口硬编码 `"23"` —— 16 处需要改

```
tools/p1/run.py:614,836,905,1811,1858          (5)
tools/p1/manager_probe.py:38, tc10_disk_full.py:84   (2)
tools/p2/scheduler.py:437                       (1)
tools/p2/pool.py:33                             (1)
tools/p2/image.py:31                            (1)
tools/p21/bench20.py:121, inventory.py:181,
         probe_assets.py:48,55,60                (5)
tools/p2/l5l6.py:191                             (1)
```

（`providers/compshare.py:131` 和 `providers/local.py:222` 里的 `"23"` 是各自适配器的正确默认值，不用动。）

智云统一 23 端口；智星云是**每台随机分配**（实测 13124 / 21316 / 26120 / 26122）。
契约层 `ssh_endpoint()` 已经返回正确端口，**但这些调用点绕过了契约直接写死 23**。

→ 要走智星云，这 16 处必须改成读 `provider.ssh_endpoint().port`。纯机械改动，但没有捷径。

### 障碍 2：reaper 的 `stop` 分支失效

[reaper.py:562](tools/p2/reaper.py) 把"停机"当零成本缓存：

```python
if s.action == "terminate":
    cs.terminate(s.uid)
else:
    cs.stop(s.uid)          # ← 智星云上这里会抛 UNSUPPORTED
    lifecycle.record_stopped(s.uid)
```

而且 reaper 直接 `from compshare.cs import CS`（[reaper.py:287,548](tools/p2/reaper.py)）、
按 `UHostId` 取实例（[reaper.py:310](tools/p2/reaper.py)）—— **完全绕过 provider 层**。
同样直连 `CS()` 的还有 pool.py:28、scheduler.py:125,135,277,421,434（共 8 处）。
要支持智星云，这些得改成走 `get_provider()` + `InstanceView`。

### 障碍 3：预热池在智星云上不成立

[pool.py](tools/p2/pool.py) 的设计前提写死了：

> 停机实例：算力费 ¥0，系统盘 ≤100G 免费 → 持仓成本 0

智星云上停机照常计时，**预热池 = 纯烧钱**（一台 ¥0.73/h 躺着，预热 2 小时就 ¥1.46，比现建还贵）。

→ 智星云上必须**关掉预热池**，走"现建现用 + 用完立即退租"。

### 障碍 4：失败保留实例的窗口算法

`lifecycle.stopped_ttl_min()` = 2 小时，逻辑是"停机 ¥0，留 2 小时不亏"。
智星云上留 2 小时等于白烧 2 小时算力费。若要用，TTL 必须压到接近 0，
那就不如直接销毁 + 重跑（反正建机只要 21-36s，比重跑作业便宜）。

### 障碍 5：`_pick_spec` 替代"自由填 CPU/内存"

智云 `cpu=16, memory_gb=64` 直接进 API；智星云只能落到 26 个固定规格之一。
我已经实现"取 ≥ 要求里最便宜的一档"，但**上层的资源估算假设的是精确值**。
实测 2核2G、8核16G 都能精确命中，够用；但 `cpu=12, mem=29` 这种会静默升档。

## 五、两个口袋：余额口径

```
优云智算: 一个余额
智星云:   现金 Money  |  算力券 PowerMoney   （扣费顺序由 pay_type_first 决定）
```

实测这台的账（建机 ¥0.1668 → 41s 后退租）：

```
现金  15.0000 → 14.8332    （扣了，没退回）
券     0.0000 →  0.1526    （退到这里）
净损失 ¥0.0142 = 41 秒的钱
```

→ `balance()` 只返回现金（`14.8332`），券另走 `balance_detail()`。
**如果上层拿 `balance()` 判断"还有没有钱"，在券充足、现金见底时会误判为"没钱"。**

## 六、共享权重：智星云没有等价物

智云的 `/model` UPFS 40T 只读、免费、跨账号共享 —— 这是它跑 ComfyUI 作业的核心优势
（模型不用下载、不用占盘）。智星云只有 `shareddisk`（6.0 AI 模型库），是**付费挂载商品**。

→ 迁移过去必须自己解决权重来源：要么每次 `provision.sh` 下载（有外网，可行，但慢且占盘），
要么挂 OSS/NAS。这一条对"同一份作业配置两地跑"影响最大。

## 七、可以复用的部分（好消息）

契约层是真的能复用的，真机已验证：

```python
p = get_provider("zhixingyun", credentials={...})
uid = p.create(image=..., gpu_type="2080 Ti", gpu=1, cpu=8, memory_gb=16)   # 36s
ep  = p.ssh_ready(uid)                                                     # +2s
# ... 干活 ...
p.terminate(uid, release_disk=True)                                        # 3-5 分钟 BUSY 冷却
```

`InstanceView` 的字段是云无关的，状态映射覆盖全部云侧状态（含 `IsAbnormal=2` 的关机态）。
**凡是已经走 `Provider` 契约的代码，换云零改动。**

问题在于：**上游还有一大批代码没走契约**（19 处硬编码端口、reaper 直连 `CS()`、
pool 直连 `CS()`、scheduler 直连 `CS()`）。

## 八、结论与建议路线

### 三条路，按代价排序

**路线 A：短租 + 留盘停放两档（推荐）**

不改上层，按间隔选退出方式：

```
跑完立刻还要接着跑   → suspend_to_disk()   ¥0.0431/h，恢复 ~0s
1 小时内不再用       → suspend_to_disk()   仍然划算（0.0431 × 1 < 0.1668 重建）
隔夜 / 几天          → terminate()         下次重建 + provision.sh（有外网，可行）
```

预热池仍不适用（智星云"预热"= 留盘，恢复后进程要重启，省不到智云那个 12s）。
但"失败保留实例"是可以做的：失败 → `suspend_to_disk()`，比智云的 `stop()` 贵 4 倍
但仍然是运行的 1/4，比直接销毁重跑一次作业便宜的话就值得。

```
适用：单次实验、批处理、短间隔重跑
代价：建机 21-36s；留盘期间 ¥0.0431/h
风险：低。退出机制靠 terminate + due_mode 双档
```

**路线 B：把 reaper / pool / scheduler 迁到契约层**

工作量集中在 4 个文件 + 19 处端口，之后两家云真正对等。
但 reaper 的"三态判定"要重写成"两态 + 云能力分支"，pool 在智星云上直接禁用。

```
代价：中等，约 3-5 天，且要重跑现有 1108 项测试
收益：多云对等，以后接第三家成本骤降
风险：动的是生产路径（reaper 是唯一防孤儿实例的闸），要非常小心
```

**路线 C：只在智星云上做"关机省钱"**

不可行。实测证明关机不省钱，且无 API 触发。**这条路已经证伪，不要走。**

### 我的建议

先走 **路线 A** 把第二家云跑起来（现在已经能跑），
`placement.py`（原 P2 待办）按"provider 能力"分流，而不是假设两家一样。
等第三家云出现、或智星云真的要承担主力流量时，再付路线 B 的迁移成本。

### 必须记住的两条硬约束

1. **智星云上任何"留着机器等会儿再跑"的设计都是错的** —— 租期在烧。
2. **退租是唯一止损动作，而它要等 3-5 分钟** —— 退出路径必须留足时间，或者靠 `due_mode=-1` 到期自动释放兜底。

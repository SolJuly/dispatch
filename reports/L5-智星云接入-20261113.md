### 这一家与智云的三个结构性差异（上层必须知道）

1. **回收语义相反**。智云「停机保状态、停着不算力费」；智星云是**租期制**，没有关机接口（`instance/stop_*`、`shutdown_*` 逐个试过全 404）。唯一省钱动作是 `stop_instance_with_refund` 提前退租。
   → `stop()` 抛 `UNSUPPORTED`，`terminate()` 才是真的收尾。**故意不把 stop 实现成 terminate**，否则上层「停一下再开」会直接把机器退订掉。
2. **CPU/内存不能自由填**。规格是固定的 `SpecName`（`gcs.g1.base` / `.large` / `.xlarge`…），必须把契约的 `(cpu, memory_gb)` 落到某个真实规格。`_pick_spec()` 取「满足要求里最便宜的一档」。
3. **「停机」不是状态，是 IsAbnormal=2**。`Status==1 && IsAbnormal==2` 才是关机态，这也是官方 `restart_instance_from_shutdown` 的前置条件（写死的判断）。

## 三、真机踩到的两个坑（都在代码里堵掉了）

### 坑 1：`gpu_type` 必须是云侧规范名

```
gpu_type="4090"                → {"code":"4000","message":"价格没有获取到"}
gpu_type="GeForce RTX 4090"    → {"code":"2000", ... FinalCost 1.6506 ...}
```

上层代码里历来写 `"4090"`（`tools/p1/run.py`、`tools/p22/trial.py` 等 10+ 处）。所以加了 `canonical_gpu()`：发往云侧前先查 selector 匹配成规范名；认不出来就**原样传**（让云侧报错，而不是擅自换一张更贵的卡）。

### 坑 2：询价镜像必须是该卡 `ValidImages` 里的

传 `centos7_base`（一个合法 kvm 镜像）给 4090，云侧同样只回「价格没有获取到」。加了 `_image_for()`：从 selector 的 `ValidImages` 里挑，优先 `ubuntu*_nvram_base`，跳过 Windows。

> 这两个坑的共同点：**云侧错误文案一模一样，都看不出根因**。文档里没写，只能靠真机撞。

### 6.4 最贵的坑：保留磁盘按整点扣费（已被账单证实）

这是交接单里标注「⚠️ 必须实测，猜错会算错钱」的那一项。实测方法：建一台、退租时
`release_disk=0` 留盘、每 60s 采样。

```
09:37 退租留盘   KeeppedDiskCost = 0
09:38~09:45      恒为 0   （8 分钟，一度以为不收费）
─────────────── 10:00 整点 ───────────────
10:00:31  账单 Type=71 "保留实例定时扣费(磁盘)"  power -0.0431
10:03:15  释放后 Type=72 "保留实例释放结算(磁盘)" power -0.0052
```

**结论：不是实时累积，是整点一次性扣。** 只看前几分钟会得出「留盘免费」的错误结论 ——
这正是交接单警告的那种错误。已验证 `release_kept_disk()` 能停掉它。

顺带实测出两个相关事实：

1. **`due_mode` 在建机时就把磁盘命运定死了**。第一台用 `due_mode=-1` 建，退租时即使传
   `release_disk=0`，磁盘照样被释放（Status→0）。要真留盘必须建机时就 `due_mode=1`。
   → 已加 `keep_disk_on_expire` 参数。
2. **退租退款进算力券，不回现金**。`现金 15.00 → 14.8332` 没退回，`券 0 → 0.1526`。
   所以「退租后现金没变」是正常的，别以为亏了。

## 八、遗留风险

| 风险 | 影响 | 处置 |
|---|---|---|
| `create_kvm_instance` 的 `data` 是 **null** | 拿不到 `Container_name` | 实测确认，已靠「按备注回查」兜住（真机第一台就是这么拿到 uid 的）|
| 退租 BUSY 冷却 3~5 分钟 | 退不掉 = 继续烧钱 | `terminate` 默认 420s 重试窗口（实测 289s / 317s 都在内）|
| 退租退款进券不回现金 | 看现金会以为亏了 | 文档 + `balance_detail()` 分开返回；报告第六节有对账 |
| 无定时关机 | 孤儿实例只能靠本地 reaper 兜 | `scheduled_stop` 抛 UNSUPPORTED，上层走降级路径 |
| 规格固定 | 上层要的 `(cpu, memory)` 落不到精确值 | `_pick_spec` 取「≥要求里最便宜」，报错列近邻；实测 2核2G/8核16G 都能精确命中 |
| `terminate` 默认 `release_disk=1` | 磁盘释放不可逆 | 有意为之：留盘按小时扣钱比丢数据更贵；要留传 `release_disk=False` + 建机 `keep_disk_on_expire=True` |
| `typical_boot_s=45` 只有 CPU/2080Ti 样本 | 40G 大卡可能更慢 | 上层本来就该用 `ssh_ready(timeout=)` 探活，这个值只用于估时 |

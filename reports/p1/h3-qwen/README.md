## 2. 测试结果

| 组 | 模型 | 方式 | 结果 | 耗时 | 产物 |
|---|---|---|---|---|---|
| 1 | Qwen-Image | 文生图 1024×1024 | ✅ | ~35s | `qwen_t2i.png` 912KB |
| 2 | MiniMax H3 | **文生视频 3s** | ✅ 出片 | **260.7s** | `h3_t2v.mp4` 190KB |
| 3 | MiniMax H3 | **图生视频 3s** | ✅ 出片 | **24.1s** | `h3_i2v.mp4` 704KB |

### 2.1 视频客观指标

| 组 | 帧 | fps | 时长 | 分辨率 | 亮度 σ | 黑帧 |
|---|---|---|---|---|---|---|
| H3 t2v | 73 | 24.0 | **3.042s** | 768×512 | 1.195 | 0 |
| H3 i2v | 73 | 24.0 | **3.042s** | 768×512 | 4.711 | 0 |

**3 秒目标达成，时间轴天然正确**（73 帧 ÷ 24fps = 3.04s，没有 SVD 那种"压缩播放"问题）。
对比 SVD 方案：97 帧被压进 5 秒 = 19.4fps = 2.4 倍速。H3 这条路不需要拼接就不存在该问题。

### 2.2 画质：前段正常，后段崩坏

`h3-strips.png`（每组首/中/尾帧）：

```
上排 h3_t2v：正常中景 → 放下手机起身 → 人物肢体扭曲、右侧糊成色块
下排 h3_i2v：清晰原图   → 微笑、光线转暖 → 整帧变成紫粉色抽象噪点
```

- **t2v**：前 ~48 帧正常，第 49 帧后开始畸变，尾帧崩坏
- **i2v**：前 ~40 帧正常，之后迅速崩解，尾帧完全失去构图
- 两组都无黑帧、无卡死，属于**生成质量崩坏**而非推理失败

### 2.3 Qwen-Image 质量

1024×1024，光影自然、针织纹理清晰、手部结构正确、客厅+厨房空间关系合理。
与 prompt 的偏差：prompt 写"坐"、图是"站"，但语义主体（人物/家居服/手机/客厅/暖光）全部命中。
**这是目前本项目质量最高的一次出图**（对比 SDXL 11–12s/张，Qwen 约 35s/张但细节显著更好）。

## 3. 崩坏原因排查（待验证假设，按可能性排序）

| # | 假设 | 依据 | 验证方式 |
|---|---|---|---|
| 1 | **4 步蒸馏模型在长序列上不稳定** | 用的 `..._4step_int8_convrot`；73 帧远超蒸馏训练常见长度 | 换 `DasiwaHybridV2_int8` / `FeiHou_Remix_v0.6`（20–30 步）再跑 |
| 2 | int8 量化累积误差 | 越到后段误差越大，符合"后段崩坏"特征 | 换 bf16/非量化变体 |
| 3 | `length=72` 超出训练帧数 | H3 原生可能按 121/144 帧训练，72 非标准 | 试 121 帧（5s）看是否反而更稳 |
| 4 | `shift_video=5.0` 偏大 | 我按经验填的，未查默认 | 查节点默认值或调 2–3 |
| 5 | 分辨率 768×512 非原生比例 | H3 可能按 16:9 训练 | 试 1024×576 |

**最可能是 1 + 3 叠加**：4 步蒸馏 + 非标准帧数。

## 4. 踩到的两个坑（已解决，记录备查）

| 坑 | 现象 | 解法 |
|---|---|---|
| Manager 阻塞启动 | ComfyUI 卡在拉 GitHub 的 `extension-node-map.json`，8188 永不监听 | 停进程 → 重命名 `custom_nodes/ComfyUI-Manager` → 不带 `--enable-manager` 重启 |
| VAE / text encoder 断链 | `qwen_image_vae.safetensors`、`qwen_2.5_vl_fp16` 在列表里但读不到 | 前者是 3D 视频 VAE（形状 [96,4,3,3,3]，不兼容 2D）；后者是 3B（2048 维）。改用软链：`FireRedTeam/.../qwen_image_vae.safetensors` + `qwen2.5vl-7b-bf16.safetensors`（3584 维） |

另：`csctl ssh` 60 秒超时会打断长任务 stdout 管道（`BrokenPipeError`），长任务必须 `--detach --log`。

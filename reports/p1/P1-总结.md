## 3. 核心技术结论

### 3.1 五个模型的稳定参数（都是花钱试出来的）

| 模型 | 结构要点 | 稳定参数 | 时长 | 禁忌 |
|---|---|---|---|---|
| **H3** | `MiniMaxH3ImageToVideo` + `SigmaShift` | **121 帧** @24fps | 5.17s | 73 帧会崩 |
| **LTXV 2B** | `SamplerCustom` + **`LTXVScheduler`** | **73 帧** @25fps | 2.92s | 97 帧会崩；用标准 KSampler 出噪点 |
| **Wan2.1** | `WanImageToVideo` + `CLIPVisionEncode` | **49 帧** @16fps | 3.06s | 社区 NVFP4 4bit 版废 |
| **Qwen-Image** | `UNETLoader` + **7B encoder** | 1024×1024 | — | 3B encoder（2048 维）不行 |
| ~~SVD-XT~~ | 4 段链式 | — | — | **已废弃**：构图自己推近 |

**关键洞察**：H3 要**高帧**、LTXV 要**低帧**，需求正好相反——这是各自训练长度决定的，不是调参能解决的。

### 3.2 踩过的结构性坑（都已写进代码或文档）

| 坑 | 表现 | 根因 |
|---|---|---|
| SVD 2.4 倍速 | 动作快得不自然 | 97 帧硬压 5 秒 = 19.4fps，生成条件是 8fps |
| SVD 构图漂移 | 中景自己推成特写 | 4 段链式，每段用上段末帧重新 init |
| LTXV 出噪点 | 抽象色块 | 缺 `LTXVScheduler`，标准 KSampler 无法匹配 LTXV 噪声分布 |
| Wan 黑帧 | 纯黑 | 0.3.40 + fp8/int8 组合；0.36 + 官方 fp8 已解决 |
| Wan 过曝 | 噪点+崩坏 | 用了社区 NVFP4 4bit 量化版 |
| Qwen 失败 ×2 | VAE/encoder 找不到 | 列表里是断链；`qwen_2.5_vl_fp16` 是 3B 不是 7B |
| Manager 卡启动 | 8188 永不监听 | 拉 GitHub 超时，概率卡（4 次建机中 2 次） |

## 4. 工程能力

### 4.1 一条命令跑完闭环

```bash
python3 tools/p1/jobctl.py new --spec reports/p1/examples/job_h3_t2v.json
python3 tools/p1/run.py <job_id>
```

九步串行：建机 → setup → 提交 → 轮询 → 拉取 → 校验 → 落盘 → 销毁 → 完成。
每一步先转移状态（守卫在此拦截）再执行动作。

### 4.2 三条硬规矩（真实生效）

| 规矩 | 实现 | 验证 |
|---|---|---|
| **G1** 未落盘不许销毁 | 状态机白名单 + 显式守卫 | TC-04 拦截 |
| **G2** 完成必须校验通过 | DONE 前检查 manifest.verdict | 无 manifest 时拒绝 |
| **8903 重试** | 销毁遇过渡期拒绝重试 3×10s | TC-11 实测：命中后 10s 成功 |

### 4.3 校验层：六项指标 + 三条内容告警

六项（参与 PASS/FAIL）：decode / geometry / frames / size / black / params
三条（只告警）：帧差 < 0.40、亮度 σ < 1.5、边缘能量 < 1.0

**这套告警是被 LTXV 逼出来的**——LTXV 两次输出六项全绿但画面是噪点，暴露了"格式合格 ≠ 内容可用"的盲区。

### 4.4 异常用例 12 条

9 PASS / 3 SKIP / 0 FAIL。SKIP 的三条（SSH 断、磁盘满、Spot 回收）需故障注入。

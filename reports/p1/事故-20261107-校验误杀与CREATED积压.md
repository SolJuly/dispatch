# 事故复盘：0046 作业被误判失败 + 后面几单卡在 CREATED

时间：2026-11-07 04:06–04:26
影响：1 个作业（`p1-20261107T0406-4ff021`，h3 文生视频 241 帧）被判 FAILED；另有 10 个作业
停在 `CREATED` 从未被执行（其中 7 个是 11-07 当天的）。

## 一、为什么会失败（误杀，不是生成失败）

作业链路本身全绿：建机 → setup → 提交 → 推理 516s → 拉回 1 个 mp4（2.5MB）→ 校验。

挂在最后一步 `frames`：

```
期望 时长[5.0, 5.4]
实际 10.125s / 243 帧 @24fps
```

原因：`tools/p20/render.py: expect_for()` 只把**尺寸**按本次请求重算，`duration_s`
是直接从工作流配置 `expect_defaults` 抄的——那个窗口是按默认 121 帧（5.04s）标定的。
作业把 `frames` 改成 241，期望窗口没跟着走，于是好视频被判 FAIL。

根因不是"帧数设大了"，是**期望值生成漏了一种参数覆盖**。

修复：`expect_for()` 现在按工作流声明的 `fps` 重算 `duration_s`：
`frames/fps ± 容差`；`duration`（秒）参数按 Wan 口径 `fps*duration+1` 换算。
h3 / ltxv / wan21 / wan2.2 系列补上 `fps` 声明（wan2.2 i2v/flf2v 顺带打开了时长门禁，
实测 5.062s 稳定）。

`4ff021` 用新口径重跑校验：PASS，243 帧 / 10.125s，已落 manifest、已进图库，
**零额外费用**（`run.py --salvage` 只补状态，不建机）。

### 补充：同一个 bug 的第二例（ltxv，帧率写错）

排队跑 `p1-20261107T0408-55efa4`（ltxv_2b_t2v，241 帧）时又挂在 `frames` 上：
期望 [2.7,3.2]，实际 9.64s。查图才确认 LTXV 是 **25fps**
（`CreateVideo.fps=25` / `LTXVConditioning.frame_rate=25`），不是 24。
241/25=9.64s 完全正确。已把 `ltxv_2b_t2v.fps` 改成 25，并加交叉校验测试：
每个视频工作流的"默认帧数 ÷ fps"必须落在自己配置的时长窗口内，防止再写错。
这一单同样是 `--salvage` 零成本救回（¥0.176 是它自己跑出来的）。

## 二、为什么后面几单停在 CREATED

`run.py` 的设计是"单任务、不排队"：拿不到 `reports/p1/.job.lock` 就

```python
raise JobLocked("已有作业在跑…本轮只做单任务")
```

而控制台提交时会 `Popen(run.py <job>)`。于是：

1. 04:08 前后 h3 那单还在跑（04:08:19 提交，04:16:56 出片），锁被占着；
2. 04:08 / 04:09 / 04:10 又提交了三单，三个 run.py 进程启动→抢锁失败→异常退出；
3. 异常发生在状态机转移**之前**，`job.json` 还停在 `CREATED`，没人再叫醒它们。

所以不是任务"没开始跑"，是**提交成功、执行器自杀、没有队列兜底**。

修复：

- `store.JobLock(wait=N)`：可以排队等锁，每 2s 重试，超时才抛；
- 控制台提交改为 `run.py <job> --no-keep --wait-lock 14400`，即"排队等前面跑完"；
- 新增 `tools/p1/p1queue.py`：把遗留 `CREATED` 作业按时间顺序串行跑掉
  （`--dry-run` / `--since YYYY-MM-DD` / `--limit N`）；
- 子进程输出同时写回作业 `run.log`，控制台详情页能看排队进度。

## 四、以后怎么避免

1. 参数一旦能覆盖帧数/时长，期望窗口必须由参数推导——已纳入 `test_render.py`
   （`test_duration_follows_frames_override` / `test_duration_follows_seconds_override`）；
2. 校验失败先看 `run.log` 的"期望 vs 实际"，`duration` 类偏差先怀疑期望而不是模型；
3. 产物在本地且判定是口径问题的，优先 `run.py <job> --salvage`，不要重跑烧钱；
4. 控制台连点多次不再产生孤儿作业：提交即排队，`reports/p1/.job.lock` 前面有几个
   作业就等几个。

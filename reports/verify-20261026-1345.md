## 4. 关键发现（本轮最需要知道的事）

1. **关机＝放弃 GPU，重启要重新抢卡。** 13:35 关机后立刻 `start` 连续失败 10 次（`226604 This GPU type is currently out of resources`），直到 13:40:41 现货回来才启动成功——**停机 5 分半**。全站库存当时为 0（V100S/A100 都没货）。
2. **重启后数据全在。** 13:34 写入的 `/root/persist_marker.txt` 重启后仍在；`output/verify_00001_.png` 仍在；`/model` 挂载正常；ComfyUI 由 `/start.d` 自动拉起（新 pid 51）。
3. **后台任务不会跨重启存活**（`nohup sleep 600` 重启后消失，符合预期）；但**同一会话内 SSH 断开不影响后台进程**——实测 `nohup ... &` 与裸 `&` 在非交互 SSH 下都存活（`KillUserProcesses` 默认 no，无 TTY 不触发 SIGHUP）。
4. **视频模型在 V100S 上基本不可用**：体积最大的 Wan 权重是 **fp8 / GGUF**，而 Volta（sm_70）不支持 fp8 计算；A100（Ampere）同样不支持 fp8。→ 视频生成实际需要 **4090/5090**（Ada/Blackwell）。
5. **实例没有 curl、没有 systemd、没有 iproute2 的 ss**：校验脚本必须用 Python urllib 或安装工具；自启动只能靠 `/start.d`。
6. **ComfyUI 是公网裸奔**：`http://<公网IP>:8188/` 无鉴权 200（本机 92ms 可达），8888/8889 同样开放。
7. **SSH 端口不是 22**：本镜像由 entrypoint 改成 **23**（`PermitRootLogin yes`、`PasswordAuthentication yes`）；`csctl` 已改为从 `SshLoginCommand` 解析端口（修复前会连错端口）。
8. **watch --ssh 的假阳性已修**：ComfyUI 常驻持有 ~312MiB CUDA 上下文，原逻辑「有进程＝在跑」会让空闲关机永不触发；现改为「显存占用 >1GiB 才算真实任务」（代码已改，待有卡回归验证）。

## 7. 结论

### 已确认（可直接依赖）
1. 建机 → 自动启动 ComfyUI → 公网 8188 可访问，全链路 75 秒内就绪。
2. GPU 推理可用：torch 2.4.0+cu124 / V100S sm_70，SD1.5 512² 8 步 10 秒。
3. 系统盘 100G（免费额度）+ `/model` 40T 共享模型库，实例内几乎不占盘。
4. 关机保留数据、重启自动恢复环境、销毁即全清。
5. 后台进程在同一次开机周期内可跨 SSH 断开存活。

### 未确认 / 需再次验证
1. 4090/5090 上的 ComfyUI 0.36（CUDA 13.x）表现（当前无货，未验证）。
2. 视频推理耗时与显存（需 4090/5090 + fp8 支持）。
3. 定时关机（15:31）在「关机→重启」后是否仍然生效（接口不返回该字段）。
4. 抢占式实例的创建与回收行为（未创建 Spot）。

### 新增风险（本轮实测暴露）
1. **停机即失卡**：关机省钱但可能长时间起不来（本次 5.5 分钟，全站 0 库存时可能更久）。→ 建议长任务宁可「无卡模式」或干脆不关机，改用 Spot + checkpoint。
2. 公网裸奔的 8188/8888/8889。→ 建议用完即关，或加 `.htpasswd`/安全组限制。
3. 销毁即丢产物。→ 产物必须外传（US3/`/model` 或回传本机）。
4. fp8 视频模型与老卡不兼容。→ 视频任务锁定 4090/5090。

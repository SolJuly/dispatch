# 质量评分表修复报告 · 2026-11-14

> 触发：用户指出「这两条文生视频人眼观看非常差，但评分只给 32 分 D，像在说『稍微糊』」。
> 深入查之后发现**三个独立标定错误**，它们互相掩盖，导致评分表在关键判断上是错的。

## 一、三个标定错误

### 错误 1：抽帧让运动量虚高 75%（最严重）

`_stats_series(every=3)` 每 3 帧只看 1 帧。而 `YDIF` 量的是「相邻**被采样**帧的差异」——
跳帧等于把时间跨度放大 3 倍，同一段动作被算成 3 倍运动量。

实测同一条片（`wan2_2_s2v`，说话+轻微点头）：

```
every=1  motion=1.123   samples=157   ← 真实运动量
every=2  motion=1.661
every=3  motion=1.970   samples=53    ← 旧评分用的就是这个
every=4  motion=2.200
```

**后果**：旧评分系统性高估运动。`s2v` 旧分 97.5 是假的 —— 按旧公式用真实
运动量 1.123 复算只有 82.4。不是新评分变严，是旧分算错。

### 错误 2：抽帧还会漏掉坏帧

`minimax_multiframe` 末尾 4 帧整屏纯蓝。`every=3` 时 124 帧只采 42 帧，
抽样率 33%，2–4 帧的瞬时事件大概率被跳过 —— 而它是这条片**唯一的硬伤**。

坏帧是「突然变成纯色」这种瞬时事件，抗抽样能力几乎为零。要么全采要么判据不可信。

### 错误 3：清晰度用全局均值，把「构图失败」记成「稍微糊」

`h3_t2v_121f` 全局边缘能量 0.561 → issue 只写「边缘能量 0.56 偏低：画面糊」。
听起来像稍微糊。把画面切 6×6 块分别算之后真相是：

```
0.23 0.26 0.37 0.59 0.36 0.19
0.18 0.19 0.53 1.02 0.31 0.19
0.14 0.17 0.74 1.27 0.50 0.27
0.11 0.20 0.83 1.19 0.38 0.22
0.15 0.18 0.86 0.79 0.35 0.23
0.20 0.19 0.75 0.79 0.35 0.25

36 块里 31 块 < 0.8 → 86% 的画面什么都没画
有内容的块均值 1.03 → 主体本身其实清楚
```

对照同一提示词的 `fasth3_i2v`（97.8 A）：36 块全部 >= 0.8，低能量块 **0%**。

这就是人眼说「非常差」而评分只说「32 分 D」的差距 —— 失败类型不是「模糊」，
是「**主体很小、其余是空**」。均值把这两件事抹成同一个数字。

## 二、改了什么

### 新增两个判据

**① 内容覆盖率 `cover_bad`**

把画面切 6×6 块，逐块算边缘能量，统计低于 0.8 的块占比。

```
COVER_BLOCK_MIN = 0.8    单块 < 0.8 → 该块「没画东西」
COVER_BAD       = 0.50   无内容率 > 50% → 硬伤，封顶 30
COVER_OK        = 0.15   容忍 15%（天空/水面/纯色背景是合法构图）
```

**② 崩坏帧 `broken_frames`**

与**中位数**比，而不是与均值比：

```
单帧边缘能量 < 中位数 × 0.15  → 该帧崩坏
崩坏帧 >= 2 帧 → 封顶 52（C 区，裁掉片头片尾可用）
崩坏帧 >= 6 帧 → 封顶 32（D 区，已影响观看）
1 帧容忍（编码边缘情况）
```

为什么用绝对帧数不用占比：5 秒片只有 124 帧，2 帧坏 = 1.6%，
任何占比阈值都会放过 —— 但观众会看成「闪了一下」。

### 权重重排

```
旧：清晰度 40 / 运动 25 / 曝光 20 / 稳定 15
新：清晰度 25 / 覆盖率 15 / 运动 25 / 曝光 20 / 稳定 15
```

清晰度从 40 降到 25 并让出 15 分给覆盖率：清晰度是全局平均值，
主体只占 15% 画面时那 40 分基本在量背景。

### 全部阈值按全帧重标

| 常量 | 旧值 | 新值 | 依据 |
|---|---|---|---|
| `every` | 3 | **1** | 抗抽样 + 运动量真实 |
| `MOTION_STATIC` | 0.6 | **0.5** | 全帧分布：animate2_distilled 0.16、h3_t2v 0.56 |
| `MOTION_GOOD` | 2.0 | **2.5** | 全帧分布：正常片 2.55–19.3 |
| `CONTENT_BLUR` | — | **1.0** | 新增，分块主体清晰度下限 |
| `CONTENT_GOOD` | — | **2.5** | 新增，对齐人眼判定「好」的分布 |

## 四、回填历史

`tools/p2/recompute_quality.py`：用新评分表重算历史 manifest。

```
改了 29 条 · 跳过 36 条 · 失败 0 条
```

**只改 `quality` 字段，不动 `verdict`** —— verdict 来自 verify.py 的七项
技术判据（能不能播、尺寸对不对），与质量分是两套东西。回填不得用
「内容好不好」改写「文件有效没效」的历史结论。

为什么回填而不是重跑：这三个错误都是**评分代码的错，不是产物的错**。
产物文件还在，重算几秒；重跑一次作业要 ¥0.1–3。

## 六、这两条文生视频现在怎么办

它们在**新评分表下依然是 D 级**，而且分数更低了（30 分）。新增的诊断说清了原因：

```
h3_t2v_121f   cover_bad 0.861   motion 0.56   luma 45.9
ltxv_2b_t2v   cover_bad 1.000   motion 0.99   luma 126.9
```

**两条的诊断不同**：

· `h3_t2v`：主体清楚但只占 14% 画面，其余是暗块；同时几乎不动、整体欠曝。
  这是**构图 + 运动 + 曝光三重失败**，不是模型坏 —— 它需要的是一张参考图
  （i2v 版本 85.1 分 A 就是证明）。

· `ltxv_2b`：**100% 的块都无内容**，即全片没有一个地方有结构。
  这是真的生成了抽象噪点，模型本身在这个配置下不work。

所以：`ltxv_2b_t2v` 建议淘汰（模型真的不行），`h3_t2v` 值得再给一次机会
（换提示词加光照/运动描述，或考虑它本质上是 i2v 模型的误用）。
